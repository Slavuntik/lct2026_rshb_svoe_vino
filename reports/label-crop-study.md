# Кроп этикетки и второй индекс «этикетка → этикетка» (оркестратор, 22.09)

Идеи Вячеслава: (1) вырезать именно этикетку — YOLO или лёгкая модель, чтобы мелкая модель на CPU
читала крупный текст; (2) отдельный индекс по вырезанным этикеткам: сначала искать по нему, при
неуверенности — полный цикл, при сомнении — лучшее из совпадений. Проверено на 62 живых фото из
каталога (индекс D1 base-384). Скрипты: `qa/real_photos_label_crops.py`, `qa/ref_label_index.py`,
`qa/real_photos_label_cascade.py`, кэши — `case-data/real-photos-labels/{label-crops,features}` (вне git).

## Как вырезали этикетку без новой модели

Боксы детектора текста RapidOCR (уже работает в конвейере, ~0.2 с) → кластер боксов центральной
бутылки → прямоугольник с полями (минимум 45% ширины / 32% высоты кропа бутылки, рост вниз).
Нашлось на 100/100 живых фото (доля кадра: медиана 16%) и на 1985/2058 эталонах каталога.
Визуально (контакт-листы): этикетка вырезается верно, но на многих фото ТОЛЬКО шапка с винодельней
(«ТАБИЯ винодельня» без названия «Олег»/«Цитрон») — детектор видит крупные буквы, а мелкое
название и сахар в кластер не попадают. Это и есть главный ограничитель всей идеи.

## Что дало (top-1 на 62 фото)

| Вход | OCR RapidOCR | Qwen3-VL-2B (448/640 px) | Qwen3-VL-4B (448/640) |
|---|---|---|---|
| кроп бутылки (текущий) | 640+960: 90.3% | 72.6 / 87.1% | 75.8 / 87.1% |
| кроп этикетки | 640+960: 79.0% | 69.4 / 74.2% | 75.8 / 79.0% |
| бутылка + этикетка (объединение текстов) | 91.9% (2 кропа CV) | — | — |
| OCR бутылки + 4B по этикетке 448 px | — | — | 93.5% (2 кропа) / 95.2% (8 кропов) |

Кроп этикетки САМ ПО СЕБЕ хуже кропа бутылки для всех читалок: теряется название. Но как
ДОБАВКА к OCR он работает: 2B ничего не прибавляет, 4B при 448 px даёт +3 п.п. — только это
на CPU стоит ~10 с (2B при 448 px на 4 vCPU — 4.7 с, 4B ×2), в лимит 10 с не укладывается.

## Второй индекс «этикетка → этикетка» и каскад

| Схема | top-1 |
|---|---|
| только индекс этикеток (кроп ↔ кроп) | 32/62 = 51.6% |
| только CV по бутылке (2 кропа) | 44/62 = 71.0% |
| полный цикл: CV бутылки + OCR (как на стенде) | 56/62 = 90.3% |
| максимум/среднее двух индексов + OCR | 56 / 55 из 62 |
| каскад «сначала этикетка (скор ≥ T, отрыв ≥ G), иначе полный цикл» | 82–89% — хуже полного цикла при любых T, G |

Индекс этикеток слабее: у половины эталонов каталога фото — бутылка целиком в сцене, этикетка
там мелкая и вырезается с искажениями; SigLIP сравнивает «дизайн», а близнецы одной линейки
различаются только словом. Ступень 1 «уверена» (высокий скор, отрыв ≥ 0.02) в 26 случаях, из
них верна в 19 — то есть каскад отдаёт неверный ответ раньше, чем полный цикл его исправит.
Полезный побочный факт: когда top-1 обеих ступеней совпадает (31/62), он верен во всех 31 —
это сигнал уверенности для интерфейса, не для метрики.

## Итог

Для метрики на CPU: кроп этикетки не заменяет кроп бутылки; лучший CPU-путь остаётся «CV по
бутылке + двухмасштабный OCR», а к нему добавлены две дешёвые поправки из разбора промахов
стенда: полная таблица греческих двойников (ОΛΕΓ → ОЛЕГ) и штраф за противоречие цвета
этикетки — офлайн 90.3 → 91.9%. Кроп этикетки + 4B стоит держать для конфигураций с GPU/Apple
Silicon (95.2% при 8 кропах), а сигнал «две ступени согласны» — для карточки в интерфейсе.
