# Frontend — остальные экраны в дизайн-системе (27.09)

Задача тимлида: перенести дизайн-систему карточки вина (`WineCardContent.tsx`/`.card`/`.spec-tiles`/`.chip`)
на онбординг, профиль, паспорт вкуса, чат-сомелье, метрики, «Витрина недоступна», сканер — по
конкретным дефектам, увиденным тимлидом живьём на 375px (`http://localhost:5176`, режим real).
Правки только `apps/web/`.

**Два захода.** Первый коммит (`6b89fde`) — `WineCardContent.tsx`/`ScanShortcut.tsx` и блоки
`.spec-tile*`/`.scan-shortcut` были под прямым запретом (доделывал другой агент). Второй коммит,
после снятия блокировки и разбора шапки тимлидом лично: доделаны 3 оставшихся заголовка 32px,
тап-зона `.chip`, откачен фикс шапки (см. «Шапка-пилюля» ниже — течи не было, дала ложный сигнал
сама методика проверки скриншотом прокрутки, не разметка).

## По экранам

- **Профиль**: 5 заголовков → `.card-heading` (Согласия/Вы-гость/Выгрузка/Удаление/модалка «Точно удалить?»); бейдж «Гостевой доступ» не растянут; чекбоксы; кнопки уже были 3 осознанные роли (primary/secondary/danger) — не трогал код ролей, только исправил их `:disabled`-состояние глобально.
- **Паспорт вкуса**: `.card-heading` на «Пока вы — гость»/«Нужно согласие»/«Вина закончились»/«Ваш вкусовой вектор». Название вина на карточке свайпа (`currentWine.name`) **не трогал** — это герой-контент карточки (как заголовок товара), не секция настроек; рядом нет других 32px-заголовков на этом экране, конфликта нет.
- **Чат**: чипы/плейсхолдеры/линия/disabled-кнопка — см. таблицу. `<h2>` на этом экране нет вовсе (проверил кодом) — пункт задания «применить в чате» технически покрыт понижением уровня `.chip`/убиранием линии; заголовков к понижению не нашлось.
- **Метрики**: плитки + `<details>`. Заголовков `<h2>` на этом экране не было изначально.
- **Витрина недоступна**: см. таблицу.
- **Онбординг**: разделитель, `.card-heading` на «Согласия», чекбоксы, `color-scheme`. Радиус/палитра поля даты уже были верны (`--radius-sm`, `--card`, `--ink` — проверено computed style), реальная проблема — низкая видимость плейсхолдера/иконки календаря нативного виджета, чинится тем же `color-scheme`.
- **Сканер**: дропзона и поле «Текст с этикетки» уже соответствуют системе (радиус 20/14, палитра, пунктир дропзоны — осознанное исключение для аффорданса drag&drop, в макете этой рамки нет вовсе); поменял только роль кнопки «Найти вино» на secondary.
- **Карточка вина / виджет сомелье** (второй заход, блокировка снята): «Вкусовой профиль» и «К чему
  подать» в `WineCardContent.tsx`, «Цифровой сомелье» в `SomelierCardWidget.tsx` → `.card-heading`.
  Проверено через `getComputedStyle` (не скриншотом): все три теперь `fontSize:"22px"`,
  `className:"card-heading"`. Композицию (иконки `.food-pairing__icon`/`.icon-badge`, порядок блоков,
  паддинги) не трогал — только `className` на трёх `<h2>`.
- **Чипы** (второй заход): невидимая зона нажатия 44px на `.chip` — см. таблицу.

## Намеренно НЕ менял

1. `.app-header` sticky-фикс — откачен, см. «Шапка-пилюля» ниже.
2. Заголовок «Похожие вина» (`wineCard.similarTitle`) — **новая находка** этого захода: живёт в
   `WineCardScreen.tsx` (не в `WineCardContent.tsx`/`SomelierCardWidget.tsx`), остаётся 32px.
   Тимлид называл ровно 3 заголовка («Цифровой сомелье» + два в `WineCardContent.tsx`) — этот четвёртый
   не входил в перечень, файл им не назывался, поэтому не трогал по своей инициативе. Тот же приём
   (`.card-heading`) применится за 1 строку, если нужно — жду решения.
3. Заголовки внутри результатов `ScanScreen.tsx` (Похожие/Аналоги/«Похоже по вкусу» и т.д.) — не
   входят в явно названные экраны задания; скану отдельно перечислены только дропзона/текстовое
   поле/кнопка.
4. `button.icon-badge:disabled` (кнопка-иконка отправки в `SomelierCardWidget`) — тот же приём
   opacity, что чинил у `.btn`, но это иконка, не текст; в задании явно назван текстовый пример
   («Спросить» в чате). Не трогал, чтобы не расширять правку за пределы текстовых кнопок без запроса.
5. Текст `metrics.eval_set`/`index_version`/бейджи каталога — данные, не интерфейсные тексты, не менял.

## Чем проверял

`npm test -- --run` (vitest): **194/194 зелёных** (тот же счётчик, что и до правки — один тест
(`ChatScreen.test.tsx::sendMessage`) обновлён под укороченный плейсхолдер). `npm run build`
(`tsc -b && vite build`): чисто, CSS-бандл 19.28 КБ/gzip 4.35 КБ (был 13.72 КБ до этой волны — рост
за счёт нового чекбокса/плиток/disabled-фикса/тап-зоны чипа). Живьём — `http://localhost:5176` (уже поднят, режим
real: реальный каталог 2103 вин, `VITE_API_MODE=real`; сервер также поднят с `VITE_THEME=portal` —
проверил, что `themes/portal.css` не переопределяет ничего из моих правок, палитра там 1-в-1 с
`tokens.css`). Смотрел на 375×812 и на десктопной ширине пейна (~800px): профиль, онбординг, чат
(оба режима), метрики (свёрнуто/раскрыто), витрина, паспорт вкуса (гостевой гейт), сканер, карточка
вина (сверка, что заголовки WineCardContent не съехали). Клавиатура: Tab до чекбокса — фокус-кольцо
видно. Тёмная тема: `VITE_THEME=portal` на этом сервере насильно светлый (уже согласовано с Figma
27.09, `themes/portal.css`) — принудительно проставил `data-theme="dark"` через DOM (не код, только
для проверки) и пересмотрел профиль/метрики — чекбоксы, плитки, disabled-кнопки, бейдж читаемы.

**Скриншоты**: инструмент Browser pane отдаёт их только инлайн в диалог, файлового пути сохранения
нет (тот же вывод, что и в `reports/frontend-figma-restyle.md` прошлой волны) — в
`/private/tmp/.../scratchpad/web-restyle/` физических файлов нет, до/после сверялись визуально по
инлайн-скриншотам в ходе сессии.

**Важная поправка методики (второй заход)**: тимлид проверил лично и нашёл причину «течи» под
шапкой — скриншот ПРОКРУЧЕННОЙ страницы в этом инструменте недостоверен (воспроизвёл тот же артефакт
на статической `/legal/privacy.html`, без React и sticky, простой прокруткой на 500px:
`getBoundingClientRect()` в этот момент показывал честные координаты, а снимок — сдвинутый контент).
Для геометрии/раскладки — только `getBoundingClientRect`/`getComputedStyle`/`document.elementFromPoint`,
скриншотом можно проверять цвет/текст/статическую (не прокрученную) компоновку. Тап-зону `.chip` этим
заходом проверял именно так: `elementFromPoint` в 6 точках (внутри/на границе/за границей 44px-зоны,
сверху и снизу видимого чипа) — зона ловит клики ровно там, где посчитана математически, скриншот и
клик по экранным координатам не использовал (у клика по `computer`-координатам в этой сессии тоже
поймал рассинхрон кадра после смены страниц — сам наступил на то же грабли, чинил тем же методом).

## Риски и предложения

1. **Шапка-пилюля — течи нет, фикс откачен.** Тимлид лично подтвердил: артефакт даёт инструмент
   (скриншот прокрутки), не разметка — см. поправку методики выше. `.app-header` вернул к виду до
   первого захода (`background:var(--bg)` и центровка, без `isolation`/`transform`/`will-change`).
2. `button.icon-badge:disabled` (виджет сомелье) — тот же класс дефекта, что был у `.btn:disabled`,
   не тронут (иконка, не текст, вне явного примера задания) — можно взять отдельным тикетом.
3. Заголовок «Похожие вина» (`WineCardScreen.tsx`, `wineCard.similarTitle`) — 32px, не входил в
   названные тимлидом три заголовка, не трогал по своей инициативе (см. «Намеренно не менял» п.2).

Коммиты: `apps/web` + этот отчёт, pathspec отдельно каждый, без push.
