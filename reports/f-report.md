## Как запустить

Одноразово ничего готовить не нужно — `make` сам поднимает `qa/.venv` (uv, Python 3.12):

```bash
cd /Users/vyacheslavfokin/ClaudeWorkspace/vines/svoy-somelye

make demo-pack WINERY=abrau-dyurso     # DoD: одна команда -> qa/packs/abrau-dyurso/{pack.md,pack.json}
make demo-pack WINERY=alma-valley      # второй пак, для проверки универсальности генератора
make demo-pack-all                     # оба разом

make qa-test                           # pytest demo_pack.py, без сети (быстрый, детерминированный)
make qa-test-network                   # то же + один тест с реальными HEAD на vino-svoe.ru
make qa-e2e                            # ставит chromium (~250 МБ, один раз) + playwright против apps/web mock
make qa-e2e-real                       # то же, но против настоящего apps/api (RAG_PROVIDER=real) — волна 3
make qa-test-all                       # ВСЁ разом: demo_pack + e2e mock + e2e real (111 тестов)
make qa-clean                          # удалить сгенерированные паки (пересборка с нуля)

make scan-eval-mock                    # кейс ЛЦТ: eval-раннер, mock-режим, без сети/сервера
make scan-mock-server                  # свой HTTP-мок POST /v1/scan/photo (foreground, Ctrl-C)
make case-script-rehearse              # рехёрсал скрипта оценки — нужен запущенный сервер выше
```

`UV` по умолчанию `~/.local/bin/uv` (как в ORCHESTRATION.md), переопределяется `UV=<путь>`.

### Накладка при первом прогоне e2e (исправлено, не блокер)

Фикстура `dev_server` поднимает `npm run dev` и ждёт готовности по `http://127.0.0.1:5199`.
На этой машине Vite слушает **только IPv6-loopback** (`[::1]`, подтверждено `lsof`) —
`127.0.0.1` отвечал `connection refused`, все 24 теста уходили в skip с honest-причиной
(таймаут 30 c), хотя сервер поднимался за 71 мс. Исправлено: хост — `localhost` (резолвится
через `getaddrinfo` в тот же `::1`), а не жёсткий `127.0.0.1`. После фикса — стабильно
зелёно на нескольких прогонах подряд. Раздел «Предложения» ниже — на будущее для других
агентов, если кто-то ещё будет поднимать dev-сервер программно на этой машине.

Отдельно: `qa/test_demo_pack.py` и `qa/e2e/*` изначально были двумя независимыми `conftest.py`
без `__init__.py` — при раздельном запуске (как в `Makefile`, единственный документированный
способ) всё работало, но комбинированный запуск (`pytest qa/e2e test_demo_pack.py` или просто
`pytest qa/`) падал `ImportError` из-за коллизии модуля `conftest` под одинаковым именем в двух
местах. Добавлен `qa/e2e/__init__.py` (пакет `e2e`), импорты в тестах `e2e/` переведены на
относительные (`from .helpers import …`) — теперь и раздельный, и комбинированный запуск
(`pytest qa/`, 60/60) зелёные из любой рабочей директории.

## Шлифовка волны 3 (2026-08-27, по замечаниям оркестратора)

После приёмки оркестратор запросил две доводки: (1) сделать оставшиеся 10 e2e-расхождений

**1. e2e — 26/26 в обоих режимах**, тремя приёмами, без единой строчки в apps/web/apps/api:
- **Мок-контент → форма/инвариант** (5 тестов): вместо конкретного имени/id вымышленного
  вина, конкретного списка «популярных стилей» или формата мок-токена — проверка того, что
  верно в обоих режимах по контракту (`≥2` цитаты с непустым содержимым вместо точного
  числа и имени бутылки; стиль назван и результат непуст; подсказка честно помечена
  «популярн[ые]» и содержит несколько альтернатив; токен — не короче 16 символов плюс
  мягкая проверка формы по режиму). Новые хелперы —
  `helpers.assert_looks_like_access_token()`, `helpers.assert_not_found_hint_lists_popular_
  styles()`. Заодно заменена сама фраза `GIBBERISH_QUESTION` — старая случайно резонировала
  с реальными статьями о сезонности вина и не рефьюзилась на живом RAG (при этом честно
  рефьюзилась в моке): новая («Сколько будет 17 умножить на 23?») проверена отдельно и
  надёжно рефьюзится в обоих режимах.
- **Разные данные → фикстура по режиму, не ветка в тесте** (3 теста): `helpers.
  scan_fixture()` возвращает свой набор (текст этикетки/id/имя/гастропара) для `mock`

  Понадобилась ещё одна поправка окружения: реальный `/scan/resolve` считает
  `low_confidence` по абсолютному порогу лучшего совпадения (`app/config.py`, дефолт `0.6`),
