# Доработка основного сканера после аудита — 28.09.2026

Основание: [аудит 119 фотографий](label-recognition-audit-2026-09-28.md). Исправления относятся к одной бутылке; алгоритм витрин и код интерфейса не менялись. Численные результаты относятся к `IMAGE_PROVIDER=real` / `CV_FUSION=1`, а не к отдельному адаптеру `winescan`.

## Выполненные изменения

- Кэш эмбеддингов вынесен из дерева приложения. Чтение повреждённой записи приводит к пересчёту, запись атомарна; отсутствие каталога и ошибки диска не отменяют распознавание. Ключ учитывает форму/dtype изображения и версию preprocessing/Transformers. Индекс и веса не меняются.
- UI-only релиз сохраняет живой `app` и runtime-файлы. Проверено сохранение inode каталога и файла кэша; при ошибке публикации веб откатывается, прежняя отметка коммита сохраняется.
- Release gate реально распознаёт эталон Nature Vert и отклоняет пустое изображение через rich-API. HTTP 200 с пустым flat-slug больше не принимается за доказательство исправного сканера. Оба сценария проверены на настоящем Docker-инференсе.
- Пользовательский прицел применяется к исходнику с учётом EXIF до уменьшения до 1024 px. На проверяемом примере фрагмент сохраняет 800×600 вместо 205×153. JSON-контракт не меняется; неверный `box` во flat по-прежнему игнорируется.
- Сохраняются границы структурированных полей VLM. Добавлены отдельные логи результата источника, выбора ветки и конфликта названия; архив получает `model_label_fields` и `identity_rejection`.
- Добавлена **экспериментальная**, выключенная по умолчанию проверка названия (`CV_FUSION_NAME_GUARD=0`). Она требует согласия VLM и независимого OCR о другом отличительном названии, не делает дополнительных LLM-вызовов и не меняет flat-best-guess. В ходе реального теста обнаружен новый пропуск C32: географическая надпись «Самара» прочитана моделью как название вина. Поэтому включение эвристики по умолчанию пока не обосновано.

Новые эталоны не выдумывались и контрольные фотографии не добавлялись в индекс: это исказило бы сравнение с исходным аудитом. 44 позиции без выбранного эталона и разные версии этикетки «Мерло Литавщуков» остаются отдельной задачей подготовки данных.

## Проверки

- Полный API из правильного cwd `apps/api`: **641 passed, 14 skipped**. Первый запуск из корня ошибался на относительных путях `../../pipeline/ref`; это ошибка команды проверки, а не регрессия рекомендаций.
- Энкодер без загрузки моделей: **8 passed**; воспроизведены удаление каталога, повреждённый/невалидный JSON, запрет записи, разные shape/dtype и cache hit.
- Text fusion + identity: **84 passed**.
- Выкладка/откат/инференс-gate: **11 passed**.
- Контейнер с закреплёнными runtime-зависимостями: **806 passed, 12 skipped**; единственный оставшийся тест выкладки отдельно прошёл после установки отсутствующего в runtime-образе `git` (**1 passed**). Это ограничение тестового окружения, а не ошибка приложения.
- Инструмент аудита и проверки выкладки: **16 passed**.
- Положительный и отрицательный smoke на реальном Docker-API: прошли.

Подробное текущее поведение и команды: [docs/label-recognition.md](../docs/label-recognition.md). Выкладка выполняется только из зафиксированной Git-ревизии; результаты HTTP smoke не следует заменять одним `warm=true`.


## Повторная оценка

Те же 119 фотографий и разметка: 72 известных, 46 отрицательных, 1 без достоверной истины. Индекс, каталог, веса, промпт VLM и пороги не менялись. Эксперимент `NAME_GUARD=1`: **119/119 HTTP 200**, top-1 **70/72**, top-5 **71/72**, верных карточек **60/72**, ложных совпадений **6/46**. По сравнению с baseline потерян только C32, ни одно ложное совпадение не устранено. Поэтому штатное значение остаётся **0**.
