# Frontend · пост-скан — гастропары + «Похоже по вкусу» (22.09)

Бриф: `reports/architect-post-scan.md` → «Задача frontend». Контракт: `contracts/post-scan.md` v1.0.
Backend-ручка `GET /wines/{id}/pairings` делалась параллельно — работал по контракту, свой мок
(`mocks/handlers.ts`) + прямой `vi.spyOn` в юнит-тестах, `/v1/analogs` и `/v1/taste/*` не трогал.

## Сделано

1. `apiClient.getWinePairings(wineId)` + типы `WinePairingsResponse/WinePairing/WinePairingsBasis`
   в `apiTypes.ts` (зеркалят `openapi.yaml` `/wines/{wine_id}/pairings`).
2. Блок «К чему подать» — внутри `WineCardContent.tsx` (`WinePairingsBlock`, один код-путь для
   `WineCardScreen` и инлайн-карточки скана), запрос по `wine.wine_id` при маунте. Три видимых
   состояния: загрузка → чипы тегов с честной подписью источника (`pairingsSourceCatalog/
   Sensory/Heuristic`, basis=unavailable подписи не несёт) **или** текст `message` (пусто ⟺
   pairings=[], контракт) **или** сетевая ошибка (`common.errorGeneric`) — не тишина, не вечный
   спиннер.
3. «Похоже по вкусу» на `ScanScreen.tsx` (ветка `confidentCard`): `POST /v1/analogs` по
   `source.grapes.join(", ")`, при 404 и >1 сорте — повтор по `grapes[0]`, иначе `source.name`.
   Успех → стиль + `WineResultChip`; 404 → `message` из ответа (топ-5 стилей, не generic);
   прочая ошибка → `common.errorGeneric`. Шлёт существующее событие `analog_requested`.
4. CTA «Пройти вкусовой паспорт»: гость (`storage.getAccountKind()==="guest"`) → `/app/profile`
   (апгрейд токена, без обращения к `/taste/*` — не тратим запрос на заведомый 403); иначе →
   `/app/taste`.
5. Опционально: если `style.slug` есть в `top_styles` (`GET /v1/taste/profile`, только не-гость,
   все ошибки тихо игнорируются) — бейдж «В вашем вкусе».
6. i18n: 5 ключей `wineCard.pairings*`, 5 ключей `scan.tasteAnalogs*`/`tastePassportCta` в `ru.ts`.
   Мок `GET /wines/:wineId/pairings` в `handlers.ts` — basis=catalog из `food_pairings` (все
   фикстуры его несут) либо unavailable; sensory/heuristic проверены юнит-тестами напрямую.

## Подсказка «снимайте одну бутылку» (задача тимлида 22.09)

Основание: `reports/qa-auto-field-photos.md` (top-1 на фото ЦЕЛОЙ ПОЛКИ 1/8=12.5% против
93.5% на фото одной бутылки тем же конфигом), `reports/ml-eng-ml3.md` (автонарезка полки в
бой не пошла — `CV_SHELF_CROP` остаётся выключен). Раз бэкенд не отличает полку, единственный
рычаг — попросить пользователя переснять сразу правильно.

1. `scan.quietPhotoCaption` дополнена смыслом «одна бутылка в центре кадра» (не заменена):
   было «Лучше всего — этикетка крупно, ровно и без бликов.», стало «Лучше всего — одна
   бутылка в центре кадра, этикетка крупно, ровно и без бликов.» — старая подстрока цела,
   старый vitest-тест не трогал регэксп.
2. Новый ключ `scan.candidatesManyHint` = «Попробуйте снять одну бутылку крупнее.» —
   рендерится в `ScanScreen.tsx` внутри существующего блока «Возможно, это одно из:» ТОЛЬКО
   когда `result.candidates.length === 5` (полный top-5 без явного лидера — контрактный
   максимум, `contracts/image-scan.md` v0.4.11 п.1 — типичный след кадра со множеством
   бутылок в объективе). Блок и так открывается только при `not_in_catalog=true`, второе
   условие ничего не меняет структурно, просто явно. При < 5 кандидатах подсказка НЕ
   показывается (не всякая неуверенность — полка, например near-dup близнецы с 2 кандидатами).
   Про архив сканов ничего не писал (не по заданию, и вообще молчим о нём в интерфейсе).
3. Тесты: +2 новых юнит-теста (ровно 5 кандидатов → подсказка есть; 2 кандидата → подсказки
   нет) и дополнена проверка тихой подписи (`/одна бутылка в центре кадра/i`). `npm test`
   17 файлов / **84 теста** зелёные (было 82). `typecheck`/`build` зелёные, Node 24.18.0.
4. Живая проверка в браузере (vite dev, mock-режим): подпись под «Выбрать фото» отрендерилась
   корректно в одну строку, без переноса/обрезки. Ветку с 5 кандидатами глазами не смотрел —
   на машине уже был чужой процесс vite:5173 в `VITE_API_MODE=real` (проксирует на
   localhost:8000, там пусто → 502 на `/v1/scan/photo` и на онбординге тоже, до моей правки
   никак не относится) — не мой процесс, не трогал/не убивал; ветка полностью покрыта
   детерминированными vitest-проверками DOM (п.3), typecheck/build подтверждают отсутствие
