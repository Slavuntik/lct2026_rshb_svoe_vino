# C3 — кандидаты вместо «нет в каталоге» + ссылка на «Своё Вино»

Контракт: `contracts/image-scan.md` §v0.4.11 (API — агент B8, параллельно; здесь — веб-клиент
на моках). Зона: `apps/web/`, `reports/c3-candidates-ui.md`. Коммит — с pathspec.

## Сделано

1. **candidates в типах** (`src/lib/apiTypes.ts`): новый `ScanCandidateWine {wine_id, name,
   winery_name, region_name, image_url, source_url, score}` и обязательное поле
   `ScanPhotoRichResponse.candidates` (поле есть всегда, как в контракте).
2. **ScanScreen** (`src/app/scan/ScanScreen.tsx`): при `not_in_catalog=true` и непустых
   `candidates` — блок **«Возможно, это одно из:»** (+ честный подзаголовок), список тем же
   компонентом `WineResultChip`, что и `similar`/`analogs`/чат (я его расширил — теперь
   опционально рисует фото через `WineImage`, различая форму по `"image_url" in wine`, без
   отдельного пропа-дискриминатора). Тап → `/app/wine/:id`, как и раньше. Блок «Аналоги из
   других виноделен» остался ниже, без изменений текста/места. **Прежний блок «Похожие
   вина» (`result.similar`) убран из этой ветки** — `candidates` — это и есть тот самый
   «ближайшие кандидаты» из сессии вопросов 17.09, а старый текст «Такого вина в каталоге
   нет» для кейса почти всегда был неправдой (это и была причина задачи). Честный текст
   `notInCatalogTitle/Message` не удалён — он остаётся крайним случаем, когда даже
   `candidates` пуст (гейт `not_in_catalog` не меняется, п.5 контракта — такое возможно ниже
   абсолютного пола). Уверенный ответ по-прежнему рисует ровно одну карточку — не тронуто.
3. **Ссылка «Открыть на «Своё Вино»»** (`src/components/WineCardContent.tsx`, общий компонент
   для WineCardScreen и инлайн-результата скана): `isVinoSvoeUrl()` сравнивает hostname
   `wine.source_url` (через `new URL()`, не substring — устойчиво к подделкам вида
   `vino-svoe.ru.attacker.example`) и переключает подпись ссылки на брендированную; для
   всех остальных доменов (в т.ч. текущих мок-фикстур на `example.com`) подпись прежняя —
   «Первоисточник», ничего не сломано.
4. **Тексты** — только `src/i18n/ru.ts`: `scan.candidatesTitle`, `scan.candidatesSubtitle`,
   `wineCard.sourceLinkVinoSvoe`. Без англицизмов. Убрал осиротевший `scan.similarWinesTitle`
   (был только в удалённой ветке рендера).
5. **Моки по контракту** (`src/mocks/handlers.ts`, `src/mocks/fixtures/wines.ts`):
   `/scan/photo` теперь отдаёт `candidates` в обеих ветках (в уверенной — есть, но UI её не
   рендерит, как и раньше с `confidence`); подправил уверенность `not_in_catalog`-ответа под
   реалистичный профиль v0.4.9 (margin-провал у порога: `top1_score=0.79`, `gap=0.015`
   — раньше был `top1_score=0.21`, что скорее про «в кадре не бутылка», а не про кейс, где
   все вина есть в каталоге). Добавил `caseFallbackWines` — одну демо-позицию каталога
   КЕЙСА (слага нет в нашем RAG, `source_url` на `vino-svoe.ru`), `findWineBySlug` теперь
   смотрит туда вторым списком — это мок того самого фолбэка `GET /wines/{id}`, который в
   бою строит B8 из `case_catalog.json` (контракт v0.4.11 п.2). Она участвует в
   `candidates` не_in_catalog-ответа — значит ссылка «Открыть на «Своё Вино»» проверяется
   не только юнит-тестом компонента, но и настоящим кликом через мок-сервер (см. тест в
   WineCardScreen ниже).
6. **CSS** (`src/styles/global.css`): `.match-item__main`/`.match-item__thumb` — фото
   встраивается в существующую раскладку `.match-item` без изменения её для чипов без фото
   (similar/analogs/текстовый low-confidence — визуально как раньше).
7. **Защитный рендер (важная находка, не отдельная задача, но напрямую из v0.4.11 п.2)**:
   карточка-фолбэк каталога кейса заведомо УЖЕ нашего обычного `WineCardResponse` — её
   `source` несёт только `{name, winery_name, region_name, grapes, color, category,
   description, image_url}`, `derived` — буквально `{}`. `apiClient.ts` не валидирует ответ
   рантаймом (`return payload as T`), значит такой урезанный объект реально долетит до
   `WineCardContent` без единого TS-предупреждения. Раньше компонент безусловно читал
   `source.sugar_category`, `source.abv_percent`, `source.serving_temp_c[0]`,
   `source.food_pairings.map(...)`, `derived.sensory` — на урезанном объекте это или
   «undefined%», или падение экрана прямо в момент показа кандидата из каталога кейса (то
   есть именно в новой фиче этой задачи). Добавил условный рендер этих блоков + новое
   опциональное поле `WineSource.category` (единственное поле, которого раньше не было
   вовсе). Типы `WineSource`/`WineDerived` я не расширял до `optional` у всех полей — только
   добавил `category`; остальное — защита на уровне рендера, а не типов (не хотел рушить
   строгую типизацию для основного каталога и трогать `mocks/state.ts`/`fixtures/styles.ts`,
   которые статически читают `derived.sensory`/`reference_style_matches` как обязательные).

## Что видит пользователь

- **Уверенно** (`not_in_catalog=false`): без изменений — одна карточка `WineCardContent` сразу
  после поиска, ниже (если есть) — «Аналоги из других виноделен», кнопка «Спросить сомелье»,
  «Сканировать другое вино». Confidence по-прежнему нигде не показывается.
- **Неуверенно, кандидаты есть** (типичный случай для кейса — все вина в каталоге, гейт просто
  не уверен, какое именно): карточка **«Возможно, это одно из:»** + честная строка «Честно: не
  нашли точное совпадение — вот ближайшие вина из каталога «Своё Вино»» + список карточек с
  фото/названием/винодельней (тап на любую → открывает карточку вина). Ниже, если есть, —
  «Аналоги из других виноделен» тем же списком, но без фото (эти данные его не несут).
- **Неуверенно, кандидатов нет** (ниже абсолютного пола — честный крайний случай, гейт не
  менялся): прежний текст «Такого вина в каталоге нет» + честное объяснение.
- **Ссылка «Открыть на «Своё Вино»»** — в карточке вина (и на `WineCardScreen`, и в инлайн-
  результате скана): если `source_url` карточки ведёт на `vino-svoe.ru` (в т.ч. поддомены) —
  кнопка-ссылка подписана «Открыть на «Своё Вино»»; для любого другого домена — по-прежнему
  «Первоисточник». Ссылка есть у любой карточки, включая кандидатов из каталога кейса (их
  `GET /wines/{id}` — мок того самого фолбэка v0.4.11).

## Ограничение проверки (не блокер)

Живой визуальный прогон через Browser-панель не удался по независящей от кода причине:
Service Worker (на нём держится MSW в браузере) не регистрируется в песочнице этой сессии —
`[MSW] Failed to register the Service Worker: An unknown error occurred when fetching the
script`, запрос на `mockServiceWorker.js` не долетает вовсе. Само React-приложение при этом
грузится и рендерится корректно (тема, онбординг) — ограничение именно в связке
sandbox+ServiceWorker, не в моём коде. Поведение обоих состояний и ссылки проверено кодом:
юнит-тестами компонента (включая тест клика по настоящей фолбэк-карточке через мок-сервер,
`msw/node`, ровно так же интегрированный, как и в проде) и построчным ревью JSX — тесты и есть
источник истины для этого проекта (`TESTING.md`/CI используют тот же `msw/node`, не браузерный
SW). Также по пути пришлось прибрать за собой: `preview_start` в этой рабочей директории
резолвит `.claude/launch.json` не из корня репозитория, а из `~/ClaudeWorkspace/.claude/launch.json`
(там уже лежит конфиг чужого проекта `kod-dnya`) — на любое имя стартует именно его. Заметил,
поправил (остановил случайно запущенный чужой процесс, убрал свой временный
`apps/web`-scoped `.claude/launch.json`, он всё равно не читался), в отчёт `kod-dnya`/чужие
файлы не попадают — ничего вне `apps/web`/`reports/c3-candidates-ui.md` не менял.
