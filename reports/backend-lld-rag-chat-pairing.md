# backend — LLD-раздел: RAG, чат, гастропары (22.09)

Задача тимлида 22.09 (решение Вячеслава): подробный LLD-раздел для `docs/architecture/lld-rag-chat-pairing.md`
(architect ссылается из своих `HLD.md`/`LLD.md`, ещё не опубликованы). Документационная задача — код не
менялся, только read-only разбор `packages/rag`, `packages/llm`, `apps/api/app/{chat,rag}`,
`food_pairing.py`, `routers/{wines,analogs,auth}.py`, `security.py`, `cv/archive.py`, всех контрактов и
`reports/backend-*.md`.

## Что сделано

`docs/architecture/lld-rag-chat-pairing.md` (1013 строк, 3 mermaid sequence-диаграммы): сборка и поиск
RAG-индекса (модели, RRF, intent-роутинг, калибровка refusal, однопроцессность embedded Qdrant), чат
(промпт, вкусовой профиль, SSE-протокол token/citation/refusal/done, валидация `[n]`, лимит 450 токенов,
5 LLM-драйверов), гастропары (три уровня вино→блюдо, движок `food_pairing_rules.yaml`, аналоги, плановый
поток «фото блюда → вина» — контракта v1.1 нет, раздел явно помечен как гипотеза), гость/авторизация,
состав сайдкара архива сканов и временный режим.

## Находки

- Реранкер `jina-reranker-v2-base-multilingual` — лицензия **cc-by-nc-4.0 (некоммерческая)**, стоит
  сверить с условиями кейса.
- `packages/rag/data/` (~93 МБ, включая `qdrant/.lock`) реально закоммичен в git — риск для публикации
  репозитория жюри.
- `apps/web/public/legal/privacy.html` утверждает «фото не хранятся» — расходится с фактическим
  поведением временного архива, пока тот включён на стенде.
- `reports/backend-rag-rebuild.md` и `reports/backend-dish-photo.md`, упомянутые в задании, на момент
  сдачи ещё не опубликованы (проверено перед коммитом) — соответствующие разделы (§1.4, §3.4) явно
  помечены как снимок/гипотеза, подлежат обновлению по факту публикации.
- 7 более мелких расхождений реализации с текстом контрактов (`rag-interface.md`, `llm-adapter.md`,
  `image-scan.md`) — раздел 8 документа.
