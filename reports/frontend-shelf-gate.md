# frontend: гейт раздела «Витрина» по живому health-чеку (26.09)

Проблема (`reports/architect-post-merge-review.md` §3): `/app/shelf` грузит iframe `/shelf-ui/…`,
который в проде разруливает только dev-proxy Vite; nginx-стенда отдаёт SPA-фолбэк (200,
наш index.html) — жюри видит свой же лендинг в рамке. Решение тимлида: не прятать раздел
навсегда, а показывать по факту доступности сервиса витрин.

## Сделано
- `apps/web/src/lib/shelfAvailability.ts` (новый) — `probeShelfHealth()`: `GET /v1/shelf/health`
  (тот же префикс, что уже проксирует `vite.config.ts`), `AbortController` с таймаутом 1.5 с,
  критерий живости — `response.ok` **и** `Content-Type: application/json` (не только код ответа —
  фолбэк nginx/наш SPA всегда отдаёт `text/html` с кодом 200). Адрес — `VITE_SHELF_UI_URL`
  (необязательная переменная сборки), без неё — тот же относительный путь на своём origin, что
  раздел использует сейчас. Один запрос на вкладку (кеш-промис), хук `useShelfAvailability()`
  не блокирует рендер (`"pending"` ведёт себя как `"unavailable"`).
- `apps/web/src/app/shelf/ShelfUnavailableScreen.tsx` (новый) — честная заглушка: «Раздел
  витрины доступен, когда запущен сервис распознавания витрин» (текст тимлида дословно).
- `apps/web/src/app/AppShell.tsx` — точечная правка: пункт навигации и роут `shelf` гейтятся
  по `shelfAvailability === "available"`; `ShelfScreen.tsx` (зона Михаила) не тронут ни строкой.
- `apps/web/src/i18n/ru.ts` — один новый ключ `shelf.unavailable`.
- `apps/web/src/mocks/handlers.ts` — дефолтный мок `GET /v1/shelf/health` воспроизводит саму
  прод-ловушку (200, `text/html`), чтобы остальные тесты жили без спец-настройки; MSW
  `onUnhandledRequest:"error"` иначе падал бы на новом фоновом запросе при каждом рендере `AppShell`.

## Как воспроизвести
`cd apps/web && npm test -- --run && npm run typecheck && npm run build`.

## Риски / на заметку
- `VITE_SHELF_UI_URL` не подключена в пайплайн сборки/деплоя — по умолчанию используется
  относительный путь (сегодняшнее поведение), так что для корректности ничего не требуется;
  если devops вынесет shelf-finder на отдельный домен, переменную можно задать при сборке.
- Сейчас `infra/ams3/nginx-somelye.conf` проксирует `location /v1/` целиком на `apps/api`
  (не на SPA-фолбэк) — значит `/v1/shelf/health` там сегодня, скорее всего, упадёт в 404 от
  apps/api, а не в html-ловушку; итог тот же («недоступен»), но за счёт `!response.ok`, а не
  Content-Type-гварда. Гвард всё равно нужен и покрыт тестами — фолбэк-путь может измениться.
- Таймаут 1.5 с — при холодном/медленном старте сервиса витрин пункт останется скрыт до
  следующей загрузки приложения; это осознанный fail-closed, безопаснее для жюри.
- Предложений к contracts/ нет — `/v1/shelf/*` вне `openapi.yaml` по ратификации архитектора.
