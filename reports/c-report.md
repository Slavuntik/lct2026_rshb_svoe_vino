# Отчёт агента C · Клиент (веб + iOS)

Зона: `apps/web/`, `apps/shell/`, `reports/c-report.md`. Контракты: `contracts/openapi.yaml`
**v0.2** (после ревью 01 — см. раздел «Контракт v0.2» ниже), `contracts/tokens.css`,
`contracts/events.md` v0.1.

## Что сделано

**apps/web** — Vite + React 19 + TypeScript + react-router 7, PWA, полностью рабочее в
мок-режиме (MSW) приложение:

- Маршрут `/` — лендинг: оффер, три фичи (скан→карточка / сомелье с цитатами / аналог
  импортного), 18+ интерстициал (разово, запоминается в localStorage), waitlist-форма
  (email + обязательное согласие, без согласия кнопка неактивна), кнопка «Попробовать в
  браузере» (гостевой вход, см. ниже), дисклеймер 18+/алкоголь в футере.
- Маршрут `/app/*` — шесть экранов и ни одним больше:
  1. `onboarding` — дата рождения (гейт 18+, honest блок без формы при отказе) + согласия
     по скоупам (base обязателен, profiling/geo/marketing — опционально);
  2. `scan` — фото (file input + подсказка камеры на мобильном) с явным чекбоксом согласия
     → `POST /scan/ocr`, и текстовый ввод → `POST /scan/resolve` как **равноправный** путь;
     low_confidence → список выбора, пустой результат → честное «не нашли»;
  3. `wine/:wineId` — карточка вина (source/derived/source_url/similar), 7-осевой
     сенсорный профиль, переход «спросить сомелье про это вино»;
  4. `chat` — SSE-парсер (token/citation/done/refusal) поверх fetch (EventSource с Bearer
     невозможен — ревью 01, риск 11), режим-чип «Аналог импортного» → `POST /analogs`;
  5. `taste` — паспорт вкуса: свайпы (кнопки + pointer-drag), 7-осевой вектор, топ-стили;
     честный гейт для гостей/без scope profiling вместо попытки свайпа;
  6. `profile` — «Мои данные»: согласия (переключатели), апгрейд гостя до полного
     аккаунта (email/пароль), выгрузка данных (скачивание JSON), удаление аккаунта
     (модалка подтверждения).
- i18n: свой хук (`src/i18n`), словарь `ru.ts` (полный) + `en.ts` (пустой, честный фолбэк
  на ru), ни одной строки интерфейса хардкодом в JSX — проверено grep-тестом.
- `tokens.css` скопирован **дословно** из `contracts/` (byte-for-byte, см. проверку ниже),
  хардкода цветов в компонентах нет. Шрифты — Google Fonts (Cormorant + IBM Plex
  Sans/Mono), загрузка асинхронная (см. «Lighthouse» ниже).
- API-клиент (`src/lib/apiClient.ts`) — вручную по `openapi.yaml`, типы в `apiTypes.ts`.
- MSW: 6 вымышленных вин (`src/mocks/fixtures/wines.ts`, форма полей — как в
  `catalog/wines/<slug>.json` у vines, но winery/name/регион полностью выдуманы),
  обработчики на все 20 путей контракта, включая честную SSE-эмуляцию чата и наивный
  `resolve_style` для `/analogs`.
- Аналитика (`src/lib/analytics.ts`) — типобезопасно по словарю `events.md`, транспорт —
  `POST /events` (см. v0.2), пишет `props._v`.
- PWA: `manifest.webmanifest`, SVG-иконки (обычная + maskable), офлайн — баннер
  «нет сети» на `useOnlineStatus()` (без Service Worker — по прямому указанию
  оркестратора, риск двойной регистрации SW с MSW и «вчерашняя сборка в кэше» на демо).
- Capacitor (`apps/shell/`): `capacitor.config.ts` (appId-плейсхолдер
  `ru.svoysomelye.app`, webDir → `apps/web/dist`), iOS- и Android-проекты сгенерированы.
- **OCR-плагин** (`apps/shell/plugins/ocr-plugin/`) — TS-интерфейс + **полная** Swift-
  реализация на Vision (не заглушка — см. «Контракт v0.2 / смена объёма» ниже).

### Lighthouse — что реально было узким местом

Промежуточный вывод по ходу работы оказался неверным: я предположил, что мок-слой
(MSW-чанк, 162 КБ gzip) конкурирует за первый рендер, и вынес его старт из-под
`await` перед `createRoot().render()` (`src/lib/mockBootstrap.ts`, `apiClient` сам
дожидается готовности мока перед реальным запросом). Правка сама по себе корректна
и осталась в коде, но замер **показал ухудшение** (87→80/81) — дело было не в этом.

Настоящая причина: `<link rel="stylesheet" href="fonts.googleapis.com/...">` —
render-blocking запрос на сторонний домен, в трассировке занимал **~530 мс** сам по
себе (`network-requests` audit) и держал первую отрисовку. Три семейства шрифтов
(Cormorant + IBM Plex Sans + IBM Plex Mono) через один блокирующий `<link>` в `<head>`.

Фикс — классический loadCSS-приём в `index.html`: `media="print" onload="this.media=
'all'"` + `<noscript>`-фолбэк. Google Fonts остались (бриф прямо требует их, самостоятельно
на self-hosting не уходил), но перестали блокировать рендер. Результат: FCP 3.5с→1.9с,
LCP 3.9с→2.6с, Perf 80→95 (два прогона подряд — 95 и 96, стабильно).

Вывод для остальных агентов и на будущее: если лендинг снова просядет по Lighthouse —
сначала смотреть `network-requests`/`render-blocking-resources` на реальные тяжёлые
цепочки, а не гадать по интуиции (я потратил один лишний прогон именно на этом).

## OCR-плагин: что реально проверено, а что — нет

Полная реализация (`apps/shell/plugins/ocr-plugin/`): TS-интерфейс
(`src/definitions.ts`), веб-реализация — честный `unavailable()` (OCR только нативный,
на вебе и на iOS до сборки плагина равноправный путь — ручной ввод текста), и **боевой**
Swift (`Sources/SvoySomelyeOcrPlugin/OcrPlugin.swift`, ~100 строк): `CAPPlugin` +
`CAPBridgedPlugin`, `VNRecognizeTextRequest` (`.accurate`, `usesLanguageCorrection`,
`recognitionLanguages = ["ru-RU","en-US"]`), поправка EXIF-ориентации кадра под
`VNImageRequestHandler`, отдача `{text, confidence}` в TS-слой.

Проверено на этой машине (Xcode нет, только Command Line Tools):

1. **`npx cap sync ios` и `npx cap sync`** — плагин обнаружен по полю `capacitor` в его
   `package.json`, признан SPM-совместимым (наличие `Package.swift` в корне пакета) и
   **автоматически вписан** в сгенерированный `ios/App/CapApp-SPM/Package.swift`:
   `.package(name: "SvoySomelyeOcrPlugin", path: "../../../plugins/ocr-plugin")` +
   продукт в зависимостях таргета. `ios/App/App/capacitor.config.json` содержит
   `"packageClassList": ["OcrPlugin"]` — нативный класс распознан по имени.
2. **Реальный SPM-резолвинг сработал.** Фоновая индексация редактора сама подтянула
   `capacitor-swift-pm` с GitHub и запинила версию — `Package.resolved` зафиксировал
   `8.5.0` (совпадает с версией `@capacitor/ios`, конфликтов в графе зависимостей нет).
3. **`swiftc -parse` на `OcrPlugin.swift` и на `Package.swift` — 0 ошибок** (синтаксис
   корректен; `-parse` не резолвит импорты, поэтому это не замена полной сборки).
4. **Попытка полной компиляции (той же фоновой индексацией) упёрлась в `no such module
   'Capacitor'`** — ожидаемо: сама библиотека Capacitor.framework у себя внутри
   зависит от iOS SDK, которого без полного Xcode на этой машине нет. Это НЕ ошибка в
   моём коде — это ровно то ограничение среды, которое было в брифе с самого начала
   («Xcode нет — iOS не собирать»). Оркестратор подтвердил этот же диагноз независимо.

**Блокер (честно, не скрываю):** я не могу дать 100% гарантию, что Swift-код
скомпилируется без единой правки на publish-Mac — семантическая проверка типов
(в отличие от синтаксиса) требует реального Capacitor.framework + iOS SDK, которых
здесь физически нет. Код вычитан вручную ещё раз построчно по прямому запросу
оркестратора (сигнатуры `CAPPlugin`/`CAPPluginCall`/`VNRecognizeTextRequest` и т.д.
сверены с образцом-шаблоном, который сгенерировал сам `cap add ios`); исправлена
одна находка при повторной вычитке (затенение имени `request` в замыкании Vision —
не баг, но убрал для чистоты). Дальше — на публикующем Маке: `cd apps/shell &&
npm run sync:ios && npx cap open ios`, первая сборка покажет, если что-то не так, и
это будет быстрый точечный фикс, а не архитектурная переделка.

## Разумные допущения (зафиксировано, не спрашивал)

- **Дыра в контракте: сцене свайпов негде брать очередь кандидатов.** В openapi.yaml
  нет discovery-эндпоинта (`GET /wines/random` или аналог) — только `GET /wines/{id}`
  по уже известному id. Временно — сид-список из 6 id тех же демо-вин
  (`src/app/taste/seedWineIds.ts`, помечен TODO). **Предложение к контракту:**
  добавить `GET /wines/random?count=N` (или `filters`-параметр к нему) — без этого
  паспорт вкуса на реальном каталоге ~2000 вин физически нечем наполнить.
- **`GET /taste/profile` не гейтится по scope** (в отличие от `POST /taste/swipes`,
  где это явно написано в контракте) — трактовал как «можно смотреть базовый вектор
  всем аутентифицированным», гейт на UI делаю клиентски (честный экран-приглашение для
  гостя до попытки). Если backend решит иначе — фронт уже готов к 403
  `consent_required` на этом эндпоинте тоже (тот же catch, что и на swipes).
- **`GET /wines/{id}` 404 и его код ошибки** — в контракте не описан прямо (только 200).
  Использую `not_found` (он есть в общем словаре кодов v0.2) — согласуется с остальным
  API.
- **Email/пароль апгрейда гостя** нигде не хранятся, кроме как в форме на момент
  отправки; дата рождения — да, хранится в `localStorage` (это собственные данные
  пользователя о себе для его же апгрейда, не тестовые фикстуры — не путать с правилом
  «никаких ПД в фикстурах/логах», которое соблюдено: фикстуры вин полностью вымышлены,
  события — только структурные props).
- **Иконки/картинки бутылок** — инлайн SVG (data URI), без внешних хостов: офлайн-
  надёжность и Lighthouse не зависят от постороннего CDN картинок.
- **Six screens** — код-сплит `/app` от `/` через `React.lazy`, чтобы лендинг не тянул
  шесть экранов и MSW в свой первый чанк (актуально теперь и для Lighthouse — см. выше).

## Известные ограничения среды (не блокеры продукта)

- **MSW Service Worker не регистрируется в песочнице Browser-пейна этой сессии**
  (`navigator.serviceWorker.register()` падает с «unknown error fetching the script»
  даже для файла, который сам по себе отдаётся по HTTP 200, — проверено `curl`).
  Это ограничение конкретно этого инструмента предпросмотра, не баг приложения:
  та же логика проверена гораздо строже через `msw/node` в 30 vitest-тестах, а в
  обычном Chrome/Safari (открыто и проверено через реальный `open -a "Google Chrome"`)
  registration проходит штатно. Если ревьюер откроет `npm run dev` в обычном браузере —
  всё должно работать; если нет, первое, что проверить — не CSP/расширение ли блокирует
  Service Worker.
- Docker/CocoaPods на машине нет — не понадобились: Capacitor 8 по умолчанию ставит
  iOS-проект на SPM, `pod`/`Podfile` в этой конфигурации не участвуют вообще.

## Постфактум: контракт v0.2.1

После коммита этого отчёта в репозитории появился `contracts/openapi.yaml` v0.2.1
