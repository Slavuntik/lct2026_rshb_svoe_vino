# ml-lead: «Блюда из птицы» — калибровка, не осознанное решение (22.09)

Проверка тимлида по санити backend (`reports/backend-dish-photo.md`): «Блюда из птицы» —
6/6 красное вместо ожидаемых белых/лёгких красных. Метод — как в отчёте backend
(`RAG_PROVIDER=real`, своя копия `packages/rag/data` без `.lock`, весь каталог 2103 вина).

## Диагноз: ошибка калибровки вектора, не осознанное решение

`portal_tag_defaults["Блюда из птицы"]` = `{fat:0.5, protein_heavy:0.6, weight:0.5}` —
`protein_heavy=0.6` ровно на пороге правила `protein_needs_tannin` (`when: protein_heavy>=0.6,
weight>=0.5`, `require: wine.tannin>=0.55`, explain дословно «мясо просит красное плотное» —
правило написано для тяжёлого красного мяса, не птицы). Проверил РЕАЛЬНЫЙ каталог: тегом
«Блюда из птицы» в `source.food_pairings` помечено 427 вин, из них **234 белых (54.8%) / 116
красных (27.2%) / 64 розовых / 12 оранжевых** — портал сам не считает тег «красным». Но т.к.
только `tannin>=0.55` (фактически только «красное тихое») проходит `require`, эти вина получали
score=1.000, а ВСЕ 234 белых — score=0.500 (только `weight_matches_body`) — 9 танинных вин
(линейка Каберне Фран) монопольно заняли топ-6 чисто по артефакту сортировки внутри яруса
`catalog` (порог/фильтрация тегом не занимается — сортирует только счёт, `apps/api/app/
dish_pairing.py`, код не трогал). Это ошибка калибровки: реальное распределение тега — большинство
белых, современная практика гастрономии не требует высокого танина для птицы.

## Фикс — 1 значение, `pipeline/ref/food_pairing_rules.yaml`

```diff
-  Блюда из птицы: {fat: 0.5, protein_heavy: 0.6, weight: 0.5}
+  Блюда из птицы: {fat: 0.5, protein_heavy: 0.55, weight: 0.5}
```

`protein_heavy` ниже порога 0.6 → `protein_needs_tannin` для птицы больше не применяется;
остаётся только `weight_matches_body` (тот же единственный механизм, что уже даёт «Блюда из
рыбы» чистый белый результат — не новое поведение, а перенос уже работающего паттерна).

## Тесты гастропар «вино → блюдо» — 4 из 536 требуют обновления пиннед-значений (не мой файл)

`cd apps/api && .venv/bin/pytest -q` → **520 passed, 12 skipped, 4 failed** (было 524/12 до
правки). Файл общий (`pipeline/ref/food_pairing_rules.yaml`), направление то же — это
математически неизбежное следствие фикса, не побочная поломка логики: все 4 теста пинуют
ТОЧНЫЕ старые числа, а не проверяемый механизм, и старые числа сами были во власти той же
ошибки калибровки (например, тест 1 давал тэгу «Блюда из птицы» скор 0.5 для танинного
красного — тот же самый баг, только в обратном направлении). Проверила КАЖДЫЙ: искомый
механизм (hard-block/тай-брейк/деградация на heuristic) по-прежнему работает верно, меняются
