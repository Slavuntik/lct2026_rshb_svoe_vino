# Обзор литературы и практик: как улучшить сканер

Собрано 2026-09-15 пятью параллельными исследовательскими агентами (поиск и чтение arXiv, GitHub,
карточек HF, документации, новостей). Цифры взяты из первоисточников, где агенты смогли их
открыть; непроверенное помечено **[не проверено]**, инженерные оценки — **[оценка]**. Перед
цитированием в питче ключевые цифры стоит перепроверить по ссылке.

План работ на основе обзора — [PLAN.md](PLAN.md).

## Что из обзора проверено на наших данных

Обзор — это гипотезы. Ниже итоги проверок; подробности и цифры — [WORKLOG.md](WORKLOG.md),
состояние пунктов плана — таблица прогресса в [PLAN.md](PLAN.md). Все замеры пока на синтетике.

| Идея обзора | Итог у нас |
|---|---|
| Цилиндрические ракурсы эталона (Huang et al., 2404.08820) | **Подтвердилось без обучения:** мультиракурсная галерея дала +2,4 п.п. top-1 на `synth_v2` и +1,4 п.п. на `synth_v1`. Оговорка: повороты запросов и эталонов делает одна функция, на v2 выигрыш может быть завышен |
| Обучаемый выбор рамки вместо правил | **Подтвердилось:** бустинг по геометрии и результату поиска +1,9 п.п. top-1 на `synth_v2`; ручное правило «вес рамки + уверенность поиска» не дало ничего |
| Дообучение детектора (RF-DETR и подобные) ради выбора бутылки | **Отменено:** нужной бутылки нет ни в одной рамке лишь у 1% кадров. Узкое место — выбор среди рамок, а не их качество |
| Улучшение выбора рамки (цель обучения, объединение кандидатов, проверка совпадений) | **Не подтвердилось:** 0,669 / 0,402 / 0,667 против 0,661 у нынешнего выбора при потолке 0,775. Из самого кадра признак «та самая бутылка» не извлекается — нужен прицел в интерфейсе |
| ALIKED + LightGlue вместо SIFT | **Не подтвердилось:** на 2103 запросах отложенная половина 0,722 против 0,723 у SIFT (21:22, p = 1,0); выигрыш появлялся только там, где подбирались константы. Дороже на 118 мс и требует ~1 ГБ признаков эталонов |
| Маски отличающихся областей внутри серии | **Не подтвердилось:** маска улучшает свои признаки, но поверх текущего скора мешает (0,885 против 0,909) |
| ELViS: переранжирование по локальным дескрипторам | **Не подтвердилось:** +4,7 п.п. на `synth_v2` (p < 0,001), но на `synth_v1` незначимо и без изменений на сериях, а на реальном фото верное вино уступает первое место розовому двойнику — сопоставитель не видит цвета. Цена: 3,16 ГБ дескрипторов и второй бэкбон в онлайне |
| Текстовый канал кандидатов и RRF | **Не подтвердилось на синтетике:** RRF рушит top-1 (0,819 → 0,642), полноту не поднимает; OCR слишком короткий |
| Обученное слияние признаков вместо ручных весов | **Частично:** по top-1 не лучше ручного веса SIFT; ценно как уверенность для отказа, но после исправления утечки AUROC 0,815, а не 0,95 |
| Более сильный бэкбон (SigLIP2 so400m-patch16-512) | **Не подтвердилось:** top-1 0,690 против 0,690 у нынешнего на рамках из разметки (34:34, p = 1,0), при этом на 30% медленнее |
| Дообучение эмбеддинга под каталог (ArcFace и подобное) | **Отклонено после проверки:** линейное преобразование поверх замороженных векторов даёт +10 п.п. на винах, которых не видело, но обучение на всех винах (как в продакшене) запоминает синтетический рендер и ломает реальное фото — верное вино уезжает с 1-го места на 36-е. Без нескольких реальных снимков на вино этот путь закрыт |
| VLM для чтения полей этикетки | **Не по времени:** Qwen3-VL-4B — 10–14 с на фото при SLA 3 с; выключено |
| Три полосы решения и честный отказ | **Частично:** полосы есть, но отказ для вина «той же серии, которого нет в каталоге» на синтетике не решён ничем |

## 0. Главные выводы

1. **Узкое место не в глобальном эмбеддинге, а в двух местах:** выбор нужной бутылки в кадре
   (у нас −8 п.п. top-1 относительно идеального кропа) и порядок кандидатов внутри серии
   (top-5 0,911 при top-1 0,858). Это же видят в свежих работах по товарам: R@5 ≈ 94,5% при
   R@1 на 17,5 п.п. ниже (2605.18029), top-5 94,7% при top-1 80,7% (2607.09888).
2. **Есть работа ровно про наш случай** — винные этикетки, одно фото на вино (Huang et al.,
   arXiv 2404.08820): цилиндрическая перепроекция этикетки эталона под разные ракурсы подняла
   top-1 с 76,4% до 91,2%.
3. **Путаницу серий не решит ни один матчер** (SIFT, LightGlue, RoMa): вёрстка честно совпадает.
   Нужны признаки отличающихся областей (цвет, отдельные слова) и чтение полей этикетки.
4. **Мультимодальные LLM хорошо выбирают из малого числа кандидатов**, но слабы в русском OCR
   (Qwen3-VL ≈ 72% на внутреннем тесте, у GPT-4o на MTVQA русский — худший язык). Опираться
   на сопоставление полей с карточками, а не на транскрипцию.
5. **Отказ «не найдено»** надо обучать как классификатор на leave-one-out негативах, а не порогом
   по косинусу, подобранным на 2–3 примерах.
6. **Для 20 баллов за функцию после поиска** портал «Своё вино» (vino-svoe.ru, РСХБ, октябрь
   2025) уже задаёт образец: карточка с сочетаниями блюд, похожими винами, народным рейтингом и
   кнопкой «Сканировать». LLM-сомелье должен выбирать только из ID каталога.
7. **Синтетика оптимистична** — это подтверждают все направления: нужны 100–300 реальных фото
   для валидации, иначе решения подбираются под генератор.

## 1. Глобальные эмбеддинги и instance-level retrieval

### Бенчмарки моделей

| Источник | Результат |
|---|---|
| ILIAS (CVPR 2025, arXiv 2502.11748), mAP@1k, 5M дистракторов | DINOv3-L@768 31,1; PE-L@336 27,1; SigLIP2-L@512 25,3; SigLIP-L@384 24,2; DINOv2-L 18,5; EVA-CLIP-L 13,6. С линейной адаптацией: PE-L 39,6, SigLIP2-L 37,3, DINOv3-L 32,9 (VLM-модели выигрывают сильнее) |
| Visual Product Search Benchmark (nyris, arXiv 2603.17186, 03.2026), R@1 без дообучения | Products-10K: Cohere Embed v4 66,5; **SigLIP2-So400m/384 66,0**; PE-Core-L/336 65,7; Gemini Embedding 2 62,0; DINOv3-L 59,2 (при 224 px); jina-v4 56,4; DINOv2-L 50,2. SOP: SigLIP2 80,3; PE 80,1; DINOv3 66,6 |
| Grocery Product Retrieval (arXiv 2605.18029, 05.2026) | SigLIP2-gopt-384 R@1 0,770, PE-Core-L 0,758, SO400M-378 0,749; выше 384 px прирост почти нет; R@5 94,5% при R@1 на 17,5 п.п. ниже |
| Qwen3-VL-Embedding (arXiv 2601.04720) | MMEB-V2 77,8; цифр по поиску товара по фото нет; 2B/8B тяжелы |

Вывод: SigLIP2 so400m — правильная база; PE-Core (Apache-2.0) сопоставим; мультимодальные
LLM-эмбеддинги не лучше и тяжелее. Проверить стоит `siglip2-so400m-patch16-512` и
PE-Core-L/G как второй голос ансамбля **[оценка +1…3 п.п.]**.

### Дообучение при одном эталоне на класс

- **Винные этикетки, 3D-аугментация** (Huang et al., arXiv 2404.08820, 04.2024): 885 вин по
  одному веб-фото, тест 3694 фото с телефона. Этикетка моделируется цилиндром (по эллипсам
  верхнего и нижнего края), перепроецируется под разные позы — 320 синтетических изображений
  на эталон; ViT-S/16 (DINO) + batch-all triplet. **Top-1: 76,39% (2D-аугментация) → 91,15%
  (3D)**; замена чёрного фона на случайный +3,27 п.п. Запрос при тесте тоже распрямляется.
  Код не опубликован; тест на тех же классах, с SigLIP не сравнивали.
- **Cat2Real** (Walmart, arXiv 2607.09888, 07.2026): DINOv3-L-384 + triplet, первые 12 блоков
  заморожены; 196 тыс. реальных фото, 27 тыс. товаров. **Top-1 53,83% (zero-shot) → 80,73%**;
  без hard negatives из похожих товаров −5,92 п.п.; на невиданных товарах 80,23% — новые
  позиции без переобучения работают.
- **1-е место Google Universal Image Embedding** (arXiv 2210.08473): OpenCLIP ViT-H + ArcFace,
  сначала голова, затем бэкбон; 0,728 mP@5.
- **FashionSigLIP2** (arXiv 2606.27708, 06.2026): полное дообучение SigLIP2-base с LwF и
  WiSE-FT (α=0,4) — R@10 0,679 → 0,795; LoRA r=16 хуже полного; без LwF/WiSE-FT портится
  качество вне домена.
- **Schall et al.** (arXiv 2409.01936): CLIP + ArcMargin на 22,6 млн изображений ≈ +10 п.п.
  **[не проверено по таблице]**.

### Без обучения

- **ELViS** (arXiv 2603.28603, 03.2026, github.com/pavelsuma/ELViS, Apache-2.0): переранжирование
  по соответствиям патч-дескрипторов, 96 тыс. параметров, 101 мкс на пару. Готовый чекпойнт
  `siglip2_elvis_gld` для SigLIP2-So400m@512: ILIAS 22,4 → 41,3; SOP 62,2 → 72,1;
  INSTRE 89,8 → 93,5. Для товаров лучше версия, обученная на SOP (чекпойнта в README нет).
  **[оценка у нас +2…5 п.п.]**
- **Линейная адаптация UnED** (репозиторий ILIAS): готовые слои для моделей статьи, не зависит
  от классов **[наличие слоя для so400m не проверено]**.
- Alpha-QE, k-reciprocal, диффузия на графе — подтверждений для «одного эталона на класс» нет;
  соседи запроса у нас — вина той же серии, расширение запроса скорее вредно.
- Генерация ракурсов диффузией (SV3D, Zero123) искажает текст этикетки — не рекомендуется;
  детерминированная цилиндрическая перепроекция безопаснее. Горизонтальный флип в TTA ломает текст.

### Реальные системы

- **Vivino:** сканирование на Vuforia Cloud Recognition (кейс PTC: 97,5% сканов распознаются
  автоматически, остальное вручную), OCR винной карты — ABBYY **[дата кейса не проверена]**.
- **Width.ai** (блог вендора): детектор → дообученный эмбеддинг → OCR как тай-брейк между
  визуально одинаковыми вариантами → порог уверенности; RP2K top-1 CLIP 41% → 89%.
- **Li & Ma, PeerJ CS 2022** (вина, 548 тыс. фото, 17 тыс. брендов, 260 тыс. суббрендов): CNN
  по бренду 93,51%, SURF по суббренду 84,03% — визуальные признаки упираются в потолок на
  уровне «вариант внутри серии».

## 2. Локальные признаки, верификация, нормализация

### Замены SIFT (скорость на RTX 3090 из статей)

| Метод | Качество | Скорость | Лицензия |
|---|---|---|---|
| SuperPoint + LightGlue | MegaDepth AUC@5 49,9 | 30,7 мс на пару при 1200² | LightGlue Apache-2.0; **SuperPoint — некоммерческая** |
| ALIKED / DISK + LightGlue | близко к SP+LG | десятки мс | ALIKED BSD-3, DISK — в kornia |
| EfficientLoFTR (CVPR 2024) | AUC@5 55,4–56,4 | 27–40 мс | **противоречие:** GitHub «Project Registration License», HF — Apache-2.0 |
| RoMa v1 / v2 | WxBS 60,8 / 55,4 | 303 мс (v1) | MIT, внутри DINOv3 со своей лицензией |
| LoMa (arXiv 2604.04931, ECCV 2026) | WxBS +29,5 mAA к ALIKED+LG | размер как LightGlue, скорость не опубликована | MIT / Apache-2.0 |
| XFeat | ниже LightGlue | ~1400 FPS на 4090, реальное время на CPU | Apache-2.0 |
| MASt3R | — | 198 мс на A40 | **CC BY-NC-SA** — не подходит |

Все бенчмарки — 3D-сцены; цифр для «фото этикетки ↔ студийный эталон» нет. Любой матчер даст
больше inliers на реальных фото, но **не отличит вина одной серии**.

### Проверка отличий текста и цвета

- AMES (ECCV 2024), SuperGlobal, R2Former заточены под «тот же объект», не под «другое слово на
  той же вёрстке»; без дообучения прироста на сериях не ожидается **[оценка]**.
- **TSIDL** (Sensors, 08.2023): для похожих упаковок лекарств вырезка области с отличиями подняла
  точность группы с 70% до 91,59% — косвенное подтверждение идеи «сравнивать только отличающиеся
  области».
- Сравнение после выравнивания гомографией (NCC/SSIM по патчам, ΔE в Lab) — готовых статей с
  цифрами для этикеток нет; проверять A/B.
- **Счёт по абсолютному числу inliers смещён** к текстурным эталонам (наш случай: розовый 87
  против белого 63) — нужны доля inliers, покрытие этикетки и калиброванное слияние.

### Нормализация фото

- **Цилиндрическое распрямление этикетки:** Huang et al. 2404.08820 (см. выше); открытый код
  github.com/Nepherhotep/unwrap_labels **[лицензия не проверена]**; флаконы лекарств (MDPI MAKE
  2022): ключевые точки этикетки PCK@0.03 = 97%.
- Удаление бликов (UnReflectAnything, arXiv 2512.09583) проверялось на матчинге, но без сравнения
  с исходными снимками — доказательство слабое.
- Баланс белого, CLAHE, ретинекс, deblur, суперразрешение — свежих цифр прироста для retrieval
  или OCR этикеток не найдено. Решать только по нашим реальным фото.

- **RF100-VL** (arXiv 2505.20612): после дообучения качество Grounding DINO одинаково с именами
  классов и с индексами — открытый словарь для узкой задачи не нужен.
- Готовых весов «бутылка на полке» с явным выигрышем не найдено (SKU-110K — только как предобучение).
- **Сегментация:** SAM 2.1 (Apache-2.0; tiny 91 FPS на A100) с промптом рамкой; SAM 3
  (11.2025, 848M) не лучше SAM 2.1 по точке/рамке и тяжёлый; MobileSAM ≈ 12 мс на GPU.
  Прирост маски для retrieval не измерен — гипотеза.
- **Выбор «той самой» бутылки:** Google ML Kit «most prominent object» (алгоритм не раскрыт),
  Alibaba Visual Search (KDD 2018) — детекция главного объекта, **Region-R1** (arXiv 2604.05268):
  выбор региона запроса по пригодности для поиска даёт до +20% conditional R@1 в другом домене.
  Практический вывод: брать 2–3 рамки, считать поиск по каждой, выбирать по комбинации
  центральности, площади, скора и отрыва.
- **Синтетика для детектора:** Cut, Paste and Learn (arXiv 1708.01642) — смешивать режимы
  блендинга; Simple Copy-Paste (arXiv 2012.07177) — сильный scale jitter; NVIDIA TAO Retail OD —
  320 тыс. синтетических кадров + ~600 реальных.
- **Без детектора** (центральные кропы разного масштаба) — прямых подтверждений нет; годится как
  запасной путь при низкой уверенности детектора.

## 4. OCR, VLM, отказ от ответа, текстовый канал

### OCR кириллицы на фото

- **PP-OCRv5 eslav / cyrillic** (PaddleOCR 3.0, arXiv 2507.05595, Apache-2.0): точность строк
  81,6% / 80,3% на внутреннем тесте (+31,4 п.п. к прошлой версии). PP-OCRv6 кириллицу не
  поддерживает.
- **CC-OCR** (ICCV 2025), F1 на русском: Gemini-1.5-Pro 70,0; GPT-4o 67,2; Qwen-VL-Max 65,9;
  Claude-3.5-Sonnet 51,0; InternVL2-76B 13,2; GOT-OCR 3,9.
- Surya — не для сцен и лицензия до $5M выручки; olmOCR, dots.ocr — документы.
- Облака: Google Vision $1,50 за 1000 запросов; Yandex Vision OCR 0,13 ₽ за запрос; сетевая
  задержка съедает SLA.

### Мультимодальные LLM

| Модель | OCRBench | CC-OCR | Лицензия |
|---|---|---|---|
| Qwen3-VL-2B / 4B / 8B Instruct (arXiv 2511.21631) | 858 / 881 / 896 | 72,8 / 76,2 / 79,9 | Apache-2.0 |
| Qwen3.5-4B (02.2026) | 85,0 | 76,7 | Apache-2.0, рассуждение выключать |
| MiniCPM-V 4.5 (8B) | 89,0 | — | — |

- Русский — слабое место: у Qwen3-VL ≈ 72% на внутреннем многоязычном OCR-тесте (одно из
  низших мест), у GPT-4o на MTVQA русский 11,5% — худший язык.
- Латентность: на A100 InternVL3.5-4B — TTFT 99 мс, 11,6 мс на токен; для 3090 и JSON на
  ~50 токенов **[оценка 0,7–1,5 с]**. FP8 на Ampere не ускоряется — нужен AWQ.
- Облака: Gemini 2.5 Flash-Lite $0,10 / $0,40 за 1M токенов; gpt-5-nano $0,05 / $0,40;
  ≈ $0,0002–0,001 за запрос **[оценка]**.
- **Практика:** извлекать поля `{винодельня, название, сорт, год, цвет, сладость, надписи}` в
  JSON с guided decoding и temperature 0, сопоставлять с кандидатами визуального top-10.

### VLM как судья

- **Qwen3-VL-Reranker-2B/8B** (arXiv 2601.04720, Apache-2.0): кросс-энкодер, скор из логитов
  yes/no, пары батчем; «фото запроса» против «эталон + текст карточки»
  **[оценка 5 пар на 2B ≈ 0,2–0,5 с]**.
- **RAR** (arXiv 2403.13805): CLIP top-5 + MLLM выбирает — до ≈ +8,8 п.п. на fine-grained;
  MLLM хорошо выбирает из малого числа кандидатов.
- **Позиционный сдвиг** (arXiv 2503.13792, CVPR 2025): выбор зависит от порядка картинок —
  оценивать попарно, переставлять, требовать дословную цитату с этикетки и проверять её кодом.
- **Retrieve-Match-Escalate** (arXiv 2608.25037, 08.2026): калиброванный дешёвый матчер делит
  случаи на HIGH / MEDIUM / LOW, VLM вызывается только в MEDIUM; главный рычаг экономии —
  сузить MEDIUM.

### Отказ «не найдено»

- Отрыв top-1 − top-2 у near-duplicates мал и для вин из каталога — считать отрыв до ближайшего
  кандидата **другой серии / другого эталона**.
- Негативы через **leave-one-out**: убрать вино из индекса и искать его фото — реалистичный
  «нет в каталоге», сотни и тысячи примеров.
- Классификатор (логистическая регрессия / GBM) на признаках: скор, отрывы, inliers, текстовое
  совпадение, скор reranker, согласие полей VLM; калибровка Платтом или изотонической регрессией.
- Метрики: AUROC, FPR@TPR95, кривая точность–покрытие, open-set top-1.
- **Conformal Risk Control** (arXiv 2208.02814): порог с гарантией «ложно отклоняем не больше X%».

### Текстовый канал

- Символьные триграммы (rapidfuzz / pg_trgm) + BM25 по «название + винодельня» с транслитом
  устойчивее к мусорному OCR, чем dense-эмбеддинги; dense в дополнение — BGE-M3 (ruMTEB
  retrieval 74,8), mE5-large 74,0.
- **RRF** (сумма 1/(60 + rank)) для объединения визуального и текстового top-10.
- Текст применять как решающий фактор внутри кластера почти одинаковых кандидатов, а не
  линейным весом **[оценка]**.

## 5. Баллы сверх точности

### Портал «Своё вино»

- vino-svoe.ru, РСХБ, запуск октябрь 2025; на старте > 200 виноделен и ≈ 2 тыс. вин; в каталоге
  уже есть кнопка **«Сканировать»**.
- Карточка вина (проверено на странице вина): название, производитель, регион, сорт; цвет
  текстом, крепость; «Народный рейтинг»; описание вкуса; «Сочетание с блюдами» (теги);
  температура подачи; «Похожие вина» (12); форма оценки; подвал 18+ и предупреждение о вреде.
- Фильтры каталога: цвет, сахар, регион, сорт, производитель, сочетания с блюдами, народный
  рейтинг, Роскачество, медали.
- «Винный гид России» Роскачества размещён на платформе (800 образцов, лидеры > 83 баллов).
- Цвета и шрифты автоматически не извлечены — снять вручную через DevTools.

### «Цифровой сомелье»

- **SommBench** (arXiv 2603.12117, LREC 2026): LLM знают теорию до 97%, но характеристики вин
  воспроизводят ≤ 65%, хуже всего — сочетания с едой. Сочетания брать из правил и каталога.
- **WineGraph** (arXiv 2407.00107): сочетания по признакам (сладость, кислотность, жирность,
  солёность, острота, «вес» блюда) — основа для детерминированного скоринга.
- **Галлюцинации позиций** (arXiv 2608.10008): на длинном хвосте каталога 11–61% несуществующих
  позиций; самооценка уверенности почти не помогает. LLM должна выбирать только ID из списка
  кандидатов (enum в JSON-схеме / guided decoding; у vLLM известен баг Qwen3 с
  `enable_thinking=False` + `guided_json`).
- Рынок: Vivino Sommelier (04.2026), ИИ-сомелье «ВинЛаб», Vino.ru «Винтеллект» на YandexGPT
  (3 вина с объяснением, ≈ 10% трафика маркетплейса).
- Стоимость: GigaChat Lite 0,065 ₽ / Pro 0,5 ₽ за 1K токенов (07.09.2026); YandexGPT Lite
  $0,0016 за 1K выходных токенов; диалог из 5 реплик ≈ 1–10 ₽ **[оценка]**.

### Закон о рекламе алкоголя

- Ст. 21 38-ФЗ: реклама алкоголя в интернете запрещена (послабления для российского вина — не
  для интернета). Одинаково оформленная информация об ассортименте рекламой не считается
  (позиция ФАС 2019) **[первоисточник не проверен]**.
- Сомелье — нейтральный информационный тон: без «купи», цен, акций, изображений людей; подвал 18+.
- 21+ пока законопроект (внесён в июле 2025, не принят на момент поиска).

### Удержание

- Vivino: «Мои вина», профиль вкуса, «Match for You», сочетания, сканер винной карты, Sommelier;
  ценность растёт с историей пользователя. Метрик удержания винных приложений не найдено.
- Дешёвые функции: история сканов, «Хочу попробовать», аналоги других виноделен, место на карте
  регионов.

### Архитектура, скорость, демо

- Docker Compose с GPU: `deploy.resources.reservations.devices` с `capabilities: [gpu]`; CPU —
  отдельный профиль. pgvector по умолчанию — точный поиск (100% recall); для 2 тыс. векторов
  индекс HNSW не нужен; `vector` до 2000 измерений (у нас 1152). Nuxt 4 стабилен с 07.2025.
- SigLIP в transformers: SDPA / FlashAttention 2, fp16; torch.compile — до ≈ 30% на CV-моделях;
  TensorRT FP16 ≈ 1,9× к ONNX Runtime в общем бенчмарке. Замеров для SigLIP 2 / OWLv2 нет.
- Критериев жюри ЛЦТ по архитектуре в открытом доступе нет. Общие советы: живой узкий сценарий,
  прогнать демо 10 раз, запасной сценарий, страница живых метрик (F1 top-1/top-5, p50/p95).
