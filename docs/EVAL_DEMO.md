# Демонстрационная проверка основного сканера

Команда **Digital Rover**, проект **«Свой Сомелье»**, ЛЦТ 2026, задача №10. [Участники и роли](../TEAM.md).

Отдельная утилита [`tools/eval_detector.py`](../tools/eval_detector.py) запускает официальный `eval/participant_test.sh` **без изменений** против основного распознавания одной этикетки, `POST /v1/eval/predict`. Она не использует Shelf Finder и не заменяет официальный формат результатов своим.

**Результат сохраняется только в указанный файл.** Утилита не делает `git add`, commit, push и не загружает отчёт куда-либо. Публикация результата, если она потребуется на демонстрации, выполняется отдельно владельцем проекта.

## Обычная папка фотографий — консольный режим

Для наших фотографий `queries.tsv` не нужен:

```bash
python3 tools/eval_detector.py \
  --images-dir /path/to/photos \
  --endpoint http://84.201.163.74/v1/eval/predict \
  --output ./eval-results/predictions.jsonl
```

Скрипт рекурсивно обходит папку, сортирует относительные пути и присваивает ID `q-000001`, `q-000002`, …; исходные файлы не меняет. Обрабатываются JPG/JPEG, PNG, WebP, BMP, TIFF, HEIC/HEIF, GIF (регистр расширения не важен). Другие файлы и служебные `._*` пропускаются. Вложенные символические ссылки на директории не обходятся; ссылки на файлы за пределами выбранной папки запрещены.

Рядом создаются два файла:

- `predictions.jsonl` — по одному результату на каждое изображение, формат организатора;
- `predictions.report.json` — отчёт: сводка, время запросов, все предсказания с путями и SHA-256, версия CV-индекса, endpoint и параметры воспроизводимости.

Путь отчёта можно изменить через `--report ./eval-results/run.json`. Если любой выходной файл уже существует, выберите новые имена. В течение долгого прогона каждые 30 секунд выводится сообщение, что обработка продолжается. Полные файлы появляются после завершения официального скрипта. Изображения и отчёты автоматически в Git не добавляются; рекомендованная папка `eval-results/` исключена через `.gitignore`.

**Это основной сканер одной этикетки:** если папка содержит фото целой полки, он всё равно возвращает один slug на фото. Детекцию всех бутылок с координатами выполняет отдельный Shelf Finder.

## 1. Представиться и клонировать проект

«Мы — Digital Rover. Наше решение “Свой Сомелье” распознаёт российские вина по фотографии этикетки и помогает продолжить выбор».

```bash
git clone https://github.com/Slavuntik/vinchik.git
cd vinchik
sudo apt-get update
sudo apt-get install -y python3 curl jq unzip
```

Нужны Python 3.11+, Bash, curl, jq, awk и sha256sum либо shasum. Python-пакеты и ML-модели для самой утилиты не требуются. На macOS используйте Python 3 и `brew install jq`; Bash/curl/awk/shasum обычно уже установлены.

## 2. Поднять настоящий сервис

Следуйте [Docker quick-start, разделы 2–3](DOCKER_QUICKSTART.md) для CPU или CPU + LiteLLM. Понадобятся реальные модели и совместимые индексы; быстрый mock-режим не подходит для оценки. Альтернатива без Docker — [локальный запуск](local-full-stack.md) или `scripts/quickstart.sh full`, описанный в [QUICKSTART](QUICKSTART.md).

После настройки `.env.docker` и подготовки данных:

```bash
docker compose --env-file .env.docker \
  -f compose.yaml -f infra/docker/compose.full.yaml \
  up -d --build --wait --wait-timeout 900
curl --fail http://127.0.0.1:8080/v1/healthz
```

Утилита требует `status=ok`, `warm=true` и непустой `cv_index_version`, отличный от `unknown` и mock. Это проверка готовности, не доказательство качества. Для уже поднятого сервера достаточно указать его `--endpoint`; SSH-доступ утилите не нужен.

## 3. Распаковать eval-dataset

Используйте выданный организатором архив. Датасет от **1 октября** на момент подготовки этой инструкции ещё не получен; испытан доступный ранее `eval.zip` с тремя фотографиями.

```bash
mkdir -p /tmp/somelye-eval-dataset
unzip /path/to/eval.zip -d /tmp/somelye-eval-dataset
```

Передавайте папку, где непосредственно лежат:

```text
queries.tsv          заголовок query_id<TAB>image_path
queries/             все перечисленные изображения
checksums.sha256     если включён организатором, суммы проверяются
```

Если архив содержит внешнюю папку `eval/`, используйте её как `--dataset`. Расширения и вложенные имена изображений сохраняются. Запрещены дубли ID, отсутствующие файлы и выход путей/символических ссылок за папку изображений. Все файлы проверяются до первого запроса распознавания.

## 4. Запустить официальный скрипт через утилиту

```bash
python3 tools/eval_detector.py \
  --dataset /tmp/somelye-eval-dataset \
  --endpoint http://127.0.0.1:8080/v1/eval/predict \
  --output /tmp/somelye-predictions.jsonl
```

Для основного тестового сервера замените endpoint на `http://84.201.163.74/v1/eval/predict`; резервный — `http://89.110.72.101/v1/eval/predict`.

Скрипт выполняет **один запрос на фото, последовательно, без повторных попыток**, с исходным лимитом 10 секунд. Дополнительного запроса распознавания для прогрева утилита не делает. Тело ответа может быть `{"slug":"..."}` или `[{"slug":"..."}]`.

Результат — неизменённый JSONL организатора:

```json
{"query_id":"q-000001","image_path":"019c68d0.jpg","image_sha256":"...","predicted_slug":"wine-slug","latency_ms":842}
```

Существующий файл не перезаписывается. Для повторного прогона укажите новое имя; результаты нельзя сохранять внутрь исходного датасета. Если организаторы выдадут новый доверенный скрипт с тем же интерфейсом и схемой JSONL, укажите `--eval-script /path/to/participant_test.sh`. По умолчанию запускается только версия из репозитория; скрипты из архива автоматически не исполняются. Изменение формата нового датасета/скрипта потребует адаптации и повторной проверки.

## 5. Проверить и сохранить результат

Терминал показывает количество строк, непустых и `null`-предсказаний, медиану/p95/max времени. p95 считается методом ближайшего ранга. Непустой slug — ответ сервиса, **не подтверждение правильного распознавания**. Top-1, top-5 и confidence без правильных ответов организатора не рассчитываются.

| Код завершения | Значение |
|---|---|
| `0` | Все строки соответствуют датасету, у каждой есть непустой slug |
| `2` | Файл сохранён, но есть `null`: возможны отказ, HTTP-ошибка, таймаут или некорректный ответ; разбор причины — по логам сервиса |
| `1` | Ошибка окружения, входных файлов, готовности сервиса, официального скрипта или формата результата |
| `130` | Прервано пользователем; полный результат не гарантирован |

Необязательный `--report /tmp/somelye-run.json` сохраняет **дополнительный** JSON: время прогона, endpoint, SHA-256 утилиты/скрипта/манифеста/результата, health сервиса, Git SHA клиентской копии и сводку. Клиентский Git SHA не утверждает версию удалённого сервера. В режиме `--dataset` без `--report` создаётся только файл `--output`; в режиме `--images-dir` отчёт создаётся автоматически рядом с JSONL. Фото и ключи в отчёт не включаются.

Если требуется передать результат организатору, передайте файл `predictions.jsonl`. В этой реализации автоматической публикации в репозитории нет.

## Проверка утилиты

```bash
python3 -m unittest discover -s tools -p test_eval_detector.py
```

Та же проверка включена в CI (`eval-tool-tests`), без GPU, датасетов и внешнего LLM.

15 тестов проверяют рекурсивный обход папки, автоматический отчёт и запускают настоящий официальный shell-скрипт против локального HTTP-сервера: multipart, оба формата ответа, 502/HTML, отсутствие файлов, повтор ID, ошибочные checksum, выход по symlink, mock/непрогретый CV, защита от перезаписи и отсутствие вычисленной accuracy без разметки.

29.09.2026 утилита также проверена на оригинальном доступном `eval.zip` (3 фото) и реальном основном API `84.201.163.74`: 3 строки, 3 непустых slug, `null=0`. Это проверка совместимости датасета, скрипта и сервиса, не оценка точности и не проверка будущего датасета от 1 октября. Исходные изображения и полученные JSONL сохранены локально вне Git.

Режим обычной папки отдельно проверен на всех 119 изображениях нашего диагностического архива (`label-audit-20260928/archive`), включая вложенные директории и отрицательные случаи. JSONL и автоматический JSON-отчёт сохранены вне Git. Сверка с `qa/audits/label-archive-20260928.manifest.json` выполнена отдельно по SHA-256; это другая выборка и протокол, чем актуальные замеры презентации.
