# Демонстрационная проверка основного сканера

Команда **Digital Rover**, проект **«Свой Сомелье»**, ЛЦТ 2026, задача №10. [Участники и роли](../TEAM.md).

Отдельная утилита [`tools/eval_detector.py`](../tools/eval_detector.py) запускает официальный `eval/participant_test.sh` **без изменений** против основного распознавания одной этикетки, `POST /v1/eval/predict`. Она не использует Shelf Finder и не заменяет официальный формат результатов своим.

**Результаты сохраняются только в локальные файлы:** JSONL и, в режиме папки, JSON-отчёт. Утилита не делает `git add`, commit, push и не загружает отчёт куда-либо. Публикация результата, если она потребуется на демонстрации, выполняется отдельно владельцем проекта.

## Обычная папка фотографий — консольный режим

Для наших фотографий `queries.tsv` не нужен:

```bash
python3 tools/eval_detector.py \
  --images-dir /path/to/photos \
  --endpoint http://84.201.163.74/v1/eval/predict \
  --output ./eval-results/predictions.jsonl
```

Скрипт рекурсивно обходит папку, сортирует относительные пути и присваивает ID `q-000001`, `q-000002`, …; исходные файлы не меняет. Обрабатываются JPG/JPEG, PNG, WebP, BMP, TIFF, HEIC/HEIF, GIF (регистр расширения не важен). Другие файлы и служебные `._*` пропускаются. Вложенные символические ссылки на директории не обходятся; ссылки на файлы за пределами выбранной папки запрещены.

Рядом создаются два файла:

- `predictions.jsonl` — по одному результату на каждое изображение, формат организатора;
- `predictions.report.json` — отчёт: сводка, время запросов, все предсказания с путями и SHA-256, версия CV-индекса, endpoint и параметры воспроизводимости.

Путь отчёта можно изменить через `--report ./eval-results/run.json`. Если любой выходной файл уже существует, выберите новые имена. В течение долгого прогона каждые 30 секунд выводится сообщение, что обработка продолжается. Полные файлы появляются после завершения официального скрипта. Изображения и отчёты автоматически в Git не добавляются; рекомендованная папка `eval-results/` исключена через `.gitignore`.

**Это основной сканер одной этикетки:** если папка содержит фото целой полки, он всё равно возвращает один slug на фото. Детекцию всех бутылок с координатами выполняет отдельный Shelf Finder.

## По какой базе выполняется поиск

Утилита не передаёт ограничений по slug и не строит индекс из тестовых фотографий. Она вызывает основной `/v1/eval/predict`, который ищет по **всему загруженному индексу выбранного сервера**. Top-5 — число кандидатов после поиска, а не база из пяти вин. Входная папка определяет только фотографии запросов; пожелания сомелье и рекомендации на этот прогон не влияют.

Основной каталог содержит **2103 вина**, RAG-манифест — также **138 виноделен** ([источник](../packages/rag/data/manifest.json), версия `20260922.1`). Размер каталога, число фотоэталонов и число векторов индекса — разные величины. По [аудиту от 28.09](../reports/label-recognition-audit-2026-09-28.md) у 44 позиций не было выбранного эталона в `slug_refs.json`; это ограничение покрытия, а не фильтр консольной утилиты. Готовность и имя индекса в `health_before` сами по себе не подтверждают наличие эталонов для каждого SKU. На новом сервере необходимо загрузить полный совместимый индекс.

## Параметры консольного скрипта

| Параметр | Назначение |
|---|---|
| `--images-dir DIR` | Обычная папка и подпапки; автоматический манифест и отчёт |
| `--dataset DIR` | Набор организатора с `queries.tsv` и `queries/`; несовместим с `--images-dir` |
| `--endpoint URL` | Основной `/v1/eval/predict`; по умолчанию `http://127.0.0.1:8080/v1/eval/predict` |
| `--output FILE` | Обязательный путь к новому JSONL вне входной папки |
| `--report FILE` | Явный путь отчёта; в режиме папки по умолчанию `<имя-output>.report.json` вместо расширения output |
| `--eval-script FILE` | Доверенный скрипт с совместимым CLI и форматом; по умолчанию `eval/participant_test.sh` |
| `--help` | Справка без обращения к сервису |

Используйте Bash на Linux/macOS либо WSL на Windows. Сама утилита не запускает API и не скачивает модели; она обращается к уже работающему сервису по HTTP(S).

## 1. Представиться и клонировать проект

«Мы — Digital Rover. Наше решение “Свой Сомелье” распознаёт российские вина по фотографии этикетки и помогает продолжить выбор».

```bash
git clone https://github.com/Slavuntik/vinchik.git
cd vinchik
sudo apt-get update
sudo apt-get install -y python3 curl jq unzip
```

Нужны Python 3.11+, Bash, curl, jq, awk и sha256sum либо shasum. Python-пакеты и ML-модели для самой утилиты не требуются. На macOS используйте Python 3 и `brew install jq`; Bash/curl/awk/shasum обычно уже установлены.

## 2. Поднять настоящий сервис

Следуйте [Docker quick-start, разделы 2–3](DOCKER_QUICKSTART.md) для CPU или CPU + LiteLLM. Понадобятся реальные модели и совместимые индексы; быстрый mock-режим не подходит для оценки. Альтернатива без Docker — [локальный запуск](local-full-stack.md) или `scripts/quickstart.sh full`, описанный в [QUICKSTART](QUICKSTART.md).

После настройки `.env.docker` и подготовки данных:

```bash
docker compose --env-file .env.docker \
  -f compose.yaml -f infra/docker/compose.full.yaml \
  up -d --build --wait --wait-timeout 900
curl --fail http://127.0.0.1:8080/v1/healthz
```

Утилита требует `status=ok`, `warm=true` и непустой `cv_index_version`, отличный от `unknown` и mock. Это проверка готовности, не доказательство качества. Для уже поднятого сервера достаточно указать его `--endpoint`; SSH-доступ утилите не нужен.

## 3. Распаковать eval-dataset

Используйте выданный организатором архив. Датасет от **1 октября** на момент подготовки этой инструкции ещё не получен; испытан доступный ранее `eval.zip` с тремя фотографиями.

```bash
mkdir -p /tmp/somelye-eval-dataset
unzip /path/to/eval.zip -d /tmp/somelye-eval-dataset
```

Передавайте папку, где непосредственно лежат:

```text
queries.tsv          заголовок query_id<TAB>image_path
queries/             все перечисленные изображения
checksums.sha256     если включён организатором, суммы проверяются
```

Если архив содержит внешнюю папку `eval/`, используйте её как `--dataset`. Расширения и вложенные имена изображений сохраняются. Запрещены дубли ID, отсутствующие файлы и выход путей/символических ссылок за папку изображений. Все файлы проверяются до первого запроса распознавания.

## 4. Запустить официальный скрипт через утилиту

```bash
python3 tools/eval_detector.py \
  --dataset /tmp/somelye-eval-dataset \
  --endpoint http://127.0.0.1:8080/v1/eval/predict \
  --output /tmp/somelye-predictions.jsonl
```

Для основного тестового сервера замените endpoint на `http://84.201.163.74/v1/eval/predict`; резервный — `http://89.110.72.101/v1/eval/predict`.

Скрипт выполняет **один запрос на фото, последовательно, без повторных попыток**, с исходным лимитом 10 секунд. Дополнительного запроса распознавания для прогрева утилита не делает. Тело ответа может быть `{"slug":"..."}` или `[{"slug":"..."}]`.

Результат — неизменённый JSONL организатора:

```json
{"query_id":"q-000001","image_path":"019c68d0.jpg","image_sha256":"...","predicted_slug":"wine-slug","latency_ms":842}
```

Существующий файл не перезаписывается. Для повторного прогона укажите новое имя; результаты нельзя сохранять внутрь исходного датасета. Если организаторы выдадут новый доверенный скрипт с тем же интерфейсом и схемой JSONL, укажите `--eval-script /path/to/participant_test.sh`. По умолчанию запускается только версия из репозитория; скрипты из архива автоматически не исполняются. Изменение формата нового датасета/скрипта потребует адаптации и повторной проверки.

## 5. Проверить и сохранить результат

Терминал показывает количество строк, непустых и `null`-предсказаний, медиану/p95/max времени. p95 считается методом ближайшего ранга. Непустой slug — ответ сервиса, **не подтверждение правильного распознавания**. Top-1, top-5 и confidence без правильных ответов организатора не рассчитываются.

| Код завершения | Значение |
|---|---|
| `0` | Все строки соответствуют датасету, у каждой есть непустой slug |
| `2` | После корректно запущенного прогона: файл сохранён, но есть `null`: возможны отказ, HTTP-ошибка, таймаут или некорректный ответ; разбор причины — по логам сервиса |
| `1` | Ошибка окружения, входных файлов, готовности сервиса, официального скрипта или формата результата |
| `130` | Прервано пользователем; полный результат не гарантирован |

Неверные аргументы CLI также возвращают стандартный код `argparse` `2`, но до прогона: в этом случае выводится справка об ошибке, файл результата не создаётся.

Необязательный `--report /tmp/somelye-run.json` сохраняет **дополнительный** JSON: время прогона, endpoint, SHA-256 утилиты/скрипта/манифеста/результата, health сервиса, Git SHA клиентской копии и сводку. Клиентский Git SHA не утверждает версию удалённого сервера. В режиме `--dataset` без `--report` создаётся только файл `--output`; в режиме `--images-dir` отчёт создаётся автоматически рядом с JSONL. Фото и ключи в отчёт не включаются.

Если требуется передать результат организатору, передайте файл `predictions.jsonl`. В этой реализации автоматической публикации в репозитории нет.

Это проверка совместимости датасета, скрипта и сервиса, не оценка точности и не проверка будущего датасета от 1 октября. Исходные изображения и полученные JSONL сохранены локально вне Git.

JSONL и автоматический JSON-отчёт сохранены вне Git. ## Как читать JSON-отчёт

| Поле | Значение |
|---|---|
| `input_mode` | `folder` или `organizer_dataset` |
| `summary.images` / `predicted` / `null_predictions` | Число обработанных фото / непустых ответов / пустых ответов |
| `summary.latency_ms` | Медиана, p95 методом ближайшего ранга, максимум в миллисекундах |
| `summary.accuracy` | `null`: утилита не получает эталонные ответы и не вычисляет точность |
| `predictions` | Результат для каждого файла: ID, относительный путь, SHA-256, slug, задержка |
| `started_at` / `elapsed_seconds` | Начало UTC и длительность работы скрипта после предварительных проверок |
| `health_before` | Версия CV/RAG-индекса и готовность до прогона |
| `client_git_commit` | Коммит клиентской копии, не сервера; незакоммиченные изменения этим полем не описываются |
| `*_sha256` | Контрольные суммы утилиты, официального скрипта, манифеста и JSONL |

`null` не равен неправильному распознаванию: в отрицательном кадре может не быть бутылки. Непустой slug тоже не равен успеху: flat API выбирает одну лучшую позицию даже при недостаточной уверенности. Для оценки показанных пользователю карточек и отказов нужен отдельный rich-протокол, описанный в [методике оценки](label-recognition-evaluation.md).

## Локальная проверка на наших данных — 29.09.2026

Проверен весь диагностический архив: **119 фото**, **118 непустых ответов**, **1 null**, все строки сохранены; код завершения `2` сигнализирует о необходимости разобрать пустой ответ. По независимой ручной разметке этот кадр C63 — здание винодельни без бутылки. При отдельной сверке по SHA-256 на **72 известных винах совпали 70 slug (97.2%)**; 46 отрицательных кадров и один кадр без надёжной истины исключены из этого знаменателя. Эту сверку выполнили отдельно, а не внутри утилиты.

Это диагностическая проверка скрипта на знакомом архиве, **не новый официальный benchmark и не замена показателям презентации**. Исходные результаты остаются файлами вне Git на машине прогона:

Последний файл — отдельная сверка с разметкой; обычный вызов CLI его не создаёт. Локальные пути не нужны после clone и не существуют автоматически на другом компьютере. Для своего прогона используйте `--output ./eval-results/predictions.jsonl`.

## Если запуск не удался

| Сообщение / симптом | Что проверить |
|---|---|
| Файл уже существует | Задайте новое имя `--output` и, если указан, `--report`; перезаписи нет |
| Нет изображений / отсутствует файл | Корневую папку, расширения, соответствие `queries.tsv` и `queries/` |
| Не совпала контрольная сумма | Целостность архива; не редактируйте манифест или файлы проверяемого набора |
| CV не готов / mock | Полный профиль API, модели, индекс и `GET /v1/healthz` |
| Есть `null`, код `2` | Файл уже сохранён; посмотрите соответствующие фото, задержку и логи API. JSONL сам по себе не различает HTTP-ошибку и отказ |
| Прогон идёт долго | Запросы последовательные; сообщение раз в 30 секунд — признак продолжающейся работы, не зависания |
| Ctrl+C | Полный результат не гарантирован; автоматического продолжения нет, следующий прогон запускайте с новым именем |

Не перезапускайте весь набор автоматически при коде `2`: сначала разберите сохранённый отчёт. Повторный прогон имеет другие условия кэша и должен храниться отдельно.

## Запуск CLI на развёрнутом сервере

Git-релиз устанавливает отдельный пакет утилиты в `/opt/somelye/tooling`: скрипт, его тесты, официальный `participant_test.sh` и эту инструкцию. Это ограниченный пакет по явному списку файлов, без датасетов, моделей и локальных отчётов. Основное приложение и зависимости API остаются отдельно.

```bash
cd /opt/somelye/tooling
python3 tools/eval_detector.py --images-dir /path/to/photos \
  --endpoint http://127.0.0.1:8000/v1/eval/predict \
  --output /tmp/eval-run-01.jsonl
```

Путь `tooling` указывает на пакет активного релиза. Версия — в `.git-revision`. Это не полный Git checkout; `git pull` здесь не используется, обновление выполняется релизом из репозитория. Результаты сохраняйте вне каталога релиза. В отчёте `client_git_commit` может быть `null`, поскольку пакет не содержит `.git`. На хосте необходимы Python 3.11+, Bash, curl, jq и awk.
