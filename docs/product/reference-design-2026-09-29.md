## Осознанные отличия от демонстрационного архива

- Переключатель «Бутылка / Блюдо» остаётся доступным: режим блюд существует в рабочем продукте.
- Прицел, уточнение среди кандидатов, гастропары, паспорт вкуса и полноценный чат сохранены. Из-за них некоторые страницы длиннее прототипа.
- Советы по съёмке раскрываются по запросу; в основном тексте исправлена опечатка из архива.
- Рейтинг, цена и характеристики не подставляются из демонстрационных бутылок. Отображаются реальные данные API; отсутствие данных не маскируется выдуманными числами.
- Кнопки сохраняют область нажатия не менее 44 px, подписи и видимый фокус. Мелкие контролы прототипа не уменьшаются до неудобного размера.
- Цвета релевантности витрины сохранены: они передают результат ранжирования, а не декоративную палитру.
- Лендинг и юридические страницы сохраняют свой состав и общие токены. Мобильная оболочка использует ту же сборку `apps/web`; расширенный `/shelf-ui/` сохраняет рабочую сетку инструмента и общие базовые стили.
- Полноэкранный демонстрационный экран ожидания с собственной отменой не подменяет существующую оркестрацию запросов. Рабочие состояния загрузки/ошибки остаются привязаны к реальным действиям.

## Галерея основного сканера

Для одной бутылки добавлен независимый `galleryInputRef`: `accept="image/*"`, без `capture`, один файл. «Сканировать» вызывает поле с `capture="environment"`. Обе кнопки вызывают нужный input синхронно внутри пользовательского жеста. После события выбора поле очищается, поэтому повторный выбор того же файла запускает обработку снова. Оба источника используют прежний обработчик распознавания, включая режим блюда; прицел остаётся доступен после ответа.

Регрессионные проверки находятся в `ScanScreen.test.tsx` и `qa/scan_photo_picker.mjs`. Отдельное исправление галереи витрины также перепроверено скриптом `qa/shelf_photo_picker.mjs`.

Браузерные сценарии загрузки используют заглушки API и синтетические PNG: это проверка UI, не повтор оценки моделей. WebKit с профилем устройства не равен физическому iPhone; системная медиатека iOS, разрешения и HEIC требуют ручной проверки на телефоне.

```bash
npm --prefix apps/web test
npm --prefix apps/web run build
# Фронтенд запущен с VITE_API_MODE=real на отдельном тестовом порту:
node qa/scan_photo_picker.mjs http://127.0.0.1:5189
node qa/shelf_photo_picker.mjs http://127.0.0.1:5189
```

Скрипты используют установленный Playwright в `apps/shelf-finder`; альтернативная установка задаётся `PLAYWRIGHT_MODULE`, нестандартный WebKit launcher — `WEBKIT_EXECUTABLE`. Эмуляция не отправляет фотографии в настоящую модель.

## Стартовая страница (29 сентября 2026)

Корневой адрес `/` теперь перенаправляет на `/app/scan` с заменой записи истории. Прежний лендинг снят с маршрутизации и больше не импортируется приложением; его исходники оставлены как архив реализации. Неизвестные адреса также ведут на сканер. Прямые ссылки на остальные разделы и юридические документы сохраняются.

При первом посещении действует существующий онбординг `/app/onboarding`: дата рождения, проверка совершеннолетия и согласия. После его завершения открывается сканер; при последующих посещениях сканер открывается сразу. Выход из профиля возвращает пользователя к первому входу.

Регрессия `apps/web/src/router.test.tsx` проверяет корень, неизвестный адрес, `/app` и полный переход от первого входа к сканеру.
