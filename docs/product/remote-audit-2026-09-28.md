## Почему витрина недоступна

На сервере отсутствует модуль API `routers/shelf_selection.py`; endpoint подбора отсутствует и в OpenAPI. В опубликованном JavaScript нет нового вызова `/sommelier/shelf-selection`.

В активном nginx есть маршруты `/v1/chat`, `/v1/` и `/`, но нет отдельного проксирования витрин. Файл `/etc/nginx/conf.d/shelf-upstream.conf` отсутствует. Подключение к GPU-сервису не проверялось: настроенного upstream для витрины нет.

`/shelf-ui/` возвращает 200 с HTML основного SPA — это fallback, а не подтверждение работы сканера. `/legal/fonts.css` также возвращает HTML; файл нового набора локальных шрифтов отсутствует в опубликованном web.

## Проверка интерфейса и ресурсов

В публичном браузере `/app/scan` и `/app/catalog` открываются, каталог загружается. `/app/shelf` показывает: «Раздел витрины доступен, когда запущен сервис распознавания витрин». Ошибок JavaScript и горизонтального переполнения в этих проверках нет.

Доступно около 130 ГБ диска и 2,6 ГиБ RAM. Проверка `sudo -n nginx -t` запрещена правами пользователя; это ограничение аудита, а не ошибка конфигурации nginx.

## Что необходимо дальше

Развернуть согласованную актуальную версию backend и frontend, подключить отдельный сервис витрин через nginx к GPU-серверу либо настроить его CPU-вариант. Перед развёртыванием сверить изменения других разработчиков и текущую production-конфигурацию моделей. Затем повторить сценарий «предпочтения → несколько фотографий → ранжированные подсветки» на реальных полках и телефоне.

Простой перезапуск текущей версии не добавит отсутствующие маршруты и frontend. Наличие коммита в GitHub не означает его развёртывание на этом сервере. Данный аудит не включал деплой, нагрузочное тестирование, полный регресс всех функций или проверку качества распознавания реальных полок.
