# Сомелье на полках

Актуально для реализации 27.09.2026. Это дополнительный сценарий Vinchik,
а основной скан этикетки остаётся на `/app/scan`.

## Пользовательский путь

1. Откройте «Витрина» (`/app/shelf`) после гостевого входа 18+ или регистрации.
   Раздел появляется при готовом сервисе распознавания. Из ответа чата кнопка
   «Найти подходящее на полке» переносит последнюю реплику пользователя в форму.
2. Напишите пожелание, например «сухое белое к рыбе, не сладкое». Подтвердите подбор:
   экран показывает учтённые критерии и до пяти предварительных вариантов каталога.
3. Добавьте до восьми фотографий разных полок из галереи или камеры.
   Снимки обрабатываются последовательно. После первого результата рейтинг строится
   исключительно по найденным слагам всех обработанных снимков, максимум 50 вин.
4. Подходящие совпадения слегка закрашиваются зелёным; подпись содержит место в
   общем рейтинге и название из базы. Остальные бутылки не отмечаются.
   Общие эталоны нескольких SKU выделяются пунктиром янтарного цвета и словом
   «Возможно»: снимок не доказывает точный год/вариант.
5. Карточка списка ведёт к общей карточке вина; ссылки «Полка N» — к его месту.
   Можно изменить пожелание без повторного CV, удалить фото, повторить неудачное
   распознавание или остановить очередь. Уже готовые результаты сохраняются.

Фотографии и результаты живут в памяти текущего экрана: уход в другой раздел,
включая карточку вина, или перезагрузка их сбрасывает. Временный отказ health
после открытия экрана не удаляет фотографии. Это не долговременная история полок.

## Общая логика сомелье

Новый endpoint использует существующие `chat.filters.extract_filters`,
`dish_pairing.get_catalog_cards`, поиск `Retriever.search`, таксономию блюд и
`food_pairing.score_wine_for_dish`. Отдельного каталога рекомендаций и отдельной
LLM для ранжирования нет. Слаги связывают каталог основного приложения с CV-сервисом;
их версии должны соответствовать одному набору данных организаторов.

Цвет, сахар, регион и простые исключения отсекают несовместимые карточки. Сначала
идут гастропары, прямо указанные в каталоге, затем вычисленные правилами; внутри
группы учитываются оценка сочетания, текстовая релевантность и стабильный слаг.
Без блюда используется общий поиск сомелье. `reason` объясняет основание, `basis`
различает `catalog-pairing`, `pairing-rules`, `catalog-filters`, `text-search`.
Неизвестные идентификаторы никогда не превращаются в придуманные вина.

Разбор пожеланий ограничен словарями, а не полноценным пониманием произвольной речи.
«К рыбе», «к мясу», «к стейку» поддерживаются; сложные отрицания и сочетания нужно
уточнять. Цены не проверяются; вкусовой профиль и вся история чата автоматически
не применяются. Предварительный подбор не ограничивает кандидатов CV: иначе запрос
пользователя мог бы склонить распознавание к неверной бутылке.

## API и границы сервисов

| API | Назначение и доступ |
|---|---|
| `POST /v1/sommelier/shelf-selection` | Основной API, Bearer гостя/пользователя. JSON `wish`, необязательные `wine_ids`, `dish`. Без `wine_ids` — предпросмотр; `[]` — ничего не найдено. До 640 ID по 300 символов; ответ до 50 вин. |
| `GET /v1/shelf/health` | Отдельный CV-сервис; готовность и таймаут. UI проверяет `ready`, `state`, `catalogSize`, `busy`; кеш 30 с для успеха, 5 с для отказа. |
| `POST /v1/shelf/scan` | Отдельный CV-сервис, multipart `image`; принимает одно фото и возвращает нормированные рамки с ID. Мультифото — очередь клиента, не batch endpoint. |
| `/shelf-ui/?engine=server` | Расширенный самостоятельный сканер для диагностики. |

Фото до 20 MiB и 32 мегапикселей уменьшается до 1920 px по длинной стороне,
перекодируется в JPEG и отправляется на сервер. Это не инференс внутри телефона.
Фронт соблюдает объявленный health таймаут 15–600 с (fallback 300 с).
CPU и удалённый GPU поддерживаются: см. [переносимость](../../apps/shelf-finder/docs/portable-litellm-2026-09-27.md).
В профиле `litellm` вырезки отправляются в настроенный шлюз Qwen; baseline работает
локальными моделями. Секреты остаются на сервере. Basic-доступ reverse proxy к CV
отделён от Bearer основного API; доступность health не гарантирует права на scan.

Отмена клиента не убивает native-поток: сервис удерживает единственный слот до
завершения вычислений; параллельный запрос получает 503. Ошибка Qwen сохраняет CV
результат, но не означает успешную LLM-проверку.

## Проверки и ограничения оценки

`apps/api/tests/test_shelf_selection.py` проверяет ограничения, исключения,
гастропары и фильтрацию найденных ID. `ShelfFlow.test.tsx` — очередь, общие результаты,
отказ одного фото и повтор. `lib/shelf.test.ts` — геометрию и отмену.

```bash
cd apps/web
npm test
npm run build
# В отдельном терминале, из apps/web:
VITE_API_MODE=real npm run dev -- --host 127.0.0.1 --port 15173
# Из apps/shelf-finder (Chromium и WebKit установлены через Playwright):
SHELF_MAIN_UI_URL=http://127.0.0.1:15173 npx playwright test -c playwright.integrated.config.ts
```

Браузерные проверки используют подставные ответы API и реальные загрузку/перекодирование
фото. Они не измеряют качество CV, гастрономического ранжирования или скорость на iPhone.
Новый размеченный end-to-end набор «пожелание + полки» пока не оценён.


## Выбор галереи и камеры на iPhone — 29.09.2026

«Добавить фото полок» открывает отдельное поле `image/*` с множественным выбором и без `capture`. «Снять полку» открывает другое поле с `capture="environment"`. Выбор системного интерфейса остаётся за браузером; галерейная кнопка не запрашивает принудительно камеру. Назначение атрибута описано в [MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture).

После сообщения об открытии камеры вместо галереи заменены кликабельные `label` с почти невидимыми абсолютно позиционированными полями на настоящие кнопки. Каждая кнопка синхронно в обработчике нажатия вызывает только своё скрытое поле через отдельный ref. Между жестом пользователя и открытием нет `await`. Поля не перекрывают область нажатия, обе кнопки блокируются во время обработки и при достижении лимита восьми фото. После выбора значение поля очищается, чтобы можно было повторно выбрать тот же файл.

В исходной разметке галерейное поле уже не имело `capture`, поэтому причиной нельзя объявлять наличие этого атрибута на галерее. Изменён способ активации и исключено попадание на соседний input; системный дефект на физическом iPhone отдельно не воспроизведён.

Проверки: восемь тестов `ShelfFlow`/`ShelfScreen`, TypeScript и production-сборка прошли. Браузерный тест `qa/shelf_photo_picker.mjs` прошёл в Chromium и WebKit с профилем iPhone 13: галерея → отмена → камера → отмена → галерея; проверяются соответствующий input, `capture`, `multiple`, загрузка двух синтетических PNG и возвращение кнопок в доступное состояние. Распознавание в этом тесте подменено HTTP-заглушкой, удалённые модели не вызываются. Это проверка маршрутизации выбора, а не автоматизация настоящей медиатеки iOS.

Воспроизведение из корня репозитория (нужен установленный Playwright с браузерами, по умолчанию используется установка `apps/shelf-finder`):

```bash
# Терминал 1
VITE_API_MODE=real VITE_THEME=portal npm --prefix apps/web run dev -- --host 127.0.0.1 --port 5188 --strictPort
# Терминал 2
node qa/shelf_photo_picker.mjs http://127.0.0.1:5188
```

При нестандартной установке доступны `PLAYWRIGHT_MODULE` (путь модуля) и `WEBKIT_EXECUTABLE` (путь launcher). Для ручной приёмки на iPhone: обновить страницу, открыть витрину, выбрать «Добавить фото полок», выбрать два имеющихся снимка, дождаться их появления; затем отдельно проверить «Снять полку», отмену и повторный выбор. HEIC/HEIF и системные разрешения нужно проверять на самом устройстве — синтетические PNG их не покрывают.
