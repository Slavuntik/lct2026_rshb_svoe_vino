# Исправления основного распознавания этикеток — 25 сентября 2026

## Изменения

- Ручная рамка применяется после EXIF-нормализации. Повороты телефона больше
  не меняют смысл координат интерфейса; выходной JPEG не несёт старую ориентацию.
- Обе формы `/v1/scan/photo` передают факт применения ручной рамки. WineScan
  получает `normalize=False` и пропускает детектор; предварительный shelf-crop
  также не переопределяет выбор пользователя. Некорректная рамка во flat-режиме
  по-прежнему игнорируется, в rich возвращается ошибка.
- Детекция и выбор рамки работают на копии до 1600 пикселей. Координаты
  масштабируются отдельно по X/Y, эмбеддинги и локальная проверка получают кроп
  исходного изображения. Размеры входов самих моделей остаются ограниченными
  их препроцессорами. Поле `box` сохраняет прежние координаты уменьшенного кадра.
- Опциональный метод адаптера `search_with_details` возвращает кандидатов,
  статус решения, причину отказа и OCR в одном результате запроса. Общего
  изменяемого кэша этих данных нет. Прежний `search` остаётся совместимым.
- API учитывает `not_found` WineScan как дополнительный запрет уверенного
  ответа. Собственные пороги API остаются. Кандидаты и `best_guess_slug`
  сохраняются, поэтому flat-режим продолжает отдавать лучшую гипотезу.
- OCR из WineScan переиспользуется внешним ранжированием и верификатором.
  Пустая строка означает завершённое чтение без текста и не вызывает повторного
  OCR. `None` означает отсутствие чтения и сохраняет прежний fallback API.

Изменения ядра сделаны в `standalone/winescan` и перенесены через
`tools/sync_winescan.py --apply`. Адаптер остаётся в `packages/winescan`.
Модуль витрин `apps/shelf-finder` не менялся.

## Проверка

```bash
PYTHONPATH=apps/api:packages/cv .venv/bin/python -m pytest \
  apps/api/tests/test_scan_user_box.py apps/api/tests/test_scan_photo.py \
  apps/api/tests/test_winescan_evidence.py -q
PYTHONPATH=packages/winescan /path/to/ml-venv/bin/python -m pytest packages/winescan/tests -q
python3 tools/sync_winescan.py --check
```

Результаты: **70 тестов API и 164 теста WineScan прошли**. Регрессионные
сценарии проверяют пиксели EXIF-повернутой области, передачу рамки через оба
HTTP-режима, сохранение отказа и кандидатов, пустой/непустой OCR, а также
извлечение деталей из исходного кадра 4000×2000. GPU и внешние API для этих
тестов не используются.

## Ограничения

Это исправления обработки данных и согласования решений, а не измеренный
прирост точности. Повторное распознавание полевой выборки и замер p50/p95
этого варианта ещё не выполнены. Сохранение разрешения может изменить
ранжирование и задержку; дополнительный запрет по `not_found` может уменьшить
число уверенных ответов. Пороги требуют отдельной калибровки на реальных
положительных и отрицательных примерах.

Этикетка по-прежнему выделяется эвристически по высоте бутылки. Обученный
детектор этикеток — отдельная задача с разметкой и проверкой на отложенных
фото; эти исправления его не подменяют. Запущенные процессы не перезапускались:
изменения применятся после перезапуска основного API.
