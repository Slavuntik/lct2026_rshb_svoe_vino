# Локальный Vinchik с витринами

Контейнерный вариант: [Docker Compose quick-start](DOCKER_QUICKSTART.md).

Один интерфейс: `http://localhost:5173/app/`. После стандартного входа доступны
«Скан», «Витрина», «Сомелье», «Вкус», «Профиль». Лендинг остаётся на `/`.

Витрина встроена в `/app/shelf` как экран основного приложения: пожелание →
подбор сомелье → несколько фотографий → общий рейтинг и подсветка. Распознавание
остаётся в отдельном `apps/shelf-finder`; основной скан этикетки сохранён.
[Поведение, API и ограничения](product/shelf-sommelier.md).

## Подготовка

Нужны Node.js 22+, Python 3.12+, подготовленные модели. Для полок доступны CPU или NVIDIA GPU; можно подключить удалённый сервис.
Установите зависимости `apps/web` и `apps/shelf-finder` через `npm ci` в каждой папке.
Python-окружение должно содержать зависимости основного API, `packages/llm`,
`packages/rag`, WineScan (если выбран этот основной провайдер), `rapidocr`, а также
[`apps/shelf-finder/server`](../apps/shelf-finder/server/README.md).
Сам launcher использует `python-dotenv` (входит в зависимости `uvicorn[standard]`).

Скопируйте `.env.example` в `.env`, задайте пути и ключ шлюза. `.env` не входит в Git;
ключи читаются только серверными процессами, а не React/Vite. `VINCHIK_PYTHON` выбирает
Python с ML-зависимостями. Индекс RAG из `packages/rag/data` используется локально,
без подключения к чужому Qdrant. При первом запуске скачиваются модели FastEmbed;
их можно заранее прогреть до включения офлайн-режима WineScan:

```bash
# Выполнить в выбранном Python-окружении, с RAG_FASTEMBED_CACHE из .env:
python -c "from rag.embeddings import DenseEmbedder; DenseEmbedder().embed_query('вино'); from rag.rerank import build_reranker; build_reranker().rerank('вино', ['красное сухое вино'])"
```

WineScan требует `WINESCAN_ARTIFACTS_DIR` и `WINESCAN_UPLOADS_DIR`.
В `CASE_DATA_DIR` разместите CSV организаторов и выполните
`python apps/api/scripts/build_case_catalog.py` с этим env для карточек всех SKU.
Каталог не сохраняется в Git. Подготовка комплекта моделей витрин описана в её README.

## Запуск

Из корня репозитория:

```bash
npm run build --prefix apps/shelf-finder
.venv/bin/python tools/run_local.py
```

Launcher читает `.env`, поднимает основной API на **8087**, API витрин (CPU/GPU) на
**8086** и React/Vite на **5173**, доступном из локальной сети. Готовый экземпляр API
может быть использован повторно. Занятые другими приложениями порты не освобождаются
принудительно. Начальный прогрев моделей занимает дольше обычного распознавания.

Логи и отдельная SQLite-база локального запуска: `.local/vinchik/`. Ctrl-C останавливает
только дочерние процессы этого запуска; ранее работавший сервис витрин продолжит работу.
Обновив код витрин, пересоберите её `dist` командой выше; React в dev обновляется сам.

Vite маршрутизирует `/v1/shelf/*` на 8086, остальные `/v1/*` на 8087,
а `/shelf-ui/*` — на статическую сборку витрин. Адреса можно переопределить через
`VINCHIK_API_URL` и `VINCHIK_SHELF_URL` при ручном запуске Vite.
Эта схема — для локальной разработки; production-прокси нужно настроить аналогично.

С телефона в той же сети открывайте `http://<LAN-IP-компьютера>:5173/app/`.
Загрузка фотографии доступна по HTTP, для прямого доступа к камере нужен HTTPS.
В baseline распознавание полок использует локальные модели; профиль `litellm`
отправляет вырезки Qwen через серверный шлюз. Ранжирование использует общие данные
сомелье и не требует отдельного вызова LLM.

## Выбор исполнителя полок

В `.env` задайте `SHELF_DEVICE=cpu` для CPU или `SHELF_DEVICE=cuda:0` и
`SHELF_GPU=<физический индекс>` для GPU. Без явного индекса сохраняется
`CUDA_VISIBLE_DEVICES`, GPU 2 больше не назначается автоматически.
Для внешнего сервиса укажите `VINCHIK_SHELF_URL`; локальный shelf-процесс тогда не
запускается. Основной API и ранжирование остаются локальными.
[Полная инструкция переноса](../apps/shelf-finder/docs/portable-litellm-2026-09-27.md).

## Историческая проверка 25.09.2026

Ниже результаты прежнего интерфейса. Текущие проверки описаны в
[готовности проекта](product/requirements-check.md); эти цифры не заменяют новый прогон.


- 124 теста React/Vite проходят; сборки React и витрин успешны.
- Реальные HTTP-запросы: регистрация, карточка вина, профиль вкуса, кандидаты,
  экспорт профиля и гастропары — 200/201. Чат через настроенный шлюз вернул
  события `token`, `citation`, `done`; подбор к мясу — 6 вин.
- Основной сканер WineScan обработал тестовую вырезку за 2,96 с и вернул
  корректный отказ `not_in_catalog`; это проверка исполнения, не точности распознавания.
- VLM на фото бутылки вернула `bottle`, не выдала её за блюдо.
- Через встроенный интерфейс фото `photo_2026-09-24_17-33-59.jpg` дало 8 совпадений.
- Chromium и WebKit с viewport iPhone 13: вход, встроенная витрина, все пункты
  навигации и ширина мобильного интерфейса проверены; ошибок JavaScript нет.
- Профиль вкуса и экспорт данных требуют регистрации; одного гостевого входа
  для них недостаточно. Для вкусового профиля также нужно согласие на персонализацию.

Результаты относятся к локальному запуску, не к публикации production-стенда.
