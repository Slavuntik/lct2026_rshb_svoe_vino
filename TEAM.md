Тимлид — сессия Fable (оркестратор): ставит задачи, принимает результаты, решает спорное, общается
с Вячеславом. Всё остальное делают роли-агенты (`.claude/agents/*.md`; копия — `~/ClaudeWorkspace/.claude/agents/`).

| architect | Opus | `contracts/`, `ARCHITECTURE.md`, `reviews/` | контракты, ратификация предложений, архитектурные ревью |
| ml-lead | Opus | `qa/real_photos_*`, `qa/scan-eval-runs/`, `agents/ML-*`, `pipeline/ref/` | стратегия точности, разбор промахов, брифы ml-engineer, решение «в бой» |
| ml-engineer | Sonnet | `packages/cv/`, `apps/api/app/cv/` (по брифу) | реализация ML-брифов с тестами и приёмкой |
| backend | Sonnet | `apps/api/`, `packages/rag/`, `packages/llm/` | API по контракту, конфиг, тесты |

`food_pairing_rules.yaml`), read-only для остальных ролей (решение тимлида, 22.09; вопрос
поднимал architect — `reports/architect-post-scan.md`, «владелец pipeline/ref/ не назначен»).

## Протокол

1. Тимлид пишет бриф `agents/<ROLE>-<тема>.md` (основание с цифрами, задача по пунктам, критерии
   приёмки, «не делать») и запускает роль. Роль читает `ORCHESTRATION.md`, `TEAM.md`, доску, бриф.
2. Роль работает в своей зоне, коммитит с pathspec, пишет `reports/<роль>-<тема>.md` и отвечает
   тимлиду ≤ 15 строк с цифрами. Пушит и ставит теги только devops.
3. Путь изменения в бой: ml-engineer/backend/frontend → qa-auto (approve/needs-work через живой API
   на 62 живых фото) → devops (тег `hack-vN`, прогон 100 фото на стенде, снимок метрик) → pm (доска).
4. Контракты правит только architect — по разделам «Предложения к контрактам» в отчётах.
5. Спорное и всё, что требует денег, внешних сервисов или действий Вячеслава, — через тимлида.
