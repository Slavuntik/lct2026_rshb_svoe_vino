# packages/winescan — второй движок распознавания

Актуальный источник: `standalone/winescan` в этом монорепо. Синхронизация: `make winescan-sync`; проверка: `make winescan-sync-check`. Подробности: [объединение от 24 сентября](../../docs/sync-2026-09-24.md).

Пакет приехал из отдельного репозитория (решение кейса ЛЦТ «Сканер российских вин»), где
велись измерения, и продолжает синхронизироваться с ним: `python tools/sync_winescan.py --check`
показывает расхождения, `--apply` переносит свежее состояние и записывает коммит источника в
`SYNC.md`. Правки, сделанные прямо здесь, скрипт покажет как расхождение и молча не затрёт;
единственное исключение — подпакет `winescan/integration`, он живёт только в монорепо.

## Чем он отличается от `packages/cv`

| | `packages/cv` | `packages/winescan` |
|---|---|---|
| Поиск бутылки в кадре | классический OpenCV: силуэт, фолбэк — центральный кроп | детектор OWLv2 + **обучаемый выбор** нужной рамки из нескольких бутылок |
| Эмбеддинги | SigLIP 2 `base-patch16-224`, один вид | SigLIP 2 `so400m-patch14-384`, два вида: упаковка и этикетка |
| Галерея эталона | 1 реальный + 24 синтетических ракурса, Qdrant | повороты цилиндра −30…+30°, максимум по векторам вина, точный перебор |
| Проверка кандидатов | OCR-верификатор (PaddleOCR) как tie-break | локальные признаки SIFT + гомография, гибридное слияние сигналов |
| Рамка от пользователя | нет | есть: доли кадра, детектор пропускается |
| Обучение | нет, всё zero-shot | обучаемый выбор рамки и слияние (бустинг и логистическая регрессия) |

Ни один из движков не «лучше» по определению: у `packages/cv` дешевле зависимости и быстрее
ответ, у `winescan` — больше сигналов и работа с кадром, где бутылок несколько. Какой из них
умолчание, решает общий замер — `docs/scan-engines.md`.

## Как включить

```bash
uv pip install -e packages/winescan"[ml]"      # torch ставится отдельно, см. ниже
IMAGE_PROVIDER=winescan uvicorn app.main:app   # из apps/api
```

`torch` с CUDA ставится под свою платформу (`--index-url https://download.pytorch.org/whl/cu126`).
На машинах без AVX2 это единственный рабочий путь: родной `packages/cv` тянет `paddlepaddle`,
которому AVX2 обязателен, — а здесь OCR при необходимости берётся в ONNX (`ocr-compare`).

Переменные окружения (полный список — в `winescan/service/pipeline.py::ScannerConfig.from_env`):

| Переменная | Умолчание | Смысл |
|---|---|---|
| `WINESCAN_ARTIFACTS_DIR` | `<пакет>/artifacts` | галерея, каталог карточек, признаки эталонов |
| `WINESCAN_UPLOADS_DIR` | из дампа кейса | эталонные фото для проверки по локальным признакам |
| `WINESCAN_INDEXES` | мультиракурсная пара | какие индексы складываются при поиске |
| `WINESCAN_BOX_CANDIDATES` | `3` | сколько рамок детектора оценивать |
| `WINESCAN_MIN_VISUAL_SCORE` | `0.74` | порог отказа «не найдено» |
| `CV_FAMILIES_JSON` | не задан | перепись near-dup семей кейса: с ней `gap` считается по правилу монорепо |

**Важно про пути.** Пакет считает своим корнем каталог с `pyproject.toml`, то есть
`packages/winescan`. Галерея и каталог карточек по умолчанию ищутся в
`packages/winescan/artifacts`; если они лежат в другом месте (например, общие для монорепо),
задайте `WINESCAN_ARTIFACTS_DIR` явно — иначе поиск честно упадёт на старте, а не ответит
молчанием.

## Сборка галереи

```bash
python -m winescan.search.build_index --yaws=-30,-15,0,15,30      # многоракурсная галерея
python -m winescan.search.build_index --view label --yaws=...      # вид «этикетка»
```

## Оценка

```bash
python -m winescan.eval.scanner_eval --split synth_v2 --tag default --holdout   # сквозной прогон
python -m winescan.eval.report                                                   # сводная таблица
python -m winescan.eval.ocr_compare --run <прогон> --split <выборка>              # EasyOCR против PP-OCRv5
```

Выборки синтетики: `v1` (простые сцены), `v2` (повороты, тесные соседи, ценники, смаз),
`v3` («другой тираж» — порча печати целевой упаковки), `v2p` (искривление запроса моделью,
не связанной с построением галереи). Пресеты парные: при одном посеве сцена не меняется,
меняется только проверяемый фактор — это позволяет считать разницу критерием Макнемара, а не
на глаз.

## Тесты

```bash
PYTHONPATH=packages/winescan pytest packages/winescan/tests -q
```

Тесты не требуют ни GPU, ни моделей, ни данных кейса.
