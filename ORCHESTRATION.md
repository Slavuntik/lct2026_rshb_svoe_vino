# Протокол мультиагентной разработки «Свой Сомелье»

Оркестратор — сессия Fable (эта ветка). Рабочие агенты — Sonnet. Ревьюер-тимлид — Fable.
План: `../docs/mvp-plan.html`. Архитектура: `../docs/architecture.html`. Демо-окно: 11–21.09, demo-ready 10.09.

## Незыблемое

1. **Контракты заморожены.** `contracts/` меняет только оркестратор. Нашёл дыру в контракте —
   не чини молча: зафиксируй в своём отчёте раздел «Предложения к контрактам» и работай
   по текущей версии (мок/заглушка на месте дыры).
2. **Пиши только в своей зоне.** Зона объявлена в твоём брифе `agents/<X>-*.md`.
   Чужие зоны и корень репо — read-only. Конфликтов быть не может по построению.
3. **Тесты — часть задачи, не приложение к ней.** Код без тестов = задача не сдана.
   Python — pytest; web — vitest. Тесты лежат в твоей зоне и проходят локально.
4. **Никаких ПД в логах, промптах и фикстурах.** Тестовые данные — вымышленные.
   Вкусовой профиль передаётся как безымянный вектор.
5. **Данные vines** (`/Users/vyacheslavfokin/ClaudeWorkspace/vines/{catalog,build,ref}`) — read-only.
6. **Сеть:** можно ставить зависимости (uv/npm). Нельзя деплоить, публиковать, регистрировать
   что-либо во внешних сервисах. LLM-ключей нет — работай на моках и фикстурах.

## Ритуалы

- **Коммиты:** мелкие, в своей зоне; сообщение `X: что сделано` (X — буква агента).
  Никогда `git add -A` из корня. **Коммитить ТОЛЬКО с явным pathspec:**
  `git commit -m "..." -- <свои пути>` — голый `git commit` забирает весь общий индекс,
  и в него попадают файлы, которые параллельный агент успел застейджить (случилось в b85223b).
- **Отчёт:** в конце — файл `reports/<x>-report.md`: что сделано, как запустить, как прогнать
  тесты (точные команды), покрытие DoD по пунктам, блокеры, предложения к контрактам.
  Краткую выжимку продублируй в финальном ответе.
- **Инструменты:** Python — `uv venv` + `uv pip install` внутри своей зоны (Python 3.12);
  web — npm. Docker на этой машине НЕТ: compose-файлы валидируем синтаксически.
  Полного Xcode НЕТ: iOS-проект генерируем, но не собираем — сборка на publish-Mac.

## Цикл ревью

Ревьюер-тимлид пишет `reviews/NN-<тема>.md`: блокеры / риски / придирки, вердикт по зонам
(approve / needs-work). Оркестратор превращает блокеры в задачи агентам следующей волны.
Спорить с ревью можно — письменно, в своём отчёте, с аргументами.
