# Shelf Finder API

Отдельный проект внутри `apps/shelf-finder`: свой Python-пакет `shelf_api`, порт
8086, HTTP API и фронтенд. Не импортирует `apps/api`, `apps/web` или WineScan.
В базовом режиме не требует внешних AI API; профиль `litellm` добавляет Qwen. Фото не сохраняются после запроса. Multipart-загрузчик может использовать временный
файл, который закрывается и удаляется после обработки.

## Установка и модели

Нужны Python 3.12+ и готовый комплект моделей. Поддерживаются CPU и NVIDIA GPU
с совместимым CUDA PyTorch. Для CPU используйте `make server-install-cpu`.
Команды выполняются из `apps/shelf-finder`:

```bash
make server-install
server/.venv/bin/python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

Подготовьте полный браузерный комплект `public/models/hybrid` по
[`docs/learned-recognition.md`](../docs/learned-recognition.md). Затем установите
зависимости экспорта **в то же окружение**, в котором будет работать сервер:

```bash
server/.venv/bin/python -m pip install -r scripts/requirements-learned.txt
CUDA_VISIBLE_DEVICES=2 server/.venv/bin/python scripts/prepare_server.py \
  --browser public/models/hybrid \
  --onnx-source artifacts/sources/LightGlue-ONNX \
  --xfeat-source artifacts/sources/XFeat \
  --output artifacts/server-models
```

Исходники моделей должны иметь ревизии из инструкции подготовки браузера. Экспорт
проверяет численное совпадение пяти ширин вырезок и пакетную проверку кандидатов.
В результате получается автономный комплект: модели TorchScript, детектор ONNX,
каталог и признаки всех эталонов. Исходные фото витрин, разметка и WineScan-сервис
при запуске не нужны. Комплект и виртуальное окружение не входят в Git.

На другом сервере используйте совместимую версию PyTorch; версия экспортера
записана в `server-manifest.json`. Экспорт и исполнение проверены на одной версии
PyTorch; совместимость произвольных версий не предполагается. Модели — доверенные
локальные артефакты, не пользовательские загрузки.

## Запуск

```bash
npm ci
npm run build
make serve GPU=2
# Интерфейс: http://localhost:8086/
# OpenAPI: http://localhost:8086/docs
```

Существующий корневой `Dockerfile` собирает только статический фронтенд, без GPU API.
Для серверного режима используйте запуск выше; в старом контейнере локальный режим
нужно выбирать явно через `?engine=hybrid` или `?engine=baseline`.

Выберите **свободную** GPU. `CUDA_VISIBLE_DEVICES` назначает её локальным `cuda:0`;
`SHELF_DEVICE=auto` выбирает CUDA при наличии, иначе CPU.
Для принудительного CPU: `make serve DEVICE=cpu`. Запускайте **один** uvicorn worker,
иначе каждая копия загрузит весь комплект и будет независимо принимать запросы.

Инициализация идёт в фоне. `/v1/shelf/health` возвращает 503 до проверки файлов,
загрузки всех 2103 эталонов и прогрева моделей. Ошибка подготовки также оставляет
сервис неготовым; подробности видны в журнале сервера.

Для разработки API можно запускать без статики:

```bash
CUDA_VISIBLE_DEVICES=2 server/.venv/bin/python -m uvicorn shelf_api.app:app \
  --host 127.0.0.1 --port 8086 --workers 1
npm run dev
```

Vite на 5180 проксирует `/v1/shelf/*` на 8086. Другой адрес задаётся через
`SHELF_API_PROXY`. В production предпочтителен один HTTPS-домен с проксированием
на 8086; внешний прокси должен пропускать фото до 20 МБ и ждать ответ не менее
330 секунд при стандартном клиентском ожидании 300 секунд. Полный список настроек — [`.env.example`](.env.example); его значения
нужно экспортировать в окружение процесса, файл не загружается автоматически.

Для проверки на iPhone нужен HTTPS. Сервер выставляет COOP/COEP для статики,
чтобы сохранённые локальные режимы также могли использовать многопоточность.
Серверный режим не загружает модели на телефон. Локальный режим выбирается явно
в переключателе или через `?engine=hybrid`; `?engine=baseline` сохраняет старые
пользовательские эталоны.

## Ограничения и API

[Контракт API](../docs/server-api.md). Принимается один запрос за раз, без очереди:
параллельный запрос получает 503 и `Retry-After`. Место занято до завершения обработки,
даже если клиент перестал ждать. Отмена в браузере отменяет ожидание/передачу, а не
прерывает уже запущенные вычисления. Фото: JPEG/PNG, до 20 МБ и 24 миллионов пикселей;
EXIF-поворот применяется до распознавания.

Сервер использует ALIKED/VLAD → XFeat/LighterGlue → независимое подтверждение ALIKED.
Это серверная реализация проверок браузерного гибрида, **не** SigLIP/SIFT из первого
замера 3090. Проверка кандидатов выполняется пакетами. Близкое первичное сравнение
может быть разрешено только явным преимуществом того же кандидата по второй модели.
Неоднозначные бутылки не получают названия. Точный год/винтаж не гарантируется.

## Проверки

```bash
make server-test
npm test
npm run build
SHELF_TEST_PHOTO=/path/to/vitrini/photo.jpg npm run test:browser
server/.venv/bin/python scripts/audit_server.py \
  --photos /path/to/vitrini --output artifacts/server-http \
  --files photo_2026-09-24_17-33-43.jpg photo_2026-09-24_17-33-59.jpg photo_2026-09-24_17-34-31.jpg
```

API-тесты используют поддельный движок, не требуют GPU или скачивания моделей.
`audit_server.py` вызывает настоящий API и сохраняет ответы без ручных подстановок.
Скорость HTTP на localhost не включает мобильную сеть и не является SLA под нагрузкой.

Результаты полного пути через Chromium и WebKit:
[проверка отдельного проекта](../docs/server-release-evaluation-2026-09-24.md).

## CPU, удалённый сервер и LiteLLM

Схемы запуска, переменные окружения и реальные замеры описаны в
[инструкции переносимого запуска](../docs/portable-litellm-2026-09-27.md).
`VINCHIK_SHELF_URL` — адрес полного сервиса витрины для `tools/run_local.py`;
`SHELF_LITELLM_URL` — OpenAI-совместимый шлюз `/v1`, не замена сервиса витрины.
Ключ хранится только на сервере. Профиль `litellm` отправляет шлюзу до трёх
спорных вырезок и эталоны, если настроены, сохраняя геометрическое подтверждение.
При недоступности шлюза возвращаются результаты локальных моделей с предупреждением.
