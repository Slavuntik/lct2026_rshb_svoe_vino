# Проверка точности на полках — 25 сентября 2026

## Что именно измеряем

`evaluation/shelves-v1.json` фиксирует SHA-256 и частичную разметку всех 17
фотографий. Три ранее демонстрировавшихся снимка относятся к `development`,
остальные 14 — к `regression`. Это **не независимый тест**: все фотографии
уже участвовали в предыдущем визуальном аудите. Нужны новые съёмки и независимая
проверка человеком, включая пропущенные детектором бутылки.

В разметке 32 положительных соответствия на уровне продукта, 546 отклонённых
кандидатов, 358 неопределённых областей и 3 ошибочные рамки. Отклонённый
кандидат не означает, что бутылки нет в каталоге. Урожай/точный SKU отдельно
не подтверждены. Скрипт оценки сопоставляет рамки один к одному при IoU ≥ 0,5;
непроверенные ответы учитывает отдельно, не объявляет их правильными или ложными.
Нельзя выводить общую accuracy/precision из этих неполных меток.

## Каталог и эталоны

4147 строк CSV дают 2103 позиции. На каждый SKU приходится одно уникальное
имя исходного фото; повторные строки не добавляют ракурсы. 11 пар используют
один исходный файл. В подготовленных галереях обнаружены 29 групп с полностью
одинаковыми файлами признаков **обоих** экстракторов (есть также дубликаты под
разными именами). API возвращает `alternativeWineIds` и
`identificationLevel: shared-reference`, интерфейс показывает варианты.
Это не подтверждение конкретного урожая или состава вина.

Подготовлены нижние вырезки этикеток для всех 2103 эталонов. Они являются
производными исходных изображений, а не новыми реальными ракурсами.

## Воспроизводимость

Артефакты, фото и веса не коммитятся. Все пути ниже относительно `apps/shelf-finder`.

```bash
python scripts/evaluate_shelves.py artifacts/accuracy/baseline-original/results.json \
  --output artifacts/accuracy/baseline-original/score.json

PYTHONPATH=server/src CUDA_VISIBLE_DEVICES=2 python scripts/audit_accuracy.py \
  --photos /path/to/vitrini --output artifacts/accuracy/run.json \
  --semantic artifacts/accuracy/semantic --limit 8 --budget 10

node scripts/prepare_query_variants.mjs /path/to/vitrini artifacts/accuracy/query-variants
```

Номер GPU выбирается по доступности. `audit_accuracy.py` не принимает разметку
и не использует её для распознавания. Результаты сохраняются после каждого фото.
Порог принятия и оценку после изменения нельзя представлять как независимую
валидацию: подбор на этих 17 фото остаётся разработкой.

## Экспериментальные модели

`prepare_accuracy.py` экспортирует ALIKED LightGlue (5 слоёв, 512 точек),
проверяет пары батчей 1/2/4/8 и строит галерею вырезок этикеток.
Нужен checkout LightGlue ONNX `d12b4ba1632f558234e3f084e1f3d8bdf9147890`.
`prepare_semantic.py` копирует локально закэшированный SigLIP2 и full/label
индексы с пятью синтетическими поворотами из каталога организаторов.
В сервисе нет импортов WineScan; после подготовки он работает автономно.
Веса и галереи проверяются по SHA-256, версия пайплайна учитывает код и конфигурацию.

[LightGlue](https://github.com/cvg/LightGlue) используется для геометрической
проверки, [SigLIP2](https://huggingface.co/google/siglip2-so400m-patch14-384)
— только для поиска кандидатов, не как доказательство идентичности SKU.
OCR выключен по умолчанию; при первом включении RapidOCR загружает свои веса
(либо использует заранее заполненный локальный кеш). Фото на внешний OCR-сервис
не отправляются. OCR допускается как проверка противоречий/разрешение ничьей между уже
геометрически подходящими кандидатами. Пустой текст и одно общее имя бренда
не подтверждают вино. В первом аудите 24 принятых областей OCR прочитал хоть
что-то в 10 случаях и не отклонил ни одного ответа: улучшение от OCR не доказано.

## Режим сервера

По умолчанию остаётся `SHELF_PROFILE=baseline`. Для эксперимента установите:

```bash
SHELF_PROFILE=accuracy
SHELF_ACCURACY_MODELS=/absolute/path/to/artifacts/accuracy/models
SHELF_SEMANTIC_MODELS=/absolute/path/to/artifacts/accuracy/semantic
SHELF_SEMANTIC_SCOPE=selected
SHELF_RESCUE_LIMIT=8
SHELF_BUDGET_SECONDS=12
SHELF_OCR=0
```

Дополнительные зависимости: `pip install -e './server[ml,accuracy]'`.
В выбранном режиме SigLIP2 проверяет предварительно принятые ответы и до восьми
спорных областей. Ответ, не входящий в его top-24, снимается; один SigLIP2
никогда не добавляет название без геометрической проверки. Для нового ответа
второго прохода требуется ещё более строгое согласие: тот же top-1 SigLIP2. Полный поиск по
всем рамкам доступен с `SHELF_SEMANTIC_SCOPE=all`.

Бюджет ограничивает начало дополнительной работы, **не гарантирует** ответ за
10 секунд: детектор, основной проход, текущая GPU-операция и загрузка фото
могут занять больше. Остановки по времени зависят от загрузки сервера;
для сравнения качества используйте большой бюджет и фиксированный лимит.
Сначала прогрейте модели. Измеряйте холодный старт отдельно.

## Передача фото

В серверном режиме JPEG/PNG до 6 МиБ и 24 Мп отправляются исходным файлом.
EXIF нормализует сервер; размеры ответа сверяются с ориентированным оригиналом,
а нормированные рамки накладываются на уменьшенный экранный canvas.
Другие/большие файлы проходят прежний ограниченный canvas-путь. Снимок с камеры
и локальное распознавание продолжают использовать canvas. Детектор работает
на копии до 1920 пикселей, признаки вырезаются из исходного изображения.
Загрузка больших фото может увеличивать время на мобильной сети.

## Измеренные результаты

Окружение замера: Python 3.12, PyTorch 2.14.0+cu126, Transformers 5.17.0,
ONNX Runtime 1.30.0, OpenCV 5.0.0.93, NumPy 2.5.3, RapidOCR 3.9.2.

RTX 3090 на общем сервере; другие задачи продолжали работать. Время включает
обработку модели, для HTTP-вариантов — также локальную передачу, но не
мобильную сеть. Режимы запускались последовательно. Это отдельные прогоны,
поэтому малую разницу времени нельзя считать доказанным ускорением.

| Режим, все 17 фото | Найдено из 32 известных | Известные ошибки | Непроверенные ответы | Медиана / максимум, с |
|---|---:|---:|---:|---:|
| Исходный сервер, оригиналы | 14 | 1 | 5 | 7,75 / 12,20 |
| ALIKED LightGlue + вырезки, до 80 уточнений | 17 | 3 | 11 | 16,65 / 22,63 |
| SigLIP2 для всех рамок + тот же второй проход | 18 | 2 | 12 | 22,45 / 29,65 |

На трёх знакомых снимках усиленные режимы дали 15/15, но на остальных —
только 2/17 и 3/17. Поэтому результат 15/15 нельзя переносить на новые полки.
Расширенный проход не включён по умолчанию: прирост найденных бутылок
сопровождается ростом известных ошибок и времени.

### Следующий необходимый набор данных

Новая съёмка других полок, затем независимая разметка: рамка каждой бутылки,
точная позиция/семейство/неизвестно, читаемость этикетки и отсутствующие в
каталоге продукты. Разделять тест и обучение по магазину и съёмочной сессии,
а не случайным вырезкам соседних бутылок. Только после фиксации теста подбирать
пороги/дообучать на трудных парах внутри бренда. На текущих 32 положительных
соответствиях нельзя надёжно обучить и независимо проверить распознаватель.


Первые сравнения SigLIP2 проводились без проверки согласия top-24
(`audit_accuracy.py --no-semantic-veto`). Это исследовательские варианты,
не окончательный режим. Для полноценного сравнения любой новый порог нужно
подтвердить на новых фотографиях, не использованных в этом отчёте.

## Финальная HTTP-проверка

После прогрева выполнены все 17 запросов к реальному FastAPI, оригинальные
файлы, `selected`, 8 уточнений, мягкий бюджет 12 секунд, OCR выключен.
Дополнительный ответ принимается только при согласии с top-1 SigLIP2.

- Найдено **14/32** частично размеченных продуктов — прироста полноты нет.
- Ошибок по зафиксированным меткам: **0** вместо 1.
- Ещё **4 ответа не проверены этой разметкой**. Нельзя писать «ошибок нет»
  или «precision 100%»: похожие варианты всё ещё могут путаться.
- HTTP-медиана **8,89 с**, максимум **11,82 с** на этом общем сервере.
- На 14 дополнительных фото по-прежнему **0/17** известных положительных
  соответствий. Это главный оставшийся недостаток; успешная демонстрация
  трёх development-фото его не устраняет.

Компактные результаты 12 сравнений, конфигурации, версии пайплайна и SHA-256
исходных отчётов: `evaluation/results-2026-09-25.json`.
Полные диагностические результаты остаются в `artifacts/accuracy/`.

Локальный Vinchik запущен с этим экспериментальным профилем для дальнейшей
проверки; параметры сохранены только в игнорируемом `.env`. В репозитории
значение по умолчанию — `baseline`, чтобы новая установка не требовала
дополнительных весов автоматически. Возврат: `SHELF_PROFILE=baseline` и
перезапуск shelf API. Не включать полный второй проход на всех бутылках
ради цифры 18/32: в этом режиме выросло число известных ошибок.


Проверка через встроенный iframe основного Vinchik в WebKit (размер экрана
как у iPhone 13): четыре фото, **7,81–11,49 с** с передачей и отрисовкой.
Ошибок JavaScript и горизонтального переполнения iframe не обнаружено.
Onboarding в изолированном тестовом контексте задан локальной тестовой
фикстурой; реальные учётные записи/согласия не создавались.
