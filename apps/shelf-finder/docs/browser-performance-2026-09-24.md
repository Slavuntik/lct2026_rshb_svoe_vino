# Бюджет времени браузерного распознавания

Цель пользователя — до **10 секунд на полную витрину**, с сохранением качества.
Она пока **не достигнута**. Базовая проверенная версия — `f0c6823`: 14/15 известных
контрольных бутылок за 83–84 секунды на фото. Это время после загрузки моделей;
первый запуск и скачивание индекса измеряются отдельно. Минимальное устройство
уточнено пользователем: **iPhone 13**, более новые iPhone также входят в целевой набор.
Основным браузером принят Safari. Физическое устройство ещё не проверено.

## Где тратится время

В трёх браузерных прогонах детектор занял 2,49 / 2,85 / 2,70 секунды,
распознавание — 81,73 / 80,22 / 80,61 секунды. Значит, ускорение одного детектора
не позволит достичь цели. Для каждой бутылки выполняются два извлечения признаков,
поиск по каталогу и геометрическая/нейросетевая проверка кандидатов.

Проба на одной вырезке AGORA в Chromium/WASM: 3,53 секунды, из них два извлечения
признаков — 1,53 секунды, поиск VLAD — 0,15, грубая проверка — 0,25,
четыре вызова LighterGlue — 0,85. Чтение эталонов частично параллельно;
вложенные длительности нельзя складывать как независимые стадии.

## Проверенные варианты

| Вариант | Наблюдение | Решение |
| --- | --- | --- |
| Высота вырезки 256 вместо 512 | Правильный товар в top-24: 10/15 вместо 14/15 | Не включать |
| Высота 128 или 384 | Правильный товар в top-24: 1/15 или 12/15 | Не включать |
| Обязательная ALIKED-проверка до LighterGlue | Первая витрина: 5 принятых совпадений, 107,2 с | Откатить эксперимент |
| INT8 свёртки ALIKED | Одна вырезка: 4,04 с, из них извлечение 1,55 с; AGORA распознана | Не включать без доказанного ускорения |

Проба разрешений выполнена в PyTorch на GPU по рамкам браузерного детектора,
со старым каталогом признаков 512 px. Это оценка кандидатов, не итоговая точность
браузера и не проверка переобученного индекса меньшего разрешения.
INT8 использовал ONNX QOperator, поканальные веса, 32 эталона каталога для
калибровки; фото витрин в калибровку не входили. Индекс оставался исходным.
Замеры получены на общем сервере с меняющейся нагрузкой, без статистически
надёжного сравнения. Они не подтверждают выигрыш этих вариантов.

Локальные диагностические данные: `artifacts/browser-upgrade/scale-probe.json`,
`artifacts/browser-speed-gate/results.json` (только первая витрина),
`artifacts/browser-upgrade/retriever-int8.onnx`. Они не входят в рабочий комплект.

## Что требуется для приёмки ускорения

- Проверять на iPhone 13 / Safari; измерять холодный запуск отдельно от обработки.
- Сократить повторное извлечение признаков: исследовать общий проход по изображению
  или компактный первый этап поиска с дорогой проверкой только неоднозначных областей.
- Для нового метода заново подготовить индекс из эталонов и проверять весь набор,
  а не только успешную вырезку; не уменьшать пороги ради количества подсветок.
- Сравнить качество, время, память и нагрев на физических телефонах. До такой проверки
  не заявлять выполнение бюджета 10 секунд.

## Путь для iPhone 13 и новее

Safari 26 добавил WebGPU на iOS ([WebKit](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/)).
Поэтому GPU-проверки ориентированы на Safari 26+, а старые версии продолжают использовать
WASM. Номер модели iPhone сам по себе не гарантирует доступность GPU в браузере:
приложение проверяет адаптер и пробный запуск. WASM сохраняется при отказе GPU.

В установленном `onnxruntime-web` 1.22.0 таблица WebGPU-операторов
`lib/wasm/jsep/webgpu/op-resolve-rules.ts` содержит `Elu` и `Mul`, но не `Selu`.
Исходный ALIKED содержит 17 `Selu`. Экспорт теперь заменяет каждую на
`gamma * Elu(x, alpha)`, сохраняя коэффициенты и веса. Это устраняет конкретный
источник CPU-переходов, а не доказывает ускорение всей цепочки. `TopK` и другие
операции по-прежнему могут требовать WASM. Проверка экспорта сравнивает признаки
PyTorch/ONNX и записывает число замен в `export-validation.json`.

Проверка нового экспорта: 17 замен; на ширинах 128/192/256 соответствие точек
PyTorch/ONNX — 100%, максимальное отличие дескрипторов — 0,00000295.
21 TypeScript-тест, 2 теста численной эквивалентности Python и production-сборка
прошли. Linux WebKit/WASM распознал контрольную вырезку AGORA за 3,40 с, без ошибок
и внешних запросов. Это проверка совместимости, не замер полной витрины на iPhone.
Локальные данные экспорта: `artifacts/browser-upgrade/iphone-webgpu/export-validation.json`.

Для приёмки на устройстве:

1. Открыть отдельное приложение через HTTPS; записать модель iPhone, версию iOS/Safari
   и состояние энергосбережения. Дождаться полной загрузки каталога.
2. Включить «Плотная полка» и «Вся полка», обработать три исходных контрольных фото.
   Для каждого скачать JSON результата; записать отдельно полное ожидание в интерфейсе.
3. Повторить каждое фото три раза без перезагрузки. Сопоставить время, найденные позиции,
   пропуски и ложные совпадения с исходным отчётом. Не считать одну удачную вырезку
   или размер viewport доказательством работы полной витрины за 10 секунд.
4. Повторить после нескольких минут работы, проверить отмену и отсутствие перезагрузки
   вкладки из-за памяти. Замеры с GPU и с WASM учитывать отдельно.
