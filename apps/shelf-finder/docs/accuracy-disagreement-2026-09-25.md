# Приоритет второго прохода: эксперимент 25 сентября 2026

## Причина изменения

В зафиксированном наборе осталось 18 пропусков. В диагностическом полном
SigLIP2-прогоне правильный продукт был первым кандидатом для всех этих 18
областей. Среди всех 32 положительных меток top-1 верен для 28, остальные
правильные кандидаты занимают места 2 или 8. IoU сопоставленных областей
выше 0,99999; это не результат сопоставления с соседней бутылкой.

У 13 из 18 пропусков правильный продукт отсутствовал в первых 24 кандидатах
старого VLAD-поиска; у 12 ALIKED находил минимум 16 согласованных точек при
прямой диагностической проверке эталона. Эта проверка использовала известный
ответ для анализа причины пропуска, **не для распознавания**.

Метки получены предыдущим визуальным аудитом ИИ и частично зависят от ранее
предложенных кандидатов. Поэтому эти числа не являются независимой оценкой
retrieval accuracy и не оправдывают автоматическое принятие top-1.

## Что изменено

Новый режим `--rescue-policy disagreement`:

1. Для каждого непринятого региона проверяет ALIKED-геометрию трёх визуальных
   кандидатов. Очередь сортируется по поддержке **визуального лидера**:
   точки на этикетке, общее число согласованных точек, их доля.
2. Передаёт трёх визуальных кандидатов в сильный matcher даже тогда, когда
   старый предварительный отбор выдвигал других конкурентов.
   Предварительный MNN-фильтр «меньше 8 точек — не запускать сильную модель»
   для выбранных регионов обходится; окончательные пороги остаются прежними.
3. Сохраняет этих кандидатов и при проверке отдельной вырезки этикетки.
4. Записывает `priorityEvidence`, `rescuePriority`, `rescueQueueRank` и
   `rescueCandidates`, чтобы причину выбора можно было проверить.

Пороги окончательного принятия: геометрия, требуемый отрыв, минимальная поддержка этикетки и согласие
с top-1 SigLIP2 для нового принятого ответа не снижены. Сам по себе первый
кандидат названия не подтверждает. Это изменение очереди и состава проверяемых
кандидатов, а не обученный общий классификатор уверенности.

По умолчанию остаётся `legacy`. Новый режим пока доступен в автономном
эксперименте и требует `--semantic-scope all`: по выборочно вычисленным
кандидатам невозможно честно ранжировать все пропуски.

## Сравнение

```bash
PYTHONPATH=server/src CUDA_VISIBLE_DEVICES=2 \
OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 python scripts/audit_accuracy.py \
  --photos /path/to/vitrini \
  --output artifacts/accuracy/disagreement-comparison.json \
  --semantic artifacts/accuracy/semantic --semantic-scope all \
  --limit 8 --budget 60 --compare-rescue
```

Обе очереди используют одинаковые фото, модели, первые проходы, пороги,
лимит 8 регионов и бюджет 60 секунд. Порядок очередей чередуется между
фотографиями; модели загружаются один раз. Каждый проход заново вычисляет
признаки запроса. Фото и разметка не передаются внешним сервисам;
скрипт распознавания не принимает файл разметки.

Большой бюджет выбран для сравнения качества при фиксированном объёме работы.
Это **не** доказательство выполнения требования 10 секунд. Полный SigLIP2 и
предварительная проверка очереди входят в измеренное время. Сравнение с прежним
HTTP-профилем `selected/12 секунд` нужно показывать отдельно.

Выходы сохраняются атомарно после каждого снимка в отдельные JSON для
`legacy` и `disagreement`. В версии каждого результата указан вариант очереди.
Оценка использует неизменённый `evaluation/shelves-v1.json`: неизвестные
совпадения учитываются отдельно от ошибок и правильных ответов.


Изменения очереди и состава кандидатов сравниваются совместно. Их отдельный
вклад этим прогоном не установлен. Ранжирование использует согласованные
точки визуального лидера; вероятность правильности или калиброванный отрыв
SigLIP2 здесь не вычисляются.

Для воспроизводимого разбора пропусков:

```bash
python scripts/analyze_rescue.py artifacts/accuracy/disagreement-comparison-legacy.json
python scripts/analyze_rescue.py artifacts/accuracy/disagreement-comparison-disagreement.json
```

Анализ различает непопадание в лимит работы, отсутствие правильного кандидата
в сильной проверке и фактический отказ после её запуска. Он читает разметку
только после завершения распознавания и перечисляет отсутствующие фото,
чтобы неполный прогон нельзя было принять за результат всего набора.

## Результат полного прогона

17 исходных JPEG, RTX 3090 (GPU 2 на общем сервере), одинаковые загруженные
модели, 8 регионов второго прохода, полный SigLIP2, semantic veto включён.
Разметка и пороги не менялись.

| Вариант | Правильно / 32 | Известные ошибки | Непроверенные ответы | Медиана / максимум, с |
|---|---:|---:|---:|---:|
| Legacy, полный SigLIP2 | 16 | 0 | 5 | 16,53 / 24,91 |
| Disagreement, полный SigLIP2 | 18 | 0 | 5 | 18,24 / 24,22 |

На трёх development-фото оба режима нашли 15/15; на остальных 14 фото —
1/17 и 3/17 соответственно. Два дополнительных совпадения —
`balaklava-pino-nuar` и `balaklava-muskat-beloe-polusladkoe` на
`photo_2026-09-24_17-34-02.jpg`. Они поднялись с мест 22 и 34 в очереди
на места 1 и 2. Уже найденные положительные метки не потеряны.

Причины по 32 положительным меткам:

| Причина | Legacy | Disagreement |
|---|---:|---:|
| Принято | 16 | 18 |
| За пределами лимита 8 регионов | 9 | 6 |
| Проверено, но отклонено | 6 | 7 |
| Не поставлено в очередь | 1 | 1 |

Это умеренный прирост на прежней частичной разметке, а не независимая оценка
точности на новых полках. Ноль известных ошибок не доказывает отсутствие
ошибок среди пяти непроверенных ответов. Повторных замеров для оценки
разброса задержек не было; сервер используется совместно. Время указано
для обработки моделями, без сети и браузерного интерфейса.

Ранее работающий HTTP-профиль `selected`, бюджет 12 секунд, давал 14/32
при медиане 8,89 с. Его нельзя напрямую смешивать с данным сравнением:
изменены охват SigLIP2 и бюджет. Новый вариант не включён в API по умолчанию.
Следующий шаг — уменьшить дублирование первого и семантического проходов
и проверить сохранение прироста при бюджете 10 секунд; этот результат
пока не получен.
