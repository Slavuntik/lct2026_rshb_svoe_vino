# Переносимый запуск витрины: CPU, GPU и LiteLLM

> Обновление 28.09.2026: для действующих нативных стендов используется [CPU + LiteLLM и API-шлюз](../../../infra/native/README.md). Старые инструкции прямого nginx-проксирования ниже описывают альтернативную схему.

## Схемы

1. Весь Shelf API на CPU: `SHELF_DEVICE=cpu`, `SHELF_PROFILE=baseline`.
   Детектор, поиск кандидатов и геометрическое подтверждение работают локально.
2. CPU/GPU + удалённый Qwen: `SHELF_PROFILE=litellm`. Локальные модели сохраняются;
   LiteLLM проверяет до трёх спорных вырезок за один запрос. Это не удалённый XFeat.
3. Полный Shelf API на GPU-хосте: приложение Vinchik проксирует его через
   `VINCHIK_SHELF_URL=http://gpu-host:8086`. Локальный launcher не запускает вторую
   копию Shelf API. При недоступности адреса запуск завершается с ошибкой, а не
   незаметно переключается на локальную модель.

`SHELF_DEVICE=auto` выбирает доступную CUDA либо CPU при запуске. Это не переключение
после OOM/ошибки работающей GPU. Для CUDA выбирайте свободную физическую карту через
`CUDA_VISIBLE_DEVICES`; внутри процесса используется `cuda:0`. Launcher сохраняет
унаследованную маску, если `SHELF_GPU` не задан; `make serve` также не назначает карту
по умолчанию. Явные `SHELF_GPU` / `make serve GPU=N` переопределяют выбор.
При `SHELF_DEVICE=cuda` запущенный CPU-сервис не переиспользуется: нужен перезапуск.

## Перенос на другой сервер

Скопируйте доверенный `artifacts/server-models` целиком, включая manifest и признаки
2103 товаров. Git не содержит веса и каталог. Для визуальных подсказок Qwen можно
также скопировать `reference_views/*.png` (имена `<catalog-id>.png`). Сырые датасеты,
WineScan и GPU на принимающем CPU-сервере не нужны.

Из `apps/shelf-finder`:

```bash
make server-install-cpu  # CPU wheels; для GPU: make server-install
npm ci
npm run build
export SHELF_MODELS_DIR=/absolute/path/to/server-models
export SHELF_DEVICE=cpu
export SHELF_PROFILE=litellm
export SHELF_LITELLM_URL=https://your-model-gateway/v1
export SHELF_LITELLM_MODEL=qwen3.8-27b-uncensored
# SHELF_LITELLM_API_KEY передайте через закрытый env-файл/секрет окружения.
# Вместо URL/key можно использовать VISION_LLM_URL и VISION_LLM_KEY.
export SHELF_LITELLM_REFERENCES_DIR=/absolute/path/to/reference_views
make serve DEVICE=cpu
```

Для работы без внешнего API задайте `SHELF_PROFILE=baseline`. Uvicorn сам не читает
`.env`; экспортируйте значения в окружение. Корневой `tools/run_local.py` читает
корневой `.env` и сохраняет явно заданный `VINCHIK_SHELF_URL`. Изменение профиля уже
работающего локального Shelf API требует его перезапуска.

Один worker на сервис: он принимает одну обработку одновременно, остальные получают
503/Retry-After. Отмена браузера не останавливает вычисления. `/v1/shelf/health`
показывает готовность, фактическое устройство, профиль и клиентский таймаут.

В production используйте существующие `/v1/shelf/` и `/shelf-ui/` locations в
`infra/ams3/nginx-somelye.conf`. Реальный upstream задаётся **только на сервере** в
`/etc/nginx/conf.d/shelf-upstream.conf`; Git сохраняет выключенный плейсхолдер.
Существующая Basic Auth остаётся включённой. Перед reload нужен `nginx -t`.
Стандартное ожидание клиента — 300 секунд, прокси — 330. Если увеличить
`SHELF_SCAN_TIMEOUT_SECONDS` (15–600), согласуйте таймауты обоих прокси.
Это срок ожидания клиента, не принудительное завершение серверных вычислений.

## Ограничения Qwen

Ключ используется только сервером. В шлюз уходят вырезки, названия кандидатов и
доступные эталоны; изображения сервис не сохраняет. Перенаправления HTTP запрещены,
TLS проверяется. `SHELF_LITELLM_TIMEOUT=60` ограничивает всю сетевую операцию,
включая отправку, заголовки и потоковое чтение ответа. Время подготовки вырезок
вычитается из сетевого бюджета; локальная подготовка и CV не прерываются принудительно.
Ответ ограничен 256 KiB. После двух последовательных отказов клиент пропускает
обращения к шлюзу на 30 секунд; после успешной попытки счётчик сбрасывается.
`SHELF_LITELLM_LIMIT=3` допускает диапазон 1–8.

Выбор Qwen не становится зелёной рамкой автоматически: требуется независимое
геометрическое подтверждение ALIKED/XFeat и минимум 16 inliers на этикетке.
Ранее подтверждённые бутылки сохраняются. Ошибка шлюза/JSON возвращает локальные
результаты с предупреждением; неизвестные бутылки остаются без подписи.

## Проверка 27.09.2026

Реальная фотография `photo_2026-09-24_17-33-43.jpg`, 960×1280, 2103 товара,
CPU threads=4, GPU скрыты через `CUDA_VISIBLE_DEVICES=''`:

| Режим | Обработка | Подтверждённые рамки |
| --- | ---: | ---: |
| baseline CPU | 31,28 с | 4 |
| CPU + LiteLLM, полный HTTP | 61,18 с | 4 |

Qwen `qwen3.8-27b-uncensored` успешно проверил три спорных бутылки; новых
геометрически подтверждённых совпадений нет. Детектор предложил 44 области.
RSS базового CPU-процесса около 1,8 GiB. Это один снимок на текущем сервере,
не замер точности всего датасета и не обещание скорости на другом CPU/телефоне.
Здесь нет доказательства улучшения качества относительно локального режима.

CPU проверен на Torch 2.14.0+cu126 с невидимыми GPU. Проверка на машине с установленным
CPU-only wheel отдельно не проводилась. Загрузчик исправляет CUDA device literals
в доверенных TorchScript-графах; простого `map_location=cpu` недостаточно.
Используется внутренний graph API, поэтому сверяйте версию с manifest экспортера.
Полный профиль `accuracy` на CPU и развёртывание на внешнем production-хосте
этим прогоном не проверены.

Проверки: pytest сервера, Vitest витрины/основного UI, обе production-сборки.
Браузерный сетевой тест включается явно:

```bash
SHELF_TEST_PORT=15180 SHELF_API_PROXY=http://127.0.0.1:8086 \
SHELF_SERVER_TEST_PHOTO=/path/to/photo.jpg npm run test:browser -- tests/browser/server-live.spec.ts
```

Тест отправляет настоящий снимок; при профиле `litellm` используется шлюз и его квота.


Итоговая проверка: 37 pytest сервера, 24 Vitest витрины, 187 Vitest основного
интерфейса; обе production-сборки успешны. Chromium: 7 браузерных сценариев,
включая реальное фото. WebKit с эмуляцией iPhone 13: 6 сценариев, включая ожидание
300 секунд через виртуальные часы, и отдельный реальный запрос через основной
Vinchik `/shelf-ui/` → `/v1/shelf/` → CPU API.

Повторные запросы через основной прокси завершились за 33,73 с (Chromium) и 32,08 с
(WebKit), по четыре совпадения, но с предупреждением о недоступности Qwen:
шлюз вернул неуспешный HTTP-ответ. Первый успешный прогон Qwen выше не доказывает
его постоянную доступность. Сетевой timeout клиента повышен с 25 до 60 секунд;
это не устраняет ошибки самого шлюза. Резервный локальный путь проверен реально.
Проверки на физическом iPhone и `nginx -t` на production-хосте не выполнялись.

Последний прямой контрольный запрос к выбранному Qwen через настроенный ключ
получил HTTP 401 (`auth_error`). Для восстановления удалённой проверки необходимо
проверить актуальность ключа и его доступ к модели на стороне LiteLLM. Секрет
в репозиторий не записывался; базовое CPU-распознавание от него не зависит.

Исправления по последующему ревью и актуальные проверки:
[отчёт об исправлениях](adversarial-fixes-2026-09-27.md). Раздел замеров выше —
исторические результаты предыдущей реализации, не повторный benchmark после исправлений.
