# API отдельного модуля витрин

Реализован самостоятельным пакетом `server/src/shelf_api`, порт 8086. Текущий интерфейс
использует его по умолчанию; локальный режим доступен через `?engine=hybrid`.
[Установка и запуск](../server/README.md). Модели исполняются нативно на CUDA;
признаки полного каталога загружаются до готовности health.

Внешние API распознавания и ключи OpenAI/Gemini не требуются. Нужны собственный
GPU-сервис на RTX 3090, подготовленные модели/индексы и HTTPS-прокси. Предпочтительно
проксировать `/v1/shelf/*` с того же домена, что и интерфейс; при разных доменах
потребуется CORS для домена приложения. Постоянные серверные ключи в браузер не передавать.

## Endpoints

| Метод и путь | Назначение |
| --- | --- |
| `POST /v1/shelf/scan` | Принять фото и вернуть все принятые совпадения на витрине |
| `GET /v1/shelf/health` | Готовность именно модуля витрин: модели и весь индекс прогреты |
| `GET /v1/shelf/catalog` | Необязательно: список SKU, названия и группы для фильтра интерфейса |

Основной сканер и его существующие маршруты сохраняются. Новый endpoint использует
собственный движок с пакетной проверкой кандидатов на GPU.

## Загрузка и ответ

`POST /v1/shelf/scan`: `multipart/form-data`, обязательное поле `image` (JPEG/PNG).
Для первой версии достаточно синхронного ответа с согласованным таймаутом клиента
и прокси, 45 секунд в клиенте; это не обещание скорости. До приёма запроса проверяются
готовность и занятость GPU. Очереди ожидания нет: второй запрос получает 503.

Пример структуры ответа; значения иллюстративные, не результат нового прогона:

```json
{
  "requestId": "request-123",
  "pipelineVersion": "shelf-server-v1",
  "catalogVersion": "organizers-2103-v1",
  "image": { "width": 960, "height": 1280 },
  "detectedCount": 44,
  "matches": [
    {
      "box": [0.12, 0.18, 0.21, 0.47],
      "wineId": "agora-bastardo",
      "name": "AGORA Бастардо"
    }
  ],
  "timingsMs": { "queue": 0, "processing": 6800 },
  "warnings": []
}
```

`box` — `[x1, y1, x2, y2]` в диапазоне 0–1 относительно исходного изображения
после применения EXIF-ориентации, до внутреннего уменьшения/нарезки. Размеры `image`
относятся к этой же системе координат. Браузер рисует зелёную заливку и название
только для `matches`; пустой список — корректный результат, а не ошибка сервера.
Не выдавать cosine/inlier ratio за вероятность правильности названия.

Ошибки: `400` — повреждённое изображение, `413` — превышены 20 МБ или 24 миллиона пикселей, `415` — неподдерживаемый формат, `503` с `Retry-After` —
прогрев или занятый GPU. Фото и временные файлы загрузки освобождаются после запроса; постоянное хранение
и использование для обучения по умолчанию выключены.

`GET /v1/shelf/health`: `200` с `ready: true` после загрузки моделей и признаков
эталонов; иначе `503` с `ready: false`. Готовность всего каталога важна: первый запрос
с ленивой подготовкой эталонов в замере занял 47 секунд.

Отмена ожидания клиентом не прерывает запущенный CUDA-запрос: место освобождается
после фактического завершения работы. Фото закрывается и освобождается в обоих случаях.

Асинхронные задания, polling и SSE можно добавить при росте очередей; для первого
измеряемого подключения телефона они не обязательны. Результаты настоящего API и браузерного интерфейса:
[проверка серверного проекта](server-release-evaluation-2026-09-24.md).
