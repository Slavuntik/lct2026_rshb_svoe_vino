# LiteLLM / Qwen на полках: эксперимент 26 сентября 2026

## Что проверено

Пользовательский шлюз `/v1/models` предоставил `qwen3.8-27b` и
`qwen3.8-flash`; имени «qwen 2.8» в списке нет. Запросы отправлялись по HTTPS
с проверкой сертификата. Ключ берётся из локального `.env` и не сохраняется
в отчётах. В основной API этот эксперимент не включён.

Три снимка: `17-34-02`, `17-33-43`, `17-34-16` от 24 сентября. Проверены:

1. Детекция и OCR целой полки — один пилотный снимок, Qwen 27B.
2. OCR 12 пронумерованных вырезок за запрос без каталога — все три снимка.
3. Те же вырезки плюс пять кандидатов SigLIP2 на бутылку — все три снимка,
   отдельно Qwen 27B и Flash. Разрешён отказ `selected_id=null`.

Вырезки выбирались автоматически из сохранённого native-прогона: до четырёх
принятых регионов, затем непринятые по очереди второго прохода, всего до 12.
Разметка не использовалась ни для выбора вырезок, ни в запросах модели.
Это 36 вырезок, содержащих 10 из 14 известных положительных меток этих фото.
Таблица ниже относится именно к этим областям. Метки прежние, частичные,
получены визуальным аудитом ИИ: это не независимый экспертный тест.

## Результаты

| Режим | Правильно / 10 | Известные ошибки | Непроверенные принятые ответы | Медиана задержки |
|---|---:|---:|---:|---:|
| Native на тех же вырезках | 6 | 0 | 3 | не измерялась отдельно для вырезок |
| Qwen 27B + кандидаты | 4 | 4 | 3 | 19,81 с дополнительно |
| Qwen Flash + кандидаты | 4 | 4 | 3 | 16,71 с дополнительно |

Нативные результаты взяты из прежнего экспериментального полного SigLIP2
прогона, а не из быстрого HTTP-профиля. Модели LLM получают готовые вырезки
и кандидатов: в их время **не входит** локальная детекция и поиск кандидатов.
Медиана native на целых трёх снимках в прошлом прогоне — 19,72 с; измерения
выполнены в разное время, складывать их в подтверждённую сквозную задержку нельзя.

Qwen 27B без каталожных подсказок читал 12 вырезок за 7,43–9,47 с. Формальный
CER/WER не вычислен: эталонных транскрипций нет. В ответах заметны искажения:
например, «ЛАФР-РЮС» вместо надписи Абрау-Дюрсо. После добавления кандидатов
OCR меняется, поэтому совпадение с названием кандидата нельзя считать
независимым подтверждением прочитанного текста.

На целом кадре 27B вернул 47 валидных рамок за 31,30 с. 43 рамки сопоставились
один к одному с 66 областями прежнего набора при IoU ≥ 0,5. Это согласованность
с прежними регионами, **не** mAP и не доказательство полноты детекции.

Простое добавление новых LLM-ответов к native на трёх целых снимках дало
7 правильных вместо 6, но 2 известных ошибки вместо 0 и 8 непроверенных
ответов вместо 5. Такую комбинацию включать как уверенное распознавание нельзя.

Всего выполнено 10 запросов, шлюз сообщил 41 408 токенов. Денежная стоимость
не вычислялась: тариф не известен. Первый запрос Flash мог пересекаться с
последним запросом 27B; задержки ориентировочные, без повторов. Имена моделей
— идентификаторы шлюза, устройство и фактические веса за ними не проверялись.

## Практический вывод

На этих снимках LLM не улучшила самостоятельное распознавание SKU. Возможное
применение — дополнительное чтение нескольких спорных этикеток с передачей
текста в поиск. Чтобы это проверить, следующий отдельный эксперимент должен
читать бутылки без подсказок каталога, сохранять неопределённость и требовать
независимого геометрического подтверждения. Общего бренда недостаточно для
выбора сорта/сахара/цвета. Потребуется также независимая разметка текста.

Увеличенные вырезки не восстанавливают детали, потерянные в исходных 960×1280.
Более крупное фото этикетки стоит проверять раньше, чем наращивать промпт.
Требование 10 секунд для всей полки этим экспериментом не достигнуто.

## Воспроизведение

Из корня монорепозитория (локальные пути заменяются своими):

```bash
pip install -r apps/shelf-finder/scripts/requirements-vlm.txt
python apps/shelf-finder/scripts/audit_vlm.py \
  --env-file .env --photos /path/to/vitrini \
  --files photo_2026-09-24_17-34-02.jpg photo_2026-09-24_17-33-43.jpg photo_2026-09-24_17-34-16.jpg \
  --mode guided --model qwen3.8-27b \
  --native-results apps/shelf-finder/artifacts/accuracy/disagreement-comparison-disagreement.json \
  --catalog /path/to/catalog.jsonl \
  --output apps/shelf-finder/artifacts/vlm/qwen-guided.json
```

`--mode full` не требует native-результатов и каталога, `--mode crops` требует
только native-результаты. `--model qwen3.8-flash` меняет модель.
Каждый вызов отправляет изображения на настроенный шлюз; автоматического
запуска в приложении нет. В full-режиме возвращённый массив нормализуется
в `bottles`, если модель не соблюла внешнюю JSON-обёртку.

```bash
python apps/shelf-finder/scripts/evaluate_vlm.py \
  apps/shelf-finder/artifacts/vlm/qwen-guided.json \
  --dataset apps/shelf-finder/evaluation/shelves-v1.json \
  --native-results apps/shelf-finder/artifacts/accuracy/disagreement-comparison-disagreement.json \
  --output apps/shelf-finder/artifacts/vlm/qwen-score.json
```

Оценщик отвергает неизвестные SKU, повторные номера вырезок и ответы без
текстового обоснования. Это проверка формата, не доказательство истинности
обоснования. Тест этих ограничений проходит без сети и моделей.

[Сводный JSON с метриками и SHA-256 результатов](../evaluation/vlm-results-2026-09-26.json).
Сырые ответы, входные коллажи и примеры `example-full.jpg`, `example-guided.jpg`
сохранены локально в `artifacts/vlm/` и исключены из Git. Рамки примеров
оранжевые: это гипотезы модели, а не подтверждённые товары из базы.
