# Витрина — отдельный модуль поиска вин на полке

Независимый проект со своим Python API (`server/`, порт **8086**) и TypeScript-интерфейсом
(Vite, порт **5180**). Он не импортирует `apps/api`, `apps/web` или WineScan и не меняет
их маршруты. Внешние AI API и ключи не требуются.

По умолчанию интерфейс отправляет один снимок в собственный GPU-сервис. На сервере
работают ALIKED/VLAD → XFeat + LighterGlue → независимая проверка ALIKED; все модели и
признаки 2103 позиций загружаются заранее. Фото не сохраняются. Совпадения закрашиваются
полупрозрачным зелёным с названием из базы, неизвестные бутылки остаются без рамок.

**Запуск отдельного проекта:** [server/README.md](server/README.md).
**HTTP API:** [контракт](docs/server-api.md), интерактивная схема `/docs`.

Сохранены локальные режимы: `?engine=hybrid` (детали этикеток) и `?engine=baseline`
(пользовательские эталоны). Только в этих режимах снимки остаются на устройстве.
[Подготовка браузерных моделей](docs/learned-recognition.md).

## Проверка и целевые устройства

Минимальный целевой телефон — iPhone 13, основной браузер — Safari. В серверном режиме
WebGPU на телефоне не нужен. Для камеры на телефоне нужен HTTPS. Физический iPhone
пока не проверен.

Исходная браузерная версия находила 14/15 контрольных бутылок за 83–84 секунды:
[отчёт](docs/browser-release-evaluation-2026-09-24.md). Реализованный сервер через браузерный интерфейс
нашёл 14/15 за 6,9–9,3 с в Chromium и 4,6–6,5 с в WebKit на localhost:
[условия и ограничения проверки](docs/server-release-evaluation-2026-09-24.md). [Замер первой серверной цепочки SigLIP/SIFT на RTX 3090](docs/server-3090-benchmark-2026-09-24.md)
сохранён как исследовательский ориентир, а не как измерение текущего native-hybrid API.

Расширенная проверка на 17 фото выявила существенно больше пропусков:
исходный сервер нашёл 14 из 32 частично размеченных бутылок. Более сильные
режимы пока увеличивают и число найденных позиций, и число ошибок, поэтому
остаются экспериментальными. [Полный протокол, сравнения и ограничения](docs/accuracy-evaluation-2026-09-25.md).
Новая экспериментальная очередь повысила результат с 16/32 до 18/32 при одинаковых
настройках полного прохода, с медианой 18,24 с: [результаты и ограничения](docs/accuracy-disagreement-2026-09-25.md).

## Возможности

- Фото или задняя камера; поиск выбранных SKU, группы или всех уверенных совпадений.
- Детекция бутылок, распознавание вырезок из исходного кадра, плотная полка с перекрывающимися фрагментами и NMS.
- В локальном режиме — несколько наблюдений для подтверждения имени в камере; неизвестные, мелкие и неоднозначные позиции не получают уверенного названия.
- В базовом режиме: импорт/экспорт каталога, добавление своего эталона из найденной бутылки и хранение в браузере.
- Диагностика задержек и разрешения, экспорт результата без фото и эмбеддингов.
- В серверном режиме — явная кнопка снимка, без отправки видеопотока.
- Остановка камеры при уходе со страницы. Один обрабатываемый кадр за раз: изображение
  обновляется по готовности результатов, а не обещает плавное видео поверх устаревших рамок.

## Быстрый запуск базового режима

```bash
cd apps/shelf-finder
npm ci
# В отдельном Python 3.12 окружении (понадобятся PyTorch и место для моделей):
python -m pip install -r scripts/requirements.txt
python scripts/prepare.py \
  --catalog /path/to/artifacts/catalog/catalog.jsonl \
  --images /path/to/strapi/uploads \
  --weights /path/to/yolo11n.pt --limit 0
npm run dev
# Откройте http://localhost:5180/?engine=baseline
```

Если веса отсутствуют, имя `yolo11n.pt` загружается средствами Ultralytics. MobileNetV3 Small
загружается из torchvision. Генерируемые файлы лежат в `public/models`, WASM — в
`public/runtime`; они не включены в Git. Подготовка сохраняет SHA-256 моделей и каталога.
Для выбора конкретных товаров используйте `--slugs slugs.txt` (по одному slug на строку).
`--limit 0` (по умолчанию) включает все доступные эталоны датасета организаторов.
`public/models/coverage.json` перечисляет позиции без эталонных фотографий. Ограничение
каталога числом позиций применяется только при явном положительном `--limit`.

Существующие локальные данные проекта:
`/home/user/work/LCT 2026/artifacts/catalog/catalog.jsonl` и
`/home/user/work/LCT 2026/data/raw/prod-svoe-vino-strapi/prod-svoe-vino/strapi/uploads`.
Фотографии пользователя: `/home/user/work/LCT 2026/data/vitrini`.
Они не копируются в публичную сборку.

В Safari камера требует **HTTPS** (или localhost) и явного разрешения. Через обычный
HTTP по адресу компьютера доступна загрузка фото. Для телефона публикуйте эту отдельную
статическую сборку через HTTPS. Модуль не запрашивает доступ к микрофону.

```bash
npm test
npm run build                # dist/ включает подготовленные локальные модели
npm run preview              # порт 4180
npx playwright install chromium
SHELF_TEST_PHOTO=/path/to/shelf.jpg npm run test:browser
python scripts/audit.py --photos /path/to/vitrini
```

## Модели и границы первой версии

Рабочий baseline: **YOLO11n COCO (`bottle`, класс 39)** и **MobileNetV3 Small ImageNet**
(576-мерный вектор, cosine-поиск по эталонам). Это НЕ обученный детектор передних этикеток
и НЕ обученный классификатор вин. Нет обещаний точности на похожих SKU или FPS iPhone.
Настройки отказа `similarity ≥ 0.90`, `margin ≥ 0.05` — начальные, не калиброванные.
Сравнение ведётся со всем каталогом, выбор пользователя применяется только к подсветке.

При импорте проверяются версия модели, размерность, значения векторов и уникальность SKU.
Названия добавленных пользователем эталонов считаются его разметкой, а не автоматическим
распознаванием. Проверять их нужно на другой съёмочной сессии. Дубликаты дизайна/годы следует
объединять или различать осознанно в SKU; импортные вина вне каталога должны остаться неизвестными.

Следующий этап качества — разметить видимые этикетки и SKU на реальных полках, собрать
несколько условий съёмки для каждого товара и отдельные неизвестные позиции. Затем сравнить
компактный классификатор и дообученные эмбеддинги на одинаковом разделении по сессиям.
OCR для похожих кандидатов, обучение детектора этикеток и проверка нагрева на iPhone
в этот baseline не включены. Скрипт аудита не вычисляет accuracy без разметки.

## Исходный датасет организаторов

Проверены файлы `eval.zip`, `prod-svoe-vino-strapi.part1.rar`,
`prod-svoe-vino-strapi.part2.rar`, `prod-svoe-vino-strapi.part3.rar` и
`strapi_output0709.csv` в `LCT 2026/data`. В CSV 4147 строк после учёта
повторов дают **2103 уникальных SKU**. Множество slug подготовленного каталога
совпадает с CSV полностью: пропущенных и лишних SKU нет. Все 2103 позиции
имеют привязанный эталон (2092 разных файла; несколько SKU разделяют фотографию).
`eval.zip` — отдельный проверочный набор, не источник товарных эталонов.

Для диагностики полного каталога существующим серверным движком есть отдельная
команда `scripts/audit_full_catalog.py`. Она требует окружения WineScan и готовых
индексов `WINESCAN_ARTIFACTS_DIR`, работает офлайн и сохраняет **кандидатов**, а не
подтверждённые названия. Её результаты нельзя приписывать браузерному MobileNet.

Размеченные картинки для всех фото аудита:
`node scripts/render-audit.mjs /path/to/vitrini` (нужен Playwright/Chromium).
См. [отчёт проверки](docs/photo-audit-2026-09-24.md).

### Сравнение с мощной моделью вне браузера

`scripts/audit_strong.py` обрабатывает плотные рамки из `audit.py`, извлекает
вырезки исходного разрешения и ищет по двум индексам SigLIP2 so400m
(бутылка/этикетка, несколько ракурсов). Для top-10 добавляет SIFT/MAGSAC.
Требуются окружение WineScan, GPU и подготовленные индексы полного каталога.

```bash
CUDA_VISIBLE_DEVICES=2 WINESCAN_ARTIFACTS_DIR=/path/to/artifacts \
  python scripts/audit_strong.py \
  --photos /path/to/vitrini --detections artifacts/audit-full/results.json \
  --catalog /path/to/catalog.jsonl --images /path/to/strapi/uploads \
  --output artifacts/strong-audit
```

Результаты: `index.html` и 17 страниц с рамками, вырезками и эталонами;
`results.json` хранит top-10, геометрические свидетельства и ответы компактной
модели на тех же рамках. `reviewedId` остаётся пустым: предсказания сильной
модели не заменяют ручную разметку. Число совпавших top-1 измеряет согласие
моделей, а не точность. Сравнение компактной модели здесь использует её
Python/ONNX-прогон, а не выполнение Safari. Детектор остаётся прежним;
пропущенные им бутылки этот эксперимент не оценивает.

После завершения запустите `python scripts/summarize_strong.py artifacts/strong-audit`: он создаёт `report.md` и `review-template.csv`. Для ручной разметки копируйте шаблон в `review.csv`; шаблон перезаписывается при повторном запуске, отдельный файл разметки не затрагивается.

### Визуальная сверка результатов

Сверка всех 939 областей выполнена Codex по изображениям; это не независимая
экспертная разметка. См. [результат проверки](docs/visual-review-2026-09-24.md)
и [явные вердикты](docs/visual-review-notes-2026-09-24.json).
Наблюдения фиксируются отдельно от предсказаний моделей:

```bash
node scripts/review-sheets.mjs artifacts/strong-audit
# Только для того же results.json (проверяется SHA-256):
cp docs/visual-review-notes-2026-09-24.json artifacts/strong-audit/visual-review-notes.json
python scripts/finalize_visual_review.py artifacts/strong-audit
```

`visual-review/index.html` показывает цветные рамки и вердикты, `review.csv`
и `review.json` содержат запись для каждой области. Зелёный означает совпадение
названия/дизайна; красный — отклонённый первый кандидат; жёлтый — неопределённость;
серый — ошибочную область. Это не доказательство наличия/отсутствия всех SKU.
`visual_product_id` не следует автоматически переносить в обучающие метки:
точный SKU, год и крепость не подтверждены, `reviewed_id` остаётся пустым.
