# WineScan Web — мобильный интерфейс сканера вин

Веб-интерфейс для кейса РСХБ «Сканер российских вин на платформе „Своё вино“» (ЛЦТ 2026).
Mobile-first, открывается в мобильном браузере и рассчитан на встраивание в каталог портала.
Стек: Nuxt 4 (SSR), TypeScript, собственный CSS без UI-китов.

Экраны:

| Путь | Что делает |
| --- | --- |
| `/` | Сканер: «Сфотографировать этикетку» (`<input type="file" accept="image/*" capture="environment">`) и «Загрузить из галереи», рамка-подсказка, превью, загрузка, ошибки сети. `found` открывает карточку, `not_found` показывает экран «Этого вина нет в каталоге» с честным пояснением, похожими этикетками (top-5) и переходом к сомелье |
| `/wine/[slug]` | Карточка в стиле портала: фото эталона, название, винодельня, регион, сорт, категория и цвет, сладость и игристость по-русски, год, описание; «Аналоги других виноделен» с причинами; «Хочу попробовать»; «Подобрать вино к блюду». После скана: бейдж уверенности и раскрывающиеся «Технические детали» (скоры top-5, отрыв, тайминги, OCR) |
| `/sommelier` | «Цифровой сомелье»: пошаговые вопросы-кнопки (блюдо обязательно, остальное с вариантом «Не важно»), 3 вина с причинами, дисклеймер из ответа, «Другие варианты» (повторный запрос с `exclude_slugs`). Блюдо можно передать ссылкой: `/sommelier?dish=fish` |
| `/history` | История сканов и список «Хочу попробовать» (localStorage), удаление и очистка |

Нижняя навигация (Сканер / Сомелье / История) и подвал 18+ есть на всех страницах.

## Установка и запуск

Нужен Node.js 22+ (проверено на 22.23).

```bash
cd web
npm ci
```

**Демо без Python-сервиса** (данные из `web/mocks/`):

```bash
NUXT_PUBLIC_MOCK=1 npm run dev             # http://localhost:3000
```

На экране сканера в режиме моков есть переключатель «вино найдено / нет в каталоге»,
а в шапке — метка «демо-данные».

**С сервисом WineScan** (FastAPI, порт 8080: `uvicorn winescan.service.app:app --port 8080`):

```bash
NUXT_API_BASE=http://127.0.0.1:8080 npm run dev
```

**Прод-сборка:**

```bash
npm run build
PORT=3000 NUXT_API_BASE=http://127.0.0.1:8080 node .output/server/index.mjs
# или демо на тех же файлах сборки:
PORT=3000 NUXT_PUBLIC_MOCK=1 node .output/server/index.mjs
```

Чтобы открыть с телефона в той же сети: `npm run dev -- --host` (или `HOST=0.0.0.0` для прод-сервера),
затем `http://<ip-компьютера>:3000`. Для `<input capture>` HTTPS не нужен — камера открывается
системным диалогом выбора файла.

**Проверки:**

```bash
npm run typecheck   # vue-tsc через nuxi typecheck
npm run build
```

## Переменные окружения

Все читаются при запуске сервера, пересборка не нужна.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `NUXT_API_BASE` | `http://127.0.0.1:8080` | Адрес FastAPI-сервиса WineScan; `/api/**` проксируется на `${NUXT_API_BASE}/**` |
| `NUXT_PUBLIC_MOCK` | пусто | `1` включает режим моков: API отвечает фикстурами из `web/mocks/` |
| `NUXT_MOCK_UPLOADS_DIR` | `../data/raw/prod-svoe-vino-strapi/prod-svoe-vino/strapi/uploads` (от текущей папки) | Папка с эталонными фото для режима моков. Если фото нет, показывается заглушка-силуэт |
| `PORT`, `HOST` | `3000`, все интерфейсы | Порт и адрес Nitro-сервера |

## Как устроено

```
web/
├── nuxt.config.ts            # runtimeConfig (apiBase, mock), head, serverAssets для фикстур
├── server/
│   ├── api/[...path].ts      # /api/** → прокси на NUXT_API_BASE или моки
│   └── utils/mock-api.ts     # мок-реализация тех же эндпоинтов
├── shared/
│   ├── types/api.ts          # типы ответов API (общие для app и server)
│   └── utils/mock.ts         # разбор флага NUXT_PUBLIC_MOCK
├── app/
│   ├── assets/css/main.css   # токены палитры портала, кнопки, чипы, сообщения
│   ├── layouts/default.vue   # шапка, main, подвал 18+, нижняя навигация
│   ├── pages/                # index, wine/[slug], sommelier, history
│   ├── components/           # AppIcon, AppFooter, BottomNav, WineImage, WineTile,
│   │                         # ConfidenceBadge, TechDetails
│   ├── composables/          # useApi (клиент API), useStoredLists (localStorage)
│   └── utils/                # подписи вина, ошибки, подготовка фото, контекст скана
├── mocks/                    # фикстуры (JSON)
└── scripts/generate_mocks.py # генерация фикстур из каталога
```

**Прокси API.** Все запросы фронта идут на относительный `/api/...`, поэтому CORS не нужен ни в dev, ни в
проде. Вместо `routeRules.proxy` используется серверный маршрут `server/api/[...path].ts`
(`proxyRequest` из h3): `routeRules` вычисляются при сборке, а маршрут читает `NUXT_API_BASE` при запуске.
Если бэкенд недоступен, маршрут отвечает `502 {"detail": "сервис распознавания недоступен"}`, и интерфейс
показывает понятную ошибку.

**Скан.** Отправляется всё фото целиком, рамка на экране — только подсказка. Если кадр больше 2048 px
по длинной стороне или файл больше 3 МБ, браузер уменьшает его до 2048 px (JPEG 0.92) с учётом
EXIF-поворота. Сервис всё равно уменьшает кадр до 1600 px, а загрузка по мобильной сети идёт в разы быстрее.
Если браузер не декодирует формат (например, HEIC), файл уходит как есть. Данные уверенности сохраняются в
`sessionStorage` и показываются на карточке только при переходе прямо со скана (`?from=scan`).

**Бейдж уверенности.** Сервис уже решил, что вино найдено. Бейдж по отрыву `margin_top1_top2` подсказывает:
при отрыве ≥ 0.03 уверенность «высокая», иначе «средняя» — с просьбой сверить название и ссылкой на
второго кандидата. Порог 0.03 — допущение интерфейса: в бэкенде `min_margin` не задан.

**Хранилище.** История (до 50 сканов) и «Хочу попробовать» (до 100 вин) лежат в `localStorage` этого
браузера. Они читаются после монтирования, чтобы SSR-разметка совпадала с гидратацией. Все обращения
обёрнуты в `try/catch`: в приватном режиме списки живут до перезагрузки.

### Режим моков

Фикстуры сгенерированы из реальных данных, а не выдуманы:

- `scan_found.json`, `scan_not_found.json` — сохранённые ответы `/v1/scan` сервиса
  (`artifacts/eval/participant_public/scan_02eef911.json` и `scan_019c68d0.json`);
- `wines.json` — 399 реальных карточек из `artifacts/catalog/catalog.jsonl`, на которые есть ссылки из фикстур;
- `analogs.json` — вывод `AnalogFinder` из `src/winescan/product/analogs.py` для 31 вина:
  найденного, кандидатов top-5 и первых подборок сомелье;
- `suggest.json` — вывод `Sommelier` из `src/winescan/product/sommelier.py` для всех сочетаний
  «блюдо × цвет × стиль», по 9 вин на ключ;
- `questions.json` — `questions()` из того же модуля.

Перегенерировать (CPU, без сервиса и моделей; нужны `artifacts/`):

```bash
.venv/bin/python web/scripts/generate_mocks.py   # из корня репозитория
```

Упрощения мок-сервера:

- в моках только 399 карточек;
- аналоги вин вне `analogs.json` считаются упрощённой JS-копией правил без TF-IDF по описанию;
- сладость в сомелье фильтруется по списку ключа, поэтому редкие сочетания могут дать меньше трёх вин;
- регион игнорируется;
- у скана искусственная задержка 700 мс.

## Стиль портала: что взято и что предположено

Источник — HTML и CSS страниц https://vino-svoe.ru/wines и https://vino-svoe.ru/wines/cantiani-cabernet-sauvignon,
загружены 15.09.2026: `/_nuxt/entry.CcAo-ZK4.css`, `UiButton.BumBsR97.css`, `UiChip.cl654D6F.css`,
`WineItem.D1J_HiaW.css`. Код и файлы портала не копировались, использованы только значения токенов.

**Взято с портала:**

- Фон страницы `#fefdfa`, фон карточки вина `#fdf9ed`, плашка рейтинга `#f8ecc9` (у нас — плашка средней уверенности).
- Основной текст `#2c2a28`; второстепенный `#857e79` и `#aea9a5`.
- Акцент — основная кнопка `#8f3d42`, hover `#ab494f`, active `#723135`. Вторичная кнопка `#f9f1f1`,
  hover `#edd4d6`, active `#e0b8ba`. Коричневый `#7b3528`. Рамка чипа `#d7d4d2`.
- Шрифты: заголовки — Playfair Display, начертание 500, межстрочный 125%; текст — `system-ui, -apple-system, sans-serif`.
- Скругления: большая кнопка 56 px / 16 px, средняя 44 px / 12 px, чип 16 px (высота 32 px), карточка 16 и 32 px, «таблетки» 999 px.
- Кнопка при нажатии: `scale(.98)`.
- Структура карточки вина (мобильная версия):
  - название;
  - производитель акцентным цветом;
  - строки «Регион», «Сорт винограда», «Категория и цвет» с круглым значком 44 px;
  - градиент цвета вина (`#A51B3A → #741D30` для красного);
  - описание вкуса;
  - лента «Похожие вина» из карточек на кремовом фоне.
- Подвал «Чрезмерное употребление алкоголя вредит вашему здоровью» со знаком 18+.

**Предположено или своё:**

- Градиенты для белого, розового и оранжевого вина — в манере красного.
- Playfair Display не встраивается: файл шрифта принадлежит порталу, а лицензия OFL не входит в разрешённый список.
  Если шрифта нет в системе, используется Georgia или системный serif.
- Иконки нарисованы заново, линейные 24 px. Портал использует набор lucide, мы его не подключали.
- Знак 18+ — текстовый бейдж, изображение портала не копировалось. Логотип «Своё вино» не используется,
  название есть только в подписи модуля.
- Нижняя навигация, видоискатель, бейдж уверенности, «Технические детали», экран вопросов сомелье — своя
  разработка в палитре портала.
- Боковой отступ 20 px, на экранах уже 360 px — 16 px. У портала на мобильных 24 px.
- Не показываются блоки, которых нет в API: «Народный рейтинг», крепость, температура подачи, картинки блюд,
  цены, Роскачество.

## Юридические ограничения (38-ФЗ)

- Тон информационный, без призывов.
- Нет слов «купить», цен, акций и изображений людей.
- Причины подбора — фактические совпадения полей каталога.
- Подвал 18+ и предупреждение о вреде алкоголя есть на каждой странице, включая страницу ошибки.
- «Хочу попробовать» — личная заметка в браузере, а не корзина.

## Известные ограничения

- Проверки автоматические:
  - `npm run build` и `npm run typecheck`;
  - SSR-рендер всех страниц через curl;
  - API в режиме моков;
  - прокси на тестовый эхо-сервер.
  
  В реальном мобильном браузере камера, localStorage и гидратация не проверялись.
- `nuxi typecheck` печатает предупреждение `Resolve plugin path failed: vue-router/volar/sfc-route-blocks`.
  Это несовместимость плагина Volar в vue-router 4.6, на результат проверки не влияет.
- Лицензии. Прямые зависимости — `nuxt`, `vue`, `vue-router`, `@types/node`, `vue-tsc` (MIT) и
  `typescript` (Apache-2.0). Транзитивно через Nuxt и Vite приходят:
  - `lightningcss` (MPL-2.0, инструмент сборки CSS);
  - `caniuse-lite` (CC-BY-4.0, данные о браузерах);
  - пакеты с BlueOak-1.0.0 и CC0-1.0;
  - `node-forge` (BSD-3-Clause OR GPL-2.0).
  
  В клиентский бандл они не попадают.
- Бейдж уверенности использует порог отрыва 0.03 — его стоит откалибровать на валидации.
- Тёмной темы нет, у портала она тоже не найдена.
- Кнопка «Подобрать вино к блюду» на карточке не передаёт в сомелье цвет текущего вина.
- История и «Хочу попробовать» не синхронизируются между устройствами.
