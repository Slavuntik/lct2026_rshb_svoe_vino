## БЛОКЕРЫ (все — волны 3; демо в mock-режиме они не роняют, интеграцию — да)

1. **Форма `Candidate.meta` несовместима между моком и реальным RAG — при `RAG_PROVIDER=real`
   падают карточка вина и весь /taste.**
   `apps/api/app/routers/wines.py:29` читает `candidate.meta["source"]`/`["derived"]`;
   `apps/api/app/routers/taste.py:53` — `candidate.meta["derived"]`. Реальный `get_by_id`
   (`packages/rag/rag/base.py:139-149`) отдаёт meta=payload, в котором НЕТ ключей source/derived —
   payload собирается в `packages/rag/rag/ingest.py:72-87` как плоский набор (name, winery_name,
   region_name, image_url, filters{...}, sensory). Итог: KeyError → 500 на каждом `GET /wines/{id}`
   и каждом `POST /taste/swipes`. Сцены 1 и 4 умирают при переключении; сцены 2/3 выживают
   (chat берёт только text/url, analogs — name/winery_name/region_name, они в payload есть).
   **Фикс:** зафиксировать форму meta в contracts/rag-interface.md по kind (для wine: обязательные
   `meta["source"]` и `meta["derived"]` как в catalog/wines/<slug>.json, плюс верхнеуровневые
   name/winery_name/region_name/color/image_url); A добавляет source/derived в payload-сайдкар wines
   (catalog уже читается при ingest — правка в одном месте); B не меняется. Приёмка — smoke-тест из
   топ-3 №1.

2. **`candidates_for_taste`: три несовпадающие версии сигнатуры.**
   Контракт `contracts/rag-interface.md:50` — `candidates_for_taste(self, exclude_ids: list[str],
   limit=20)`; реальный `packages/rag/rag/base.py:156` — совпадает; мок
   `apps/api/app/rag/mock.py:206` — `*, exclude_ids: set[str] | None = None` (keyword-only, set);
   зеркало-Protocol `apps/api/app/rag/interface.py:48-78` метода не содержит вовсе (застряло на
   v0.2.1), а `apps/api/app/routers/taste.py:123-124` зовёт его через `getattr(..., None)` c
   деградацией в пустую колоду. Сегодня работает по случайности (kwargs); первый же вызов по
   контрактной позиционной сигнатуре против мока — TypeError, а опечатка в имени метода будет
   молча отдавать пустую колоду вместо ошибки.
   **Фикс (зона B):** догнать interface.py до v0.2.4, привести сигнатуру мока к контракту, убрать
   getattr (метод теперь обязателен), добавить тест сигнатурной сверки Protocol↔mock
   (`inspect.signature`), по образцу его же теста на build_messages.

3. **Экран паспорта вкуса игнорирует GET /taste/candidates — колода зашита сид-листом мок-вин.**

5. **Compose задаёт переменную, которую никто не читает; реальный RAG ждёт другие имена.**

6. **Индексу нечем доехать до VPS: артефакты ingest вне git и вне deploy.**

## Риски волны 3 (не блокируют, но держим в голове)

1. **Refusal-гарантия не переживёт реальный ретривер.** «Пустая выдача ⇒ refusal» у мока держится
   на пороге `_SEARCH_MIN_SCORE=0.08` (`apps/api/app/rag/mock.py:31`) — у реального `search()`
   порога нет вообще: dense-ветка Qdrant всегда возвращает top-k соседей, на любую бессмыслицу
   выдача непуста → refusal не сработает, и mock-LLM (который цитирует всё, что дали) на мусорный
   вопрос выдаст уверенную чушь с цитатами. Сцена «честный отказ» демо на связке real-RAG+mock-LLM
   невоспроизводима. Решить: отсечка после реранка у A (логит-порог, откалибровать на 10 мусорных
   вопросах, добавленных в голд-сет) — с оговоркой, что score по v0.2.4 несравним между вызовами,
   так что порог живёт внутри search(), не у B.
2. **refusal.reason: три конвенции.** B шлёт человеческий текст (`app/chat/service.py:30-32`),
   клиент сравнивает с кодом (`ChatScreen.tsx:98` — `reason === "llm_unavailable"` никогда не
   совпадёт), MSW шлёт код `"no_results"` (`src/mocks/handlers.ts:242`). UI не ломается (падает в
   дефолтный честный текст), но серверная формулировка теряется. Выбрать конвенцию (лучше коды +
   i18n у клиента) и записать в openapi.
3. **SSE-стрим фиктивный: ответ буферизуется целиком** (`app/chat/service.py`, честно
   задокументировано). TTFB сцены 2 на реальном DeepSeek = вся генерация (+0.7-0.8 с реранк) —
   5–10 секунд молчания перед «стримом». Для демо решить: либо live-прокси чанков (SSE-парсер C
   дробление уже умеет), либо принять и отполировать индикатор «сомелье думает».
4. **Свободнотекстовые фильтры чата против нормализованных payload-значений.**
   `ChatScreen.tsx:181-207` — color/sugar/region это текстовые инпуты; реальный фильтр ждёт
   «красное»/slug региона «kuban» (`packages/rag/rag/filtering.py`, payload). Введённая руками
   «Кубань» даст пустую выдачу → refusal на ровном месте. Селекты со словарными значениями
   (ref/ уже содержит справочники) или убрать фильтры из UI до 10.09.
5. **hit@8=0.87 измерен с роутингом коллекций по типу вопроса в eval** (`rag/eval.py`), а прод
   `/chat` роутинга и извлечения Filters не делает (`run_chat` — всегда
   ("wines","knowledge") + фильтры из UI). Продовый retrieval заведомо слабее измеренного
   (pick 0.72 без фильтров против 1.00 с ними — диагностика A). Задача «/chat извлекает Filters из
   реплики» (v0.2.4 закрепил ответственность за вызывающим) — не назначена никому. Назначить B
   в волну 3 (дёшево: rapidfuzz по справочникам цветов/регионов/сортов из ref/).
6. **Цитаты в чате не кликабельны** (`ChatScreen.tsx:264-267`): url есть в данных, ссылки нет,
   wine_id не ведёт на карточку. «Цитаты-ссылки на первоисточник» — прямое обещание архитектуры и
   киллер-довод демо («не выдумка — вот источник»); сейчас это просто бейджи. Дёшево и сильно
   поднимает сцену 2.
7. **/consents принимает любые строки скоупов** (`app/routers/consents.py:46-50` пишет в ledger
   что дали; openapi:113 сам не ограничивает items enum'ом). Мусор в журнале согласий — юр-грязь.
   Enum в контракт + валидация у B.
8. **Дубли логики low_confidence:** B считает своим порогом 0.6 (`config.py:42-44`,
   `scan.py:44`), реальный A кладёт готовый `meta["low_confidence"]` с порогом 0.75
   (`rag/resolve.py:45`). При интеграции победит B-шный 0.6 на скорах другой природы — пороги
   разъедутся молча. Выбрать один источник (естественнее — meta от A).
9. **tokens.css живёт в трёх копиях** (contracts/ → src/styles/ → public/legal/) — уже отмечено D;
   при следующей правке токенов прогнать diff всех трёх или генерить копию на build.
10. **Версии текстов согласий по-прежнему не архивируются** (риск 8 ревью 01, D зафиксировал
    сам): consent_version="2026-08-v1" указывает на файл, который будет перезаписан следующей
    редакцией. До первой правки юриста завести `public/legal/consents/<version>.html`.
