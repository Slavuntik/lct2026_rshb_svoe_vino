## БЛОКЕРЫ

1. **consent_ledger стирается вместе с пользователем — теряем доказуемость.**
   `contracts/schema.sql:16` — `user_id uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE`.
   Схема сама говорит (`schema.sql:10`): soft-delete, «затем строка удаляется» — в момент фоновой
   очистки CASCADE снесёт весь журнал согласий, включая строку отзыва. Прямое противоречие с
   `openapi.yaml:233` («consent-ledger хранит факт отзыва») и с принципом «append-only…
   доказуемость» (`schema.sql:13`). Жалоба удалённого пользователя в РКН — и доказать нечем.
   **Фикс:** убрать FK (плоский `user_id uuid NOT NULL`, индекс оставить); в комментарии:
   строки ledger переживают удаление users; фоновая очистка ledger не трогает.

2. **Клиентским событиям некуда лететь: POST /events нет в контракте.**
   `contracts/events.md:5` — «пишутся в Postgres events»; `agents/B-api.md:27` — «POST-хук пишет
   в events…, неизвестное имя — 400»; `agents/C-client.md:36` — клиент шлёт события. А в
   `contracts/openapi.yaml` пути `/events` нет. B обязан либо нарушить заморозку, либо провалить
   собственный DoD «openapi-схема совпадает с контрактом» (`agents/B-api.md:42`). Половина
   словаря (app_open, wine_card_viewed, source_link_clicked, scan_started, age_gate_failed) —
   чисто клиентские, серверными хуками их не собрать.
   **Фикс:** добавить в openapi `POST /events {name, props}` → 204, неизвестное имя → 400
   `invalid_event_name`; auth опциональна (age_gate_failed и app_open случаются до логина).
   Тем же патчем решить транспорт для `feedback` (`schema.sql:80` таблица есть, эндпоинта нет,
   а `events.md` chat_feedback несёт только verdict без message_id): `POST /feedback
   {message_id, verdict}` или расширить props события.

3. **Сцена 3 «люблю Просекко» не имеет пути через API.**
   В `contracts/openapi.yaml` нет ни analog-эндпоинта, ни слова в описании `/chat` (стр. 157–178)
   о том, как реплика с импортным стилем превращается в вызов
   `analog_for_style(style_slug)` (`contracts/rag-interface.md:38-40`). Никто не резолвит текст
   «Просекко» → slug `prosecco`; событие `analog_requested {style_slug}` (`events.md:24`)
   некому заполнить. Киллер-фича демо держится на неписаном соглашении.
   **Фикс:** (а) в `rag-interface.md` добавить `resolve_style(text: str) -> str | None`
   (fuzzy по именам/синонимам 146 стилей из `ref/reference_styles.yaml`); (б) в описании
   `/chat` зафиксировать: при распознанном стиле — путь analog_for_style, ответ теми же
   SSE-событиями с цитатами, сервер пишет `analog_requested`. Данные готовы: матчер стилей
   покрывает 95% каталога, вектора не нужны.

4. **Сцена 2 в плане обещает бюджет, которого нет в данных.**
   План (mvp-plan, раздел 0): «что взять к устрицам до 1500 ₽». Проверено по живому каталогу:
   ни одного ценового поля ни в `build/index.jsonl`, ни в `catalog/wines/*` (`derived.price_tier`
   — всюду null). `openapi.yaml:178` `budget_rub_max` — мёртвый фильтр: в `Filters`
   (`rag-interface.md:15-20`) бюджета нет, ретриверу его некуда деть. На демо реплика «до
   1500 ₽» гарантирует либо отказ, либо выдумку цены — обе против правил.
   **Фикс:** убрать `budget_rub_max` из `/chat` (или пометить «не поддерживается, игнорируется»);
   из демо-скрипта сцены 2 убрать бюджет; F генерирует вопросы пака только из полей, которые
   в паке реально есть (гастропары, цвет, сахар — есть; цены — нет).

5. **Citation-события не сопоставимы с маркерами [n] в тексте.**
   `openapi.yaml:161` — citation несёт `wine_id|chunk_id, url, quote`, но не порядковый номер;
   при этом B собирает промпт «каждое утверждение с [n]» (`agents/B-api.md:24-25`). Клиент
   получает токены с «[1]», «[2]» и кучу цитат без индексов — сопоставить нечем, сцена 2
   рендерится вслепую.
   **Фикс:** добавить обязательное поле `n` в citation-событие; слать citation до первого
   токена с его маркером (или все citation до done — но с номерами).

6. **rag-interface противоречит сам себе: payload беднее, чем нужен интерфейсу.**
   `contracts/rag-interface.md:48` — «payload повторяет filters-блок vines». Но filters-блок
   index.jsonl — это color/sugar/region/winery/grapes/food/rating/abv (проверено по данным);
   там нет ни `stillness` (нужен `Filters.stillness`, `rag-interface.md:20`, и тесту A
   «analog_for_style('prosecco') возвращает только игристые», `agents/A-rag.md:32`),
   ни `styles` (нужны analog_for_style: «вина с этим стилем в derived», `rag-interface.md:40`).
   Агент A либо нарушит контракт, либо не сможет его выполнить.
   **Фикс:** одна строка в контракте: payload = filters-блок + `stillness` + `styles`
   (оба лежат в записи index.jsonl / derived, ingest их уже видит).

7. **Сцену 1 на iPhone никто не реализует: у C — заглушка, у вехи — e2e.**
   `agents/C-client.md:26-27` — «каркас плагина (интерфейс TS + заглушка Swift-файла Vision
   с TODO)». Веха В2 10.09 (mvp-plan, календарь) — «скан → карточка e2e на iPhone против
   staging», DoD C — «скан → карточка ≤ 3 c на iPhone к 10.09». Заглушка с TODO этого не даст,
   а писать Swift на publish-Mac 05–10.09 некому и некогда — работа осталась без владельца.
   **Фикс:** переформулировать C: полный Swift-код Vision (VNRecognizeTextRequest,
   `recognitionLanguages` с кириллицей, ~50 строк) пишется сейчас и целиком — вслепую, но
   код-ревью вместо сборки; publish-Mac только компилирует. Fallback «ввести текст» остаётся
   равноправным путём.

8. **Словарь кодов ошибок пуст — три команды изобретут три разных.**
   `openapi.yaml:2` задаёт формат `{"error":{code,message}}`, но именует только
   `age_restricted` (:46) и `consent_required` (:136). B велено «включая коды ошибок»
   (`agents/B-api.md:19`), C рендерит ошибки, F пишет e2e как исполняемую спецификацию по
   контрактам (`agents/F-qa-demo.md:24`) — каждый придумает своё, интеграция волны 2 разойдётся
   по построению. Нет даже 404 для `/wines/{wine_id}` — а демо ходит по deep-link'ам.
   **Фикс:** enum в components + привязка к путям: `invalid_credentials`, `unauthorized`,
   `not_found`, `validation_error`, `rate_limited`, `age_restricted`, `consent_required`,
   `profiling_required` (для /taste/swipes без скоупа), `invalid_event_name`; для SSE-refusal —
   словарь reason: `no_results`, `llm_unavailable`.

## Риски (держим в голове)

1. **Перфоманс мерим не там, где показываем.** p95 ≤ 300 мс и «скан ≤ 3 с» замеряются «на этой
   машине» (Apple Silicon), а прод — Contabo VPS на CPU. bge-reranker-v2-m3 по top-50 на CPU —
   потенциально секунды, не миллисекунды. План Б: реранк top-20 или dense+BM25 без реранкера в
   прод-пути (это допускает сам контракт — «замерить оба»); обязательный повторный замер на
   staging до заморозки 10.09.
2. **Гостевой режим не решён.** openapi: «Auth: Bearer JWT» глобально, а лендинг обещает
   «Попробовать в браузере» за один тап и «первый скан» как конверсию. Стена
   регистрации (email+пароль+дата рождения) перед первым сканом убьёт этот путь; `scans.user_id`
   nullable намекает, что аноним задумывался. Решить явно: /scan/resolve и /wines — без auth
   (18+ гейт интерстициалом), /chat, /taste — с auth. Это же упрощает план Б демо.
3. **hit@8 ≥ 0.85 рискует быть цикличной метрикой.** Голд-сет генерируется из того же каталога,
   по которому ищем — 0.85 достижимо почти автоматически, и метрика перестаёт что-либо
   гарантировать. Защита — ручная проверка честности вопросов (в брифе A есть) и типы
   analog/pairing, где ответ не совпадает с формулировкой. Если модели не скачаются —
   BM25-only просядет именно на analog/pairing; сцену 3 это не топит (матчер стилей без векторов).
4. **Lighthouse ≥ 90 у React-SPA лендинга — на грани.** Cormorant + два Plex, фото бутылок,
   общий бандл с /app. План Б: route-splitting (лендинг не тянет чанки /app), font-display:
   swap + subset, prerender `/` в статику при билде; замер не только локально, но и со staging.
5. **/scan/ocr нереализуем как записан.** Серверный OCR-движок не назван ни в одном брифе,
   в зависимостях B его нет. Предлагаю вычеркнуть (см. ниже) — вернуть 501; веб-фолбэк = текст.
   Если оставляем — `explicit_consent` транзиентный boolean нигде не фиксируется: согласие на
   обработку фото недоказуемо, нужна строка в ledger.
6. **Зоны C и D пересекаются в apps/web.** D пишет в `apps/web/src/landing/` — это зона C;
   «конфликтов не может быть по построению» здесь ломается. Секвенировать: C закладывает
   `src/landing/` в каркасе и с волны 2 туда не пишет.
7. **Поведенческая аналитика не привязана к скоупу согласия.** Enum скоупов —
   base/profiling/geo/marketing (`openapi.yaml:40`); под какой из них падают events —
   не сказано (план относит их к отдельному согласию). Вопрос юристу до написания текстов D;
   AppMetrica в демо-сборке (EU-контур, тестовые аккаунты) выключить env-флагом — незачем
   светить SDK на показе.
8. **Версии текстов согласий нигде не архивируются.** consent_version ссылается на текст,
   а D кладёт один consent.html без версий. Для доказуемости — `public/legal/consents/<version>.html`
   или git-тег на каждую версию; иначе ledger ссылается в пустоту.
9. **Картинки карточек — хотлинк на vino-svoe.ru.** Сцена 1 зависит от чужого хоста и сети
   на площадке. Демо-пак должен прекэшировать ассеты пака локально (у F уже есть HEAD-проверка —
   добавить скачивание в pack).
10. **JWT истекает посреди показа.** TokenPair без refresh; 15-минутная сцена + подготовка =
    401 в кадре. Для демо-контура expires_in ставить часами; refresh — после окна.
11. **SSE с Bearer невозможен через EventSource.** Клиент обязан парсить fetch-стримом
    (тест C уже намекает); одной строкой зафиксировать в брифе C, чтобы не было «почему 401».
