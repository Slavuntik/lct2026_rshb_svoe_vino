# Продакт · Стратегия победы и «плюшки» после сканирования (Вячеслав, 22.09)

**Зона записи:** `docs/product/strategy.md`, `docs/product/post-scan.md`, `reports/product-strategy.md`.

Стратегия (дословно от Вячеслава): 1) даём 99.99% достижимого с CPU + наш приватный GPU-сервер;
2) декомпозируем финансовую разницу (4 ядра против 2× RTX 3090); 3) предлагаем варианты комбинаций,
включая Mac; 4) после того как метрика взята — «плюшки»: что подать к блюду, подбор по вкусу.
Главное — TCO решения при самой высокой точности.

## Задачи

1. `docs/product/strategy.md` — история для жюри на этой стратегии: потолок каталога 97–98%
   (`reports/cpu-path-study.md` §«потолок», `reports/label-crop-study.md`), где мы относительно него
   на каждом железе (цифры только измеренные, см. `qa/scan-eval-runs/real-photos-stand/README.md`,
   `contracts/image-scan.md` v0.4.13 п.6), таблица комбинаций железа (данные TCO берёт архитектор —
   `docs/strategy/tco.md`, до его отчёта оставь ссылку-заглушку), формулировка «X% от достижимого».
2. `docs/product/post-scan.md` — сценарий после распознавания на том, что УЖЕ есть в API и
   интерфейсе: карточка → «похожие» и «аналоги» (`/v1/analogs`, `similar`), сомелье-чат
   (`/v1/chat`, RAG по базе знаний «Своё Вино», LLM GigaChat при ключе — сейчас на стенде mock),
   вкусовой профиль (`/v1/taste/*`, свайпы). Проверь по `contracts/openapi.yaml` и `apps/web`, что
   реально работает, что требует ключа GigaChat, чего нет (гастрономические пары «что подать к
   блюду» — есть ли в базе знаний/описаниях каталога поле или это новая задача backend). Итог —
   список «плюшек» с оценкой: есть / нужен ключ / нужна задача (кому, сколько).
3. В `docs/product/slides-7-11.md` и сценарий видео добавь блок стратегии и TCO (после отчёта архитектора).
