## Что должно лежать в ml-handoff/ (всё самодостаточно, читается без нас)

1. **README.md** — постановка: цель ≥90% top-1 (flat) на полевых фото кейса;
   текущий zero-shot: raw top-1 69.4% / top-5 89.9% (синтетика, 1982 позиции,
   qa/scan-eval-runs/case-20260917-final-b7); ranking — узкое место, retrieval
   уже сильный. Что можно и что нельзя (веса и датасет кейса НЕ в git; всё
   локально; лицензии моделей свободны по ТЗ).
2. **DATA.md** — карта данных: case-data/ (дамп uploads, slug_refs.json c usable
   и качеством эталонов, families.json — 165 near-dup семей), какие сиды каких
   синтетических наборов уже «сожжены» (build 0, delta 9973, baseline 20260917,
   B4 314159) и почему полевой датасет по приезду ПЕРВЫМ ДЕЛОМ замораживается в
   dev/holdout ДО любого тюнинга (наш SHA-сплит из qa/scan_eval.py — как
   переиспользовать).
3. **RECIPE.md** — рецепт по arXiv:2404.08820 и нашему опыту: metric fine-tune
   SigLIP2 vision-башни (или адаптер поверх) на триплетах; позитивы — синтетические
   ракурсы эталона (наш cv/augment.py, ≥20 видов, детерминированный); hard
   negatives — ЧУЖИЕ члены той же near-dup семьи (families.json — готовый майнинг)
   + ближайшие соседи из индекса; лестница ДО обучения (порядок из acceptance.md
   §9: интейк-гигиена → верификатор/tie-break → фотометрия → re-augmentation →
   large-чекпойнт → fine-tune ПОСЛЕДНИМ); критерий остановки и риск переобучения
   на студийный домен.
4. **EVAL.md** — обвязка приёмки: как прогнать наш eval (scan_eval.py против API
   или CLI cv search), какие цифры сдавать (raw top-1/top-5, F1, срезы near-dup/
   fallback, p50/p95 на MPS и CPU), eval-gate: новая модель не публикуется, если
   метрики просели (наш принцип версий индекса); как собрать индекс новой моделью
   (cv build-index, версия в манифест).
5. **scripts/**: `make_triplets.py` — генератор триплетов из slug_refs+families
   (эталон→якорь, свои ракурсы→позитивы, семья/соседи→негативы; JSONL-манифест,
   БЕЗ копирования фото — только пути); `eval_new_encoder.md` — пошаговая инструкция
   замены CV_MODEL/чекпойнта и замера. Скрипты — работающие, с тестом на фикстурах
   в qa/tests/ НЕ лезь — тест положи в ml-handoff/tests/ + запуск через venv
   packages/cv.
6. **BASELINES.md** — сводная таблица ВСЕХ наших замеров с указанием коммитов и
   отчётов (94.7% покрытие, 99.5% usable, self-match 75.2/88.2, e2e 41.6% гейт,
   послойные срезы, латентности, размеры индекса).
