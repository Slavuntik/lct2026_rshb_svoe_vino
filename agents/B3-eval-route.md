Его поведение:

- Дефолтный эндпоинт: `POST http://127.0.0.1:8080/v1/eval/predict` (URL передаётся
  параметром `--endpoint`, но дефолт должен работать «из коробки»).

- Без auth, последовательно, без ретраев. predictions.jsonl уходит организатору.

## Задачи

1. **Роут `POST /v1/eval/predict`** в apps/api: алиас плоского режима скана — та же
   несгораемая семантика, что `/v1/scan/photo?flat=1` (ВСЕГДА `{"slug":"..."}` лучшим
   кандидатом, любой сбой → валидный JSON со slug'ом-лучшей-догадкой, без auth, HTTP 200).
   Реализация — общий обработчик с flat (не копипаста). Поле `image` и любое другое
   файловое поле (наш приём «первое файловое поле» сохраняется).
2. **Тесты** (pytest, к существующим 171): роут отвечает 200 + ровно `{"slug": str}`
   на mock-провайдере; на битом файле — тоже 200 + slug; auth не требуется; поле `image`
   принимается; ответ — одна строка JSON без лишних полей.
3. **README**: раздел «Прогон скрипта кейсодержателя» — как поднять API на :8080
   (`uvicorn ... --port 8080`), команда запуска их скрипта, ожидание predictions.jsonl.
4. **Генеральная репетиция** (после сигнала оркестратора, что боевой индекс G3 готов):
   поднять API с IMAGE_PROVIDER=real, VERIFIER_PROVIDER=real на :8080, выполнить ИХ
   participant_test.sh на `case-data/eval/queries/` с их queries.tsv → предъявить
   predictions.jsonl (3 строки, latency_ms) в отчёте. До сигнала — шаги 1–3 полностью.
