# Агент H3 · Третий проход OCR по кропу этикетки (1280 px) + бикубика для мелких входов

**Зона записи:** `packages/cv/cv/ocr_rapid.py`, `packages/cv/cv/label_crop.py` (новый — перенос
эвристики из `qa/real_photos_label_crops.py::label_bbox`), `packages/cv/tests/`, `apps/api/app/config.py`
(если нужен новый параметр), `apps/api/tests/`, `infra/ams3/somelye.env.example`,
`infra/local-check/run-check-server.sh`, отчёт `reports/h3-label-crop-ocr.md`.

## Основание — `reports/label-crop-study.md`, обсуждение схемы «два потока» (22.09)

CPU-путь стенда hack-v7: 91.9% top-1 на 62 живых фото. Разбор промахов: OCR не находит мелкие
строки («ПОЛУСЛАДКОЕ РОЗОВОЕ», «WINEMAKER'S SELECTION») — узкое место ДЕТЕКТОР при 960 px, не
распознаватель (перераспознавание строк из оригинала в родном разрешении — хуже: 88.7%).
Измерено на кэше: детектор+распознаватель RapidOCR на КРОПЕ ЭТИКЕТКИ при 1280 px как третий
источник текста (объединение с проходами 640+960 по кропу бутылки) → +1 фото (90.3 → 91.9% при
2 кропах CV, `qa/real_photos_cpu_path.py --union rapid_640+rapid_960+lab_rapid_1280`); при 1600 px — 0.
Кроп этикетки: кластер боксов детектора текста центральной бутылки (`qa/real_photos_label_crops.py`,
находится на 100/100 живых фото, медиана 16% кадра), без отдельной модели-детектора.

## Задача

1. `cv/label_crop.py`: `label_bbox()` из прототипа (дословно, с тестами на синтетических боксах:
   кластеризация по вертикали, минимальный размер, рост вниз, фолбэк — весь кроп бутылки).
2. `cv/ocr_rapid.py`: третий масштаб — `CV_OCR_LABEL_SIZE` (дефолт 1280; 0 = выключено). Порядок:
   проход 960 по кропу бутылки даёт боксы → `label_bbox` → кроп этикетки ИЗ ОРИГИНАЛА (полное
   разрешение) → даунскейл до 1280 → детектор+распознаватель → текст в объединение. Боксы прохода
   960 переиспользуются, лишней детекции нет. Этикетка не найдена → проход пропускается.
3. Бикубика для мелких входов: перед каждым проходом, если кроп МЕНЬШЕ целевой стороны прохода,
   увеличить `Image.BICUBIC` до неё (сейчас `thumbnail()` только уменьшает; на фото < ~1000 px
   кроп бутылки меньше 960). Тест: даунскейл фикстуры до 700 px → путь с увеличением читает не
   хуже, чем без.
4. Приёмка через живой API на Mac (индекс `packages/cv/data-d1`, `CV_MODEL=google/siglip2-base-patch16-384`,
   `CV_FUSION=1 CV_FUSION_W=0.3 CV_FUSION_TEXT_SOURCE=ocr CV_OCR_ENGINE=rapid`, свободный порт ≥ 8770,
   VLM не подключать): `CV_OCR_LABEL_SIZE=0` против `1280`, 2 кропа CV. Цель: не хуже 91.9% и +1 фото
   (93.5%); p50/p95 по `timing_ms`. Плюс имитация «мессенджера»: те же 100 фото, уменьшенные до 1000 px
   по длинной стороне (временный каталог вне git) — с бикубикой и без; в отчёт.
5. Полные тесты `packages/cv` и `apps/api` зелёные; env-примеры стенда и локальной проверки —
   `CV_OCR_LABEL_SIZE=1280`; коммиты с pathspec.
