# Агент G5 · Точность: текстовое переранжирование и TTA (главные 50 баллов)

**Зона:** `packages/cv/`, `qa/`, `reports/g5-accuracy.md`. Коммиты только с pathspec.
**Не трогать** `apps/api` — встраивание в сервис сделает оркестратор/B по твоему отчёту.

## Почему это главное (разбор чата кейса, сессия вопросов 17.09)

Приватная проверка: 100 фото, ВСЕ вина есть в каталоге, фото без бутылки нет. Оценивается
ОДНО — совпал ли первый ответ (raw top-1). Наш честный уровень: 64.6% top-1 / 83.1% top-5
(`qa/scan-eval-runs/case-20260918-honest`). Правильный ответ часто в пятёрке, но не первым —
узкое место в РАНЖИРОВАНИИ. «92% за 2 минуты лучше 87% за 2 секунды»: скорость ~5% оценки,
жёсткий предел — таймаут 10 с в их скрипте. Сейчас мы тратим 0.35 с (Mac) — бюджет почти не
используется. Цель по задержке: ≤ 1.5 с на Mac (MPS), ≤ 6 с на стенде ams3 (CPU, OCR там ~2.5–3 с).

## Задачи

1. **Лаборатория** `qa/accuracy_lab.py` — офлайн, без HTTP, по набору
   `/private/tmp/claude-501/-Users-vyacheslavfokin-ClaudeWorkspace/3ef8e524-2f02-493d-bf79-36104e8b36c9/scratchpad/case-synth-honest`
   (2054 фото, per-slug сиды; истинный слаг — префикс имени файла до `__synth`). Кэшировать на
   диск (qa/.cache/, в .gitignore): для каждого фото CV top-20 {slug, score} через ImageIndex
   (индекс case-20260918 в packages/cv/data; лок свободен — локальный API оркестратор погасил) и
   OCR-текст через `cv.verify.LabelVerifier.read_text` — в двух вариантах: по кропу
   `normalize_query` и по всему кадру (что читает больше полезного?). Сплит dev/holdout —
   `qa/scan_eval.py::assign_split` (тот же SHA-сплит). Подбор параметров — ТОЛЬКО на dev, цифры
   в отчёт — по holdout.
2. **Текстовое переранжирование** `packages/cv/cv/text_rerank.py`: текст кандидата = название +
   винодельня + сорт (+ регион) из каталога кейса
   `/Users/vyacheslavfokin/ClaudeWorkspace/vines/case-data/strapi_output0709.csv` (колонки
   «Название вина», «Винодельня», «Сорт винограда», «Регион»; слаги в CSV дублируются — брать
   первое непустое). Нормализация: нижний регистр, ё→е, пунктуация прочь; **транслитерация
   кириллица→латиница с обеих сторон** (этикетка «ARISTOV» ↔ каталог «Аристов»). Скор: токенное
   пересечение с IDF по каталогу (редкие токены — винодельни, названия — весят много; «вино,
   красное, белое, сухое, брют, россии» — почти ничего) + нечёткое сравнение rapidfuzz для
   ошибок OCR. Итог = cv_score + w·text_score на top-K. Подобрать K∈{5,10,20} и w на dev.
3. **TTA** (ограничь по времени): эмбеддинги 2–3 кропов (кроп этикетки, весь кадр, центр) →
   слияние max/mean; прирост и цена по задержке.
4. **Санити на реальных фото**: 3 из `case-data/eval/queries/` (истина известна по нашему
   разбору: Мускатель Массандра Белый в каталоге; Табия и Aristov Donum — нет) и 7 полочных из
   `case-data/field-shots/`. Отдельной строкой, без подгонки под них.
5. **Отчёт** `reports/g5-accuracy.md` (≤ 40 строк): таблица holdout top-1/top-5 — база /
   переранжирование / +TTA; задержка по стадиям на Mac; рекомендованная конфигурация (K, w,
   кропы) + оценка задержки на ams3. Явно: синтетика рендерится из тех же эталонов, что в
   индексе, поэтому CV оптимистичен, а OCR читает студийную этикетку — полевые фото хуже.
6. Тесты на text_rerank: транслитерация, IDF-веса, опечатки OCR, пустой OCR → порядок CV.
