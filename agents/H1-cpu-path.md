**Зона записи:** `packages/cv/cv/text_fusion.py`, `packages/cv/cv/index.py` (только если нужно),

## Основание (оркестратор, 21.09, офлайн на 62 живых фото из каталога, индекс D1 base-384)

CPU-путь = слияние с текстом PaddleOCR (`CV_FUSION_TEXT_SOURCE=ocr`) — то, что работает без GPU
и без внешних моделей. Через живой API он даёт 75.8% top-1. Разбор 15 промахов: OCR на кропе
детектора при 320 px не читает мелкие слова; в 6 случаях CV была права, а слабый текст сбивал.
Три поправки, проверенные на кэше (каждая строка — накопительно):

| Поправка | top-1 |
|---|---|
| как сейчас: `read_query_text` = детектор (`normalize_query`) + OCR 320 px | 75.8% |
| OCR на ЦЕНТРАЛЬНОМ кропе кадра 640 px (доли 0.15/0.05/0.85/0.98 — тот же, что уходит VLM), без детектора | 83.9% |
| + греческие двойники в токенах OCR (Λ→Л, Γ→Г, Π→П, Δ→Д, Φ→Ф и т.д.: «OΛEΓ» = ОЛЕГ) | 87.1% |
| + текст в полсилы (×0.5), если у кандидата не подтверждена ВИНОДЕЛЬНЯ (recall токенов поля winery < 0.5) — ТОЛЬКО для источника ocr; для vlm-источников гейт вреден (95.2 → 93.5) | 88.7% |

800 px хуже 640 (85.5%: больше шума), объединение с текстом детекторного кропа ничего не добавляет.
OCR на центральном кропе 640 к тому же быстрее (медиана 1.0 с против 1.7 с на Mac).
Скрипт эксперимента — в истории оркестратора; воспроизводится через `qa/real_photos_eval.py --ocr cwide640`
(признаки `features/ocr_cwide640.jsonl` уже посчитаны `qa/real_photos_features.py`).

## Задача

1. `LabelVerifier`: новый метод чтения текста с центрального кропа кадра при заданной стороне
   (`CV_OCR_QUERY_MODE=center|detector`, `CV_OCR_CENTER_SIZE=640`; дефолт пока `detector`, включим
   после приёмки). `read_query_text` при `center` использует его. Верификатор near-dup
   (`verify`) получает тот же текст — как сейчас.
2. `cv/text_fusion.py`: греческие двойники в нормализации токенов запроса (вариант токена, как
   с латинскими двойниками); синхронно в `qa/text_v2.py`.
3. `cv/text_fusion.py` + `service.py`: параметр «вес текста для кандидата без подтверждённой
   винодельни» (`CV_FUSION_UNCONFIRMED_WINERY_W`, дефолт 1.0 = как сейчас). При источнике `ocr`
   apps/api передаёт 0.5 (`CV_FUSION_OCR_UNCONFIRMED_W`, дефолт 0.5); при `vlm*` — 1.0.
   Подтверждение: индекс только по полю winery, recall ≥ 0.5.
4. Тесты на каждую поправку (гомоглифы, гейт, режим кропа — без сети, без PaddleOCR в юнитах).
5. Приёмка через живой API на Mac (индекс `packages/cv/data-d1`, `CV_MODEL=google/siglip2-base-patch16-384`,
   `CV_FUSION=1 CV_FUSION_W=0.3 CV_FUSION_TEXT_SOURCE=ocr`, порт свободный, например 8767; локальные
   VLM не подключать): `qa/real_photos_serve.py --flat-only` → `qa/real_photos_eval.py --served`.
   Цель: ≥ 87% top-1 (офлайн 88.7%), p95 не хуже нынешних 1.3 с на Mac. И контроль, что источник
   `vlm_both` не регрессировал (можно офлайн-оценкой, VLM-тексты в кэше `features/ocr_gwf1024.jsonl`).
6. Полные тесты API и CV зелёные; коммиты с pathspec.
