# Агент B7 · Аналоговый фолбэк текстового resolve (иностранное вино → российский аналог)

**Зона:** `apps/api/`, `reports/b7-foreign-analogs.md`. Коммиты только с pathspec.
Идея Вячеслава (17.09, живой тест стенда): «Urban Risling» → 0 совпадений — надо
отдавать российские аналоги по стилю. Это и киллер-фича «Своего Сомелье», и
«функция после поиска» ТЗ (20/100).

## Задачи

1. `POST /v1/scan/resolve`: при пустых matches (low_confidence) — извлечь из текста
   запроса токены сорта/стиля по справочникам `pipeline/ref/grape_synonyms.yaml`
   (Riesling→рислинг и т.д.) и `pipeline/ref/reference_styles.yaml`; при попадании —
   получить аналоги существующим механизмом аналогов (тот же резолвер стиля, что у
   /v1/analogs — НЕ дублируй логику, вынеси общий вызов) и вернуть доп-поля:
   `analogs: [...]` (той же формы, что /v1/analogs) и `analog_reason: str`
   (например: «„Urban Riesling“ вне каталога российских вин — аналоги по стилю:
   рислинг»). Токенов нет → как сейчас (пусто, без analogs).
2. Матчинг токенов: регистронезависимо, латиница и кириллица, учёт опечаток лёгкий
   (risling/riesling). Не изобретай NLP — словарного прохода достаточно.
3. Контракт: схему ответа /scan/resolve в openapi.yaml обновит оркестратор по твоему
   отчёту; в контрактном тесте — задокументированное временное исключение (паттерн
   B3, `_KNOWN_UNDOCUMENTED_*` с комментарием и ссылкой на этот бриф).
4. Тесты: «Urban Risling» (моки) → analogs непусты + reason; «Chianti» → санджовезе;
   «абракадабра» → пусто без analogs; существующее поведение непустых matches — без
   изменений (регрессия).
5. e2e против живого стенда :8000 (НЕ гасить, НЕ перезапускать — только HTTP):
   гостевой токен → resolve «Urban Risling» → в отчёт фактический ответ.
