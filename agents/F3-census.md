## Задачи

1. **Дожать матчер** → `qa/case_census.py` (чистый, с тестами в `qa/tests/`):
   транслитерация кириллицы по правилам Strapi (npm `transliteration`; сверь эмпирически
   по парам из данных), повтор прохода по 427 промахам. Оставшиеся промахи классифицируй:
   фото реально НЕТ в uploads (слаг без эталона — отдельный список `no_ref_slugs`) vs
   не сматчилось по имени. Итог перезапиши в `case-data/slug_refs.json` (тот же формат +
   поле `match_method`). Проверь и 30 слагов с >1 файлом-кандидатом — выбери лучший
   (не-превью, максимальное разрешение).
2. **Перепись семей near-dup**: (а) год-в-слаге; (б) общие фото (shared) — семья гарантирована;
   (в) почти одинаковое «Название вина» при разном slug (нормализованное расстояние).
   Итог: `case-data/families.json` + таблица в отчёте (семья, слаги, различитель:
   год-читаем/год-в-этикетке-отсутствует/категория/одинаковый-файл-неразличимы).
3. **OCR-читаемость года на ИХ эталонах** (записанный пункт переписи): для всех слагов из
   семей прогони PaddleOCR по эталонному фото через venv `packages/cv` (там всё стоит;
   смотри `packages/cv/cv/verify.py` — импортируй и используй его пайплайн; НЕ ставь paddle
   заново). В отчёт: у каких семей год реально читается с эталона, у каких нет. Это решает,
   где верификатор вообще может помочь.
4. **Шумовая перепись uploads**: оригиналы, НЕ являющиеся эталонами вин (~4.5 тыс) —
   классифицируй по расширению/имени (svg-логотипы, geojson, xml-сайтмапы, pdf, фото статей).
   Они в индекс не идут. Цифры в отчёт.
5. **Качество эталонов**: распределение разрешений (min/p50/p95), список подозрительно
   мелких (<400px по короткой стороне).
6. **Статус заморозки**: публичный датасет полевых фото в поставке ОТСУТСТВУЕТ (только
   3 пробных query в eval/). Зафиксируй в отчёте: split dev/holdout замораживается по его
   приезду; 3 пробных фото — smoke-набор, в тюнинг не идут. Обнови чек-лист §9 в
   `qa/acceptance.md` (галочки выполненного, владельцы).
