# Агент G6 · Энкодер крупнее: SigLIP 2 large / so400m против base (без обучения)

**Зона:** `packages/cv/` (кроме `cv/verify.py` — там работает B9), `qa/`,
`reports/g6-encoder.md`. Коммиты только с pathspec.

## Зачем

Точность (raw top-1) — 50 баллов. Переранжирование текстом на синтетике почти ничего не дало
(reports/g5-accuracy.md). Следующий рычаг без обучения — более сильный энкодер. Сейчас
`google/siglip2-base-patch16-224`, holdout top-1 63.9% / top-5 84.5% (n=374). Организаторы:
точность важнее скорости, таймаут скрипта 10 с.

## Задачи

1. Кандидаты (по одному, от дешёвого к дорогому): `google/siglip2-base-patch16-384`,
   `google/siglip2-large-patch16-256`, `google/siglip2-so400m-patch14-384`. Скачать веса можно
   (сеть разрешена для HF-загрузки; после — офлайн).
2. Для каждого — ОТДЕЛЬНЫЙ индекс в своём `CV_DATA_DIR` (например `packages/cv/data-exp/<model>/`),
   боевой `packages/cv/data` НЕ трогать. Ракурсы переиспользовать из кэша аугментаций
   (`packages/cv/data/augmented`, CLI `--views-cache`) — считать заново только эмбеддинги.
   Если полный набор ракурсов для самой тяжёлой модели не укладывается в ~2 ч — честно
   уменьши число ракурсов ОДИНАКОВО для базы и кандидата и сравни на равных.
3. Оценка на ТОМ ЖЕ holdout (qa/accuracy_lab.py, сплит assign_split): raw top-1/top-5, срезы
   near-dup и fallback-детектора. Подбор — только по dev.
4. Задержка embed на Mac (MPS) и на CPU (замер `CUDA_VISIBLE_DEVICES`/`device=cpu`) — чтобы
   оценить стенд ams3 (4 vCPU).
5. Отчёт `reports/g6-encoder.md` (≤ 30 строк): таблица модель → holdout top-1/top-5,
   время сборки индекса, embed p50/p95 MPS/CPU, размер индекса; рекомендация.

## Не делать

Боевой индекс и стенд не трогать; apps/api не трогать; обучение не запускать.
Лок embedded-qdrant у каждого CV_DATA_DIR свой — боевой свободен для B9.
ORCHESTRATION.md — длинные шаги синхронно или с явной передачей оркестратору.
