## Основание (ml-lead, 22.09, офлайн; полный разбор и цифры — `reports/ml-lead-shelf-crop.md`)

Полевые фото ЦЕЛЫХ ПОЛОК (`Field/`, разметка `case-data/real-photos-labels/part3-field.csv`) в
боевой конфигурации дают top-1 1/8 (qa-auto, `reports/qa-auto-field-photos.md`) — причина:
центральный кроп кадра (0.15-0.85 ширины) на кадре полки содержит 3-4+ бутылки вместо одной.
Прототип `qa/real_photos_shelf_crop.py` (запусти сам, воспроизводится детерминированно):

1. Детектор текста RapidOCR (сенситивный, детекция без распознавания — быстро, ~0.3-0.6 с) по
   всему кадру.
2. РЯД (полка): растим окно от Y-центра кадра наружу по сглаженной (4.5% высоты) плотности
   боксов до структурного разрыва между полками (`expand_from_center`).
3. КОЛОНКИ (бутылки) внутри ряда: реальные разрывы нулевого X-покрытия (`run_clusters`); фолбэк
   — проекция границ Sobel/OpenCV (`geometric_columns`) при < 2 колонок.
4. Раздел Вороного между колонками = кроп «одна бутылка с полями»; ближайшая к X-центру кадра —
   «центральная» (это и есть новый вход для стандартного конвейера: 2 эмбеддинга CV + RapidOCR
   640/960 на этом кропе, вместо кадра целиком).
5. **Гейт «это полка»** — обязателен, без него регрессия на студийных фото каталога (см. ниже):
   колонок ≥ 2 И боксов в полосе ряда ≥ `SHELF_MIN_BOXES=30`. Гейт не пройден → кроп = весь
   кадр побитово (по коду by construction, не приближённо).

**Офлайн-цифры (`reports/ml-lead-shelf-crop.md`, воспроизведи и сверь перед своим прогоном):**

| | top-1 (8 полевых) | top-1 (62 фото каталога) |
|---|---|---|
| без сегментации (боевой) | 1/8 (совпадает с живым qa-auto) | 59/62 = 95.2% |
| с гейтом (порог выше) | 2/8, true_rank улучшился у 5/8 | 59/62 = 95.2%, **0 регрессий** |
| без гейта («всегда применять») | — | 32/62 = 51.6% — КАТАСТРОФА |

22 NONE полевых фото: офлайн-гейт уверенности (мой прокси cv≥0.80/gap≥0.03, НЕ боевой
`CV_ABS_FLOOR`/`CV_MARGIN_FLOOR`) — confident=0/22 и без, и с локализацией. Наивное правило
«просто ≥2 колонки» без порога боксов ОТКЛОНЕНО ml-lead — на случайных фото каталога находит
2-4 «колонки» у одной бутылки (герб/текст разнесены по X) в 6/8 случаев; `SHELF_MIN_BOXES=30`
подобран на ВСЕХ 100 фото каталога (макс. боксов у не-полочных — 51; полевые ряды — 41-118).

## Что сделать

1. Перенести `segment_shelf()`/`expand_from_center()`/`run_clusters()`/`geometric_columns()`/
   `voronoi_bounds()` из `qa/real_photos_shelf_crop.py` в `packages/cv/cv/shelf_crop.py` —
   боевой код с тестами, теми же порогами (box_thresh=0.3, unclip=2.0, limit_side_len=1800,
   `SHELF_MIN_BOXES=30`, search_frac=0.4, smooth_frac=0.045). Детектор RapidOCR без
   распознавания (`Global.use_rec: False`) — отдельный, дешёвый проход ДО обычного OCR.
2. Вызвать в `run_photo_scan()` (`apps/api/app/cv/service.py:658`) — САМЫМ ПЕРВЫМ шагом, ДО
   `image_index.search()`/`_run_photo_scan_fusion()`: декодировать `image_bytes` (как обычно,
   `cv.imageio.decode_image` + EXIF), прогнать `segment_shelf()`; гейт пройден → дальше по
   конвейеру идёт кроп центральной бутылки, иначе — исходное фото без изменений. И
   `/scan/photo` (flat и rich), и `/v1/eval/predict` зовут ровно эту функцию (`routers/scan.py`
   докстринг строка ~195) — правка одна на все три пути. Как передать кроп дальше (заново
   закодировать в bytes или провести массив глубже, минуя лишний JPEG-круговорот) — на твоё
   усмотрение, обоснуй в отчёте.
3. Флаг `CV_SHELF_CROP` (дефолт `false` до приёмки, как остальные флаги слияния), порог
   `CV_SHELF_MIN_BOXES` (дефолт 30) — оба в `config.py`, по образцу существующих `CV_FUSION_*`.
4. Тесты `packages/cv`: синтетические паттерны боксов — один блок (проход, без изменений),
   два разделённых кластера с ≥30 боксов (гейт срабатывает, верный раздел Вороного), редкие
   боксы < 30 (гейт НЕ срабатывает). Тесты `apps/api`: флаг выключен → поведение не меняется
   (регрессия невозможна by construction); флаг включён + полочная фикстура → кроп применяется.
