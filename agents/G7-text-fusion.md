# Агент G7 · Слияние CV + текст этикетки по всему каталогу (боевой путь)

**Зона записи:** `packages/cv/cv/text_fusion.py` (новый), `packages/cv/cv/index.py` (расширение
поиска), `packages/cv/tests/`, `apps/api/app/cv/service.py`, `apps/api/app/config.py`,
`apps/api/tests/`, `qa/` (приёмка), отчёт `reports/g7-text-fusion.md`. Контракт
`contracts/image-scan.md` правит оркестратор по твоему отчёту (раздел «Предложения к контракту»).

## Основание (оркестратор, 21.09, реальные фото организаторов)

Приватная проверка — «реальные фото Android/iPhone, ориентир — выданные живые примеры»
(пересказ сессии вопросов). 100 живых фото размечены (`case-data/real-photos-labels/part*.csv`).
На фото из каталога: стенд hack-v5 (CV + верификатор) — top-1 ≈ 55%, top-5 ≈ 73%;
переранжирование G5 (`CV_TEXT_RERANK`) не меняет НИЧЕГО (безопасный гейт по медиане IDF
отсекает даже названия виноделен). Прототип `qa/text_v2.py` + `qa/real_photos_eval.py`
(схемы `v3_*`) — top-1 ≈ 70–73%, top-5 ≈ 85–88%, обе половины выборки согласны. Гейт
уверенности на слиянии: 96% точности уверенных ответов против 60% у нынешнего гейта.

Что даёт прирост (всё есть в прототипе — перенести, не изобретать):
1. Текст ищет по ВСЕМУ каталогу, а не переставляет top-5 CV: верного вина часто нет в
   CV top-10 (Фанагория, Табия), текст находит винодельню и название.
2. Гомоглифы OCR: eslav-модель пишет кириллицу латинскими двойниками (CAMAPA=САМАРА,
   KPACHAA=КРАСНАЯ, ДЕHИCOB=ДЕНИСОВ, PO3E=РОЗЕ) — вариант токена с заменой двойников.
3. Потокенная нечёткость (ratio ≥ 0.8, префикс ≥ 5: CKАЛИСТ→скалистый) вместо одного
   token_set_ratio на строку; английские маркеры сахара (dry/semi-sweet/brut) → русские.
4. Поля кандидата: название + винодельня + сорт + категория (`Категория` CSV) + маркер
   сахара (`sugar_of`: слаг → «Название фото» → название). Сахар различает SKU одной линейки
   (Жемчужная 9 сухое/полусухое/полусладкое — картинка одна, отличие только в «п.сух/п.сл»).
5. CV: максимум по двум входам — нормализованный кроп этикетки И весь кадр (`sims_norm`,
   `sims_raw`): на реальных фото детектор этикетки часто берёт не то.
6. Итог: `final = cv + W·rel`, `rel = mass / max(mass)` (IDF-масса совпавших токенов
   кандидата относительно лучшего кандидата). Слагам без эталона в индексе (usable=false и
   т.п.) — CV-заглушка `cv_top1 − 0.03` (иначе текст не может их поднять).

Параметры (плато на разметке; финальные — в дополнении ниже): W=0.2, OCR — как сейчас
(`read_query_text`, кроп 320: 640 и полный кадр не лучше), гейт: уверенно, если отрыв
итогового скора от первого кандидата ДРУГОЙ семьи (`families.json`) ≥ 0.03 И CV top-1 ≥ 0.80.

## Задача

1. `cv/text_fusion.py` — перенос прототипа с тестами (гомоглифы, токены, сахар, скоринг),
   индекс текста строится один раз из CSV кейса (`CV_CASE_CATALOG_CSV` / `CASE_DATA_DIR`,
   как `text_rerank.default_catalog_csv_path`). Бюджет: ≤ 50 мс на запрос на Mac.
2. CV: запрос по двум эмбеддингам (norm + raw), per-slug максимум; CV-скоры для текстовых
   кандидатов вне CV-топа — отфильтрованным запросом Qdrant по payload `slug` (MatchAny) или
   эквивалентно точно. Кандидаты: CV top-50 слагов ∪ текст top-30.
3. apps/api: флаг `CV_FUSION` (по умолчанию false до приёмки). При true: OCR один раз
   (`read_query_text`), слияние, flat → итоговый top-1; rich → `matches` = итоговый top-5
   (score = final), `candidates` из него же, `confidence.top1_score` = CV-скор top-1,
   `gap` = итоговый отрыв по семье, гейт по правилу выше (свои настройки `CV_FUSION_W`,
   `CV_FUSION_GAP_FLOOR`, `CV_FUSION_CV_FLOOR`). Верификатор near-dup при слиянии — флагом
   `CV_FUSION_VERIFY` (по умолчанию false), замерь оба варианта. `CV_TEXT_RERANK` не ломать;
   если включены оба — действует слияние (задокументировать).
4. Приёмка: свой uvicorn на отдельном порту (боевой индекс держит один процесс — если занят,
   `CV_QDRANT_PATH` на копию `case-data/real-photos-labels/qdrant-copy`), прогон
   `qa/real_photos_serve.py` → `qa/real_photos_eval.py --served ...`: top-1 не хуже офлайн-
   прототипа v3 минус 2 п.п.; p50/p95 flat на Mac последовательно. Санити на синтетике:
   небольшая выборка честного baseline (qa/scan_eval.py) — без катастрофы (текста там мало).
5. Полные тесты API и CV зелёные.
