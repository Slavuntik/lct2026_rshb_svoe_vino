# ml-handoff — пакет передачи ML-команде (fine-tune до ≥90%)

Команда «Свой Сомелье» довела кейс-сканер (ЛЦТ 2026, «Своё Вино» / РСХБ.Цифра,
`../case.md`) до рабочего zero-shot пайплайна и откалибровала всё, что калибруется
БЕЗ дообучения. Этот пакет — передача узкого, конкретного участка работы
(fine-tune вижн-башни под задачу) внешней ML-команде. Читается независимо от
остального репозитория (хотя лежит внутри него и переиспользует его код —
`packages/cv/`), без контекста прошлых волн разработки.

**Мы ничего не обучали в рамках этого пакета.** Здесь — постановка, данные, рецепт,
обвязка приёмки и working-скрипт для генерации обучающих триплетов. Задание, из
которого собран этот пакет — `../agents/M1-ml-handoff.md`.

## Порядок чтения

1. **README.md** (этот файл) — постановка задачи, текущий результат, что можно/нельзя.
2. **[DATA.md](DATA.md)** — карта данных: что приехало, что нет, какие сиды синтетики
   уже "сожжены", как переиспользовать наш SHA-сплит dev/holdout.
3. **[RECIPE.md](RECIPE.md)** — рецепт fine-tune: по мотивам arXiv:2404.08820 + наш
   собственный опыт (лестница мер, риск переобучения на студийный домен).
4. **[EVAL.md](EVAL.md)** — как мерить, какие цифры сдавать, eval-gate, подводные камни.
5. **[BASELINES.md](BASELINES.md)** — сводная таблица ВСЕХ наших измерений с коммитами
   и отчётами-источниками — точка отсчёта "лучше/хуже" для новой модели.
6. **[scripts/make_triplets.py](scripts/make_triplets.py)** — генератор манифеста
   триплетов (работает, протестирован — `tests/test_make_triplets.py`).
7. **[scripts/eval_new_encoder.md](scripts/eval_new_encoder.md)** — пошаговый runbook
   замены `CV_MODEL`/чекпойнта и замера.

## Задача и цель

`../case.md` (ТЗ кейсодержателя): фото этикетки в реальных условиях (у полки, под
углом, блики, плохой свет) → **одна** карточка вина каталога «Своё Вино», без экрана
вариантов. Критерий №1 (50 из 100 баллов оценки): **точность на контрольной выборке
90–100% совпадений**. Метрика уверенности F1 топ-1/топ-5 отдаётся в API. SLA ответа
≤ 3 с. Near-duplicates (одна серия, разные год/сезон/категория при одинаковой
этикетке) — по тексту ТЗ **главный источник ошибок**, и именно на них проверяют
достоверность.

**Цель этого fine-tune: поднять top-1 (flat-режим, как реально шлёт скрипт
кейсодержателя) к 90–100%.**

## Где мы сейчас (zero-shot SigLIP2, БЕЗ единого шага дообучения)

Всё нижеперечисленное — **на синтетике** (self-match-style свежие ракурсы ТЕХ ЖЕ
эталонов, что в индексе; см. DATA.md/BASELINES.md почему это верхняя, не честная
граница). Полевых фото кейса в поставке физически нет (см. DATA.md) — оценки на них
ещё не существует.

| Метрика | Значение | Источник |
|---|---:|---|
| raw top-1 (ANN-ранжирование, без гейта confident/not_in_catalog) | **69,4%** | `../reports/f3-synthetic-baseline.md` (commit `b4f9608`), 1982/1982 запросов, seed 20260917 |
| raw top-5 | 89,9% | там же |
| match-rate top-1 (реальный путь `/v1/scan/photo`, С гейтом) | **41,6%** (0,4157) | `../qa/scan-eval-runs/case-20260917-final-b7/report.md` (commit `fc6a1f6`) |
| match-rate top-5 | 89,8% (0,8985) | там же |
| F1 top-1 / top-5 (macro) | 0,4103 / 0,4083 | там же |

**Прочитать эти четыре числа вместе:** raw top-1 (69,4%) — это потолок текущего
ranking'а (сырое ANN, до порогов уверенности). match-rate (41,6%) — то, что реально
увидит кейсодержатель через основной путь API; разрыв между 6,8% (первая калибровка
порогов, `../reviews/05-dataset-wave.md`) и 41,6% (эта волна) закрыт ЦЕЛИКОМ
калибровкой порогов и routing-фиксами (`../contracts/image-scan.md` v0.4.7→v0.4.9),
**без единого шага обучения** — см. BASELINES.md, раздел "Эволюция гейта". Это уже
почти исчерпанный резерв: чтобы 41,6%→90%+ по факту, raw top-1 тоже обязан вырасти
намного выше 69,4% — **ranking (сырое качество embedding) — узкое место, retrieval
(способность найти правильный slug хоть где-то в top-K, top-5=89,9%) уже сильный.**
Отсюда и задача этого пакета: fine-tune, поднимающий именно top-1 ranking.

## Что можно и что нельзя

- **Обучение не запускалось.** Этот пакет — постановка и working-инструмент для
  подготовки данных, не результат fine-tune.
- **Веса моделей — НЕ в git.** SigLIP2 (`google/siglip2-base-patch16-224`, env
  `CV_MODEL`, `packages/cv/cv/config.py`) кэшируется в `packages/cv/.hf_cache/`
  (гитигнорено). Новый чекпойнт/адаптер — та же локальная зона, тот же принцип.
- **Датасет кейса — НЕ в git.** `case-data/` (см. DATA.md) — весь путь локальный, вне
  репозитория (`.gitignore: case-data/`). В документах этого пакета пути к нему
  помечены явно как "локально, вне git" — их нужно воспроизвести на СВОЕЙ машине
  ML-команды (дамп каталога кейс содержатель предоставляет отдельно).
- **Лицензии моделей — свободны по ТЗ.** `case.md`: "нейросети не обязательны; для
  сомелье/LLM-функций — любые модели"; требований к реестру ПО в ТЗ нет.
  SigLIP2/трансформерные вижн-башни — open-weight модели, замена чекпойнта — одна
  переменная окружения (`CV_MODEL`, `packages/cv/cv/encoder.py`), без правок кода.
- **Стенд на порту :8000 (живой процесс на этой машине на момент сборки пакета) —
  не трогать.** Ни один скрипт этого пакета не поднимает и не гасит API-процессы и не
  открывает `packages/cv/data/qdrant/` (embedded Qdrant — файловый лок, которым стенд
  может владеть) — `make_triplets.py` работает ТОЛЬКО с JSON-каталогом кейса и (опционально)
  голым энкодером, без `cv.index`/`cv.store` (см. докстринг скрипта).
- **Фото кейса не копировать.** Все инструменты этого пакета оперируют ПУТЯМИ в
  `case-data/`, не пиксельными данными — см. DATA.md/RECIPE.md/сам скрипт.
