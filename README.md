## Как это работает

Принцип: **сопоставление важнее распознавания**. Снимок в магазине всегда несовершенен (блик,
ракурс, текст по дуге, латиница вперемешку с кириллицей), поэтому точность добирается не «умной
моделью с одного взгляда», а подготовленным каталогом, мульти-ракурсным индексом и калиброванным
порогом. Три честных исхода: одна карточка · несколько кандидатов · «не найдено» без фантазий.

Боевой путь (`IMAGE_PROVIDER=real`): нормализация кадра → SigLIP2 base-384 → поиск по индексу
каталога → слияние с текстом этикетки (RapidOCR в два масштаба и/или чтение моделью Qwen3.8-27B
через свой шлюз, правило выбора `confident_else_cv`) → карточка. Бюджет скана и предохранитель
ограничивают ожидание внешней модели; жёсткая верхняя граница всей обработки не гарантирована. Детали и все ADR — `docs/architecture/models-and-algorithms.md`.

## Быстрый старт (без ключей и без данных)

Одной командой, с проверкой окружения и понятными сообщениями об ошибках:

```bash
scripts/quickstart.sh          # веб, API, Swagger; сомелье на реальном индексе из репозитория
scripts/quickstart.sh full     # настоящее распознавание: модели и сборка индекса, 40 мин – 1.5 ч
scripts/quickstart.sh verify   # официальный скрипт проверки против локального сервиса
```

Подробности, требования и что работает в каждом режиме — [docs/QUICKSTART.md](docs/QUICKSTART.md).
Ниже — то же самое вручную:

```bash
cd apps/api && uv venv && uv pip install -e . && ./.venv/bin/uvicorn app.main:app   # mock-LLM + mock-RAG
cd apps/web && npm i && npm run dev                                                 # клиент в mock-режиме
```

Реальный поиск: `IMAGE_PROVIDER=real VERIFIER_PROVIDER=real RAG_PROVIDER=real RAG_MODE=embedded`.
Полный справочник env (дефолт кода и значение на стенде) — `docs/architecture/operations.md` §4.
LLM-ключей для запуска не нужно: `LLM_PROVIDER=mock` оставляет сканер и каталог полностью рабочими.

## Прогон скрипта кейсодержателя

Прогнать обычную папку изображений (включая подпапки) и оставить JSONL + JSON-отчёт:

```bash
python3 tools/eval_detector.py --images-dir /path/to/photos \
  --endpoint http://127.0.0.1:8080/v1/eval/predict --output ./eval-results/predictions.jsonl
```

[Сценарий демонстрации: clone → setup → eval-script + dataset → файл результата](docs/EVAL_DEMO.md).
Отдельная утилита проверяет весь датасет и готовность основного CV, запускает официальный скрипт и сохраняет JSONL без автоматического коммита:

```bash
python3 tools/eval_detector.py --dataset /path/to/unpacked-eval \
  --endpoint http://127.0.0.1:8080/v1/eval/predict --output /tmp/predictions.jsonl
```

`POST /v1/eval/predict` — фиксированный путь скрипта оценки: без авторизации, multipart-поле
`image`, всегда HTTP 200 и `{"slug": "..."}` (лучшая доступная догадка даже при сбое пайплайна).
Это алиас «несгораемого» плоского режима `/v1/scan/photo?flat=1` (`contracts/image-scan.md`).

```bash
cd apps/api && IMAGE_PROVIDER=real VERIFIER_PROVIDER=real ./.venv/bin/uvicorn app.main:app --port 8080
# в другом терминале — скрипт организаторов без правок:
cd eval && ./participant_test.sh --images-dir ./queries --manifest ./queries.tsv \
  --endpoint 'http://127.0.0.1:8080/v1/eval/predict' --output ./predictions.jsonl
```

## Состав репозитория

**Продукт — то, что сдаётся и работает на стенде:**

```
apps/api      FastAPI: /v1/scan/photo, /v1/eval/predict, /v1/wines, /v1/chat (SSE с цитатами),
              /v1/analogs, /v1/pairing/*, /v1/metrics/scan
apps/web      веб-клиент (React + TS + Vite, PWA): скан, карточка, чат, вкусовой паспорт, полки, подтверждение 18+
apps/shelf-finder отдельный CPU/GPU сервис полок (:8086); основной UI использует его в /app/shelf
apps/shell    Capacitor-оболочка + нативный OCR-плагин (Vision, кириллица)
packages/cv   боевой движок распознавания: нормализация, SigLIP2, индекс, слияние с текстом
packages/rag  поисковое ядро сомелье: гибрид BM25 + вектора, реранкер, intent-роутинг, goldset
packages/llm  адаптер LLM с заменяемыми драйверами (mock/openai-совместимый/deepseek/gigachat/anthropic)
pipeline/     подготовка данных: краулер каталога, нормализация, справочники
contracts/    замороженные контракты: OpenAPI, image-scan, post-scan, события, схема БД
infra/        стенд ams3 (нативный, без Docker), Compose prod/staging, CI/CD, RUNBOOK
qa/           приёмка, e2e (Playwright), прогоны на живых фото и снимки метрик
eval/         комплект проверки кейсодержателя (см. «Материалы кейса»)
docs/         архитектура (HLD/LLD/C4/ADR), продуктовые документы, эксплуатация
```

**R&D — рядом, но не часть сдаваемого решения** (держим в репозитории честно, с их собственными
замерами и оговорками; на стенде не разворачиваются и в проверке точности не участвуют):

```
packages/winescan    второй движок за тем же контрактом ImageIndex (IMAGE_PROVIDER=winescan):
                     OWLv2 + SigLIP2 so400m + проверка по локальным признакам. В бою НЕ используется:
                     его сравнение с базовым путём сделано 17.09 на синтетических сценах «у полки»
                     и не переносится на живые фото — все цифры выше получены IMAGE_PROVIDER=real
standalone/winescan  автономный снимок исходного проекта WineScan целиком (Nuxt + свой API), архив
nt/, tools/          нагрузочный прогон сканера и сопровождение монорепо
```

Граница «продукт / R&D» и почему она проведена именно так — [`ARCHITECTURE.md`](ARCHITECTURE.md),
раздел «Граница продукта».

## Данные и материалы кейса

В репозитории лежит **наш** обработанный массив портала «Своё Вино» — реальный поиск запускается
без выкачки: `pipeline/catalog/` (1978 карточек вин, 138 виноделен, 1298 статей; у каждой записи
провенанс `source_url`/`fetched_at`/`content_hash`), `pipeline/build/` (плоские артефакты),
`packages/rag/data/` (готовый индекс сомелье: **2103 вина, 138 виноделен, 5592 текстовых чанка**,
манифест `20260922.1` с откалиброванным порогом отсечки). Сырые HTML-снапшоты (502 МБ) — архивом
`pipeline/raw-archive/raw-snapshots.tar.xz` (6.6 МБ) с sha256.

Материалы кейсодержателя **не распространяем**: дамп каталога, эталонные и живые фото организаторов
лежат вне git (`CASE_DATA_DIR`, правило в `.gitignore`), ТЗ кейса в репозитории нет — есть только
наша выжимка [`case.md`](case.md) со ссылкой на первоисточник. Каталог `eval/` — комплект проверки,
**подготовленный кейсодержателем** (`participant_test.sh`, `queries.tsv`, `checksums.sha256`);
приведён как есть, без правок, чтобы проверяющий мог повторить прогон одной командой; права на него
принадлежат организаторам. Описания вин принадлежат платформе «Своё Вино» — сервис использует их как
базу поиска и в каждом ответе ссылается на страницу-первоисточник.

## Юридическая рамка

18+ подтверждается самим пользователем кнопкой в клиенте; дата рождения не собирается; согласия по 152-ФЗ (append-only журнал); фото обрабатывается в памяти;
персональные данные не попадают в промпты LLM; ответы ассистента цитируют только данные портала и
ведут на страницу-первоисточник.
