# vinchik — сканер вина по кейсу «Своё Вино» (ЛЦТ)

**Запуск всего приложения с витринами:** [локальная инструкция](docs/local-full-stack.md).
Раздел «Витрина» доступен в общей навигации (`/app/shelf`); его [GPU-сервис](apps/shelf-finder/README.md) остаётся отдельным проектом.

Синхронизация с WineScan (24.09.2026): [состав, совместимость и проверки](docs/sync-2026-09-24.md). Автономный проект целиком сохранён в `standalone/winescan`.

Сервис «фото → карточка вина»: снимок этикетки в точке продажи превращается в карточку
с описанием и ссылкой на первоисточник. 18+.

Подход: сопоставление важнее распознавания. Снимок в магазине всегда несовершенен
(блики, текст по дуге, латиница вперемешку с кириллицей), поэтому точность добирается
подготовленным каталогом, словарями синонимов и калиброванным порогом уверенности.
Три честных исхода: одна карточка · несколько кандидатов на выбор · «не найдено» без фантазий.

Архитектура (C4, три уровня): `docs/architecture-c4.html`.

```

             OWLv2 с обучаемым выбором рамки, SigLIP 2 so400m в двух видах, мультиракурсная
```

## Данные

В репозитории лежит обработанный массив кейса — можно запускать реальный поиск сразу,
без выкачки:

- `pipeline/catalog/` — нормализованные карточки: 1978 вин, 138 виноделен, 1298 статей;
  у каждой записи провенанс (`source_url`, `fetched_at`, `content_hash`), факт (`source`)
  отделён от вычисленного (`derived`);
- `pipeline/build/` — плоские поисковые артефакты (index.jsonl и чанки статей);
- `packages/rag/data/` — готовый индекс: вектора (Qdrant embedded), BM25, payload'ы
  и манифест с откалиброванным порогом отсечки.

Описания принадлежат платформе «Своё Вино»: сервис использует их только как базу поиска
и в каждом ответе ссылается на страницу-первоисточник. Сырые HTML-снапшоты (провенанс,
502 МБ) лежат архивом `pipeline/raw-archive/raw-snapshots.tar.xz` (6,6 МБ — xz дедуплицирует
общий каркас страниц; рядом sha256). Распаковка: `tar -xJf pipeline/raw-archive/raw-snapshots.tar.xz`
из корня `pipeline/`. Полная пересборка с нуля:

```
cd pipeline && make install && make wines     # discover → fetch → parse → normalize → index
```

Подробности, покрытие полей и грабли источника — `pipeline/README.md`.

## Быстрый старт (без ключей и без данных)

```
cd apps/api && uv venv && uv pip install -e . && ./.venv/bin/uvicorn app.main:app   # mock-LLM + mock-RAG
cd apps/web && npm i && npm run dev                                                 # клиент в mock-режиме
```

Реальный поиск: собрать индекс пайплайном, затем `RAG_PROVIDER=real RAG_MODE=embedded` —
интеграционные тесты: `RUN_RAG_INTEGRATION=1 pytest` в `apps/api`.

Документация API (Swagger/ReDoc) отдаётся самим FastAPI под префиксом `/v1`, чтобы
попадать в API и на стенде, где nginx проксирует в бэкенд только `/v1/*`
(`infra/ams3/nginx-somelye.conf`): локально — `http://127.0.0.1:8000/v1/docs`
(ReDoc: `/v1/redoc`, схема: `/v1/openapi.json`), на стенде —
**http://89.110.72.101/v1/docs**.

## Прогон скрипта кейсодержателя

`POST /v1/eval/predict` — фиксированный путь скрипта оценки ЛЦТ
(`case-data/eval/participant_test.sh`), алиас несгораемого плоского режима сканера
(`/v1/scan/photo?flat=1`, `contracts/image-scan.md`): без авторизации, multipart-поле
`image`, всегда HTTP 200 + `{"slug": "..."}` (лучшая доступная догадка, даже при
низкой уверенности или сбое пайплайна).

Поднять API на порту 8080 — дефолтный эндпоинт скрипта уже
`http://127.0.0.1:8080/v1/eval/predict`, дополнительных ключей не требуется
(mock-провайдеры по умолчанию):

```bash
cd apps/api
./.venv/bin/uvicorn app.main:app --port 8080
```

В другом терминале — их скрипт как есть, без правок:

```bash
cd /Users/vyacheslavfokin/ClaudeWorkspace/vines/case-data/eval
chmod +x participant_test.sh
./participant_test.sh \
  --images-dir ./queries \
  --manifest ./queries.tsv \
  --endpoint 'http://127.0.0.1:8080/v1/eval/predict' \
  --output ./predictions.jsonl
```

По завершении — `predictions.jsonl` рядом со скриптом, по одной JSON-строке на фото
(`query_id`, `image_path`, `image_sha256`, `predicted_slug`, `latency_ms`); если файл
уже существует, скрипт откажется запускаться — удалите/переименуйте перед повторным
прогоном.

На mock-провайдерах (команда выше) сервис отвечает мгновенно, но `predicted_slug` —
не настоящие слаги каталога. Содержательный прогон на боевом индексе — те же команды с
`IMAGE_PROVIDER=winescan VERIFIER_PROVIDER=real` перед `uvicorn` (движок выбран замером, см.
ниже; прежний путь `IMAGE_PROVIDER=real` работает и остаётся переключателем);
см. `reports/b3-eval-route.md` и `docs/scan-engines.md`.

## Качество

- **выбор движка распознавания сделан замером** (17.09): на общей выборке из 1991 вина
  (синтетические сцены «у полки», один раннер, один стенд, менялся только `IMAGE_PROVIDER`)
  `winescan` дал 0,610 совпадений против 0,031 у `real`, «сырое» ранжирование — 0,732 против
  0,105; парный критерий 1266 против 18 при p ≈ 0. Причина разрыва, четыре оговорки и условия
  воспроизведения — `docs/scan-engines.md`;
- голд-сет из 78 вопросов шести типов; hit@8 ≥ 0.85 на ранжирующих типах,
  отсечка-refusal калибруется на заведомо посторонних вопросах;
- eval-гейт: просевшие метрики не пускают новую версию индекса в работу;
- тесты: api 114 · rag 81 · web 56 · qa 59 · e2e 26/26 в mock- и real-режимах.

## Юридическая рамка

18+ с гейтом в клиенте; согласия по 152-ФЗ (append-only журнал); фото обрабатывается
в памяти и не сохраняется; персональные данные не попадают в промпты LLM; ответы
ассистента цитируют только данные портала и ведут на страницу-первоисточник.
