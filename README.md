# vinchik — сканер вина по кейсу «Своё Вино» (ЛЦТ)

Сервис «фото → карточка вина»: снимок этикетки в точке продажи превращается в карточку
с описанием и ссылкой на первоисточник. 18+.

Подход: сопоставление важнее распознавания. Снимок в магазине всегда несовершенен
(блики, текст по дуге, латиница вперемешку с кириллицей), поэтому точность добирается
подготовленным каталогом, словарями синонимов и калиброванным порогом уверенности.
Три честных исхода: одна карточка · несколько кандидатов на выбор · «не найдено» без фантазий.

Архитектура (C4, три уровня): `docs/architecture-c4.html`.

## Состав репозитория

```
pipeline/    подготовка данных: краулер каталога, нормализация, справочники
             (синонимы сортов, эталонные стили, гастроправила) — см. pipeline/README.md
contracts/   замороженные контракты: OpenAPI, схема БД, RAG-интерфейс, события, токены
packages/rag поисковое ядро: гибрид BM25+вектора, реранкер, intent-роутинг,
             голд-сет и eval; порог отсечки калибруется и хранится в манифесте индекса
packages/llm адаптер LLM с заменяемыми драйверами (mock/deepseek/gigachat/anthropic)
apps/api     FastAPI: /scan/resolve, /wines/{id}, /chat (SSE с цитатами), /analogs
apps/web     веб-клиент (React + TS + Vite, PWA): скан, карточка, чат, лендинг
apps/shell   Capacitor-оболочка + нативный OCR-плагин (Vision, кириллица)
qa/          демо-паки (make demo-pack WINERY=<slug>), e2e (Playwright), приёмка
infra/       Docker Compose (prod/staging), CI, деплой индекса, RUNBOOK
docs/        C4-архитектура сервиса
```

## Данные

Контент платформы «Своё Вино» в репозитории **не хранится** — он принадлежит порталу
и используется как база для поиска с цитированием первоисточника. Каталог собирается
локально пайплайном (идемпотентно, у каждой записи провенанс: `source_url`,
`fetched_at`, `content_hash`):

```
cd pipeline && make install && make wines     # discover → fetch → parse → normalize → index
```

Подробности, покрытие полей и грабли источника — `pipeline/README.md`.

## Быстрый старт (без ключей и без данных)

```
cd apps/api && uv venv && uv pip install -e . && ./.venv/bin/uvicorn app.main:app   # mock-LLM + mock-RAG
cd apps/web && npm i && npm run dev                                                 # клиент в mock-режиме
```

Реальный поиск: собрать индекс пайплайном, затем `RAG_PROVIDER=real RAG_MODE=embedded` —
интеграционные тесты: `RUN_RAG_INTEGRATION=1 pytest` в `apps/api`.

## Качество

- голд-сет из 78 вопросов шести типов; hit@8 ≥ 0.85 на ранжирующих типах,
  отсечка-refusal калибруется на заведомо посторонних вопросах;
- eval-гейт: просевшие метрики не пускают новую версию индекса в работу;
- тесты: api 114 · rag 81 · web 56 · qa 59 · e2e 26/26 в mock- и real-режимах.

## Юридическая рамка

18+ с гейтом в клиенте; согласия по 152-ФЗ (append-only журнал); фото обрабатывается
в памяти и не сохраняется; персональные данные не попадают в промпты LLM; ответы
ассистента цитируют только данные портала и ведут на страницу-первоисточник.
